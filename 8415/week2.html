🔑 1. The Key Distribution Problem
KEY IDEA: Symmetric cryptography has a fundamental scaling problem -- how do you securely share the secret key with the other party?

The core challenge: In symmetric encryption, both parties must share the same secret key. But how do you securely transmit that key in the first place? If you have a secure channel to send the key, why not just use that channel for the message itself?

The Scaling Problem

For N users to communicate pairwise, you need N(N-1)/2 unique keys. This grows quadratically and becomes unmanageable fast:

Users (N)Keys Needed
510
1045
1004,950
1,000499,500
1,000,000~500 billion
This scaling problem motivated the invention of public key cryptography. Instead of N(N-1)/2 shared secrets, each user only needs one key pair (public + private).
Professor's Tip: This is the "WHY" behind everything in this week. Every concept -- DH, RSA, PKI -- exists because symmetric key distribution does not scale.
🔒 2. Diffie-Hellman Key Exchange (1976)
Remember This
Diffie-Hellman = First published public key exchange protocol

Published by Whitfield Diffie and Martin Hellman in their landmark paper "New Directions in Cryptography" (1976). This protocol allows two parties to establish a shared secret over an insecure channel without any prior shared secrets.

Mathematical Foundation

Based on the Discrete Logarithm Problem: Given g, p, and g^a mod p, it is computationally infeasible to determine a. This one-way property is what makes DH secure.

How It Works

  1. Alice and Bob publicly agree on a large prime p and a generator g
  2. Alice picks a secret integer a, computes A = g^a mod p, sends A to Bob
  3. Bob picks a secret integer b, computes B = g^b mod p, sends B to Alice
  4. Alice computes shared secret: s = B^a mod p = g^(ab) mod p
  5. Bob computes shared secret: s = A^b mod p = g^(ab) mod p
Diffie-Hellman Key Exchange
ALICE BOB | | | Public: p (prime), g (gen) | |<----------------------------->| | | | Secret: a | Secret: b | Compute: A = g^a mod p | Compute: B = g^b mod p | | |------------ A --------------->| |<----------- B ---------------| | | | s = B^a mod p | s = A^b mod p | = g^(ab) mod p | = g^(ab) mod p | | | SAME SHARED SECRET |

Small Number Example

Example: p = 23, g = 5
Alice: a = 6, A = 5^6 mod 23 = 8
Bob: b = 15, B = 5^15 mod 23 = 19
Alice: s = 19^6 mod 23 = 2
Bob: s = 8^15 mod 23 = 2
Both arrive at the same shared secret: 2
Critical Limitation: DH does NOT authenticate the parties. An attacker in the middle can intercept and establish separate keys with each party. This is the man-in-the-middle attack.
🔐 3. RSA Algorithm (1977)
Remember This
RSA = Rivest, Shamir, Adleman | Security based on factoring large primes

The RSA algorithm, published by Ron Rivest, Adi Shamir, and Leonard Adleman in 1977, is the most widely used public key cryptosystem. Its security relies on the computational difficulty of factoring the product of two large prime numbers.

Key Generation

  1. Pick two large primes p and q
  2. Compute n = p * q (the modulus)
  3. Compute phi(n) = (p-1)(q-1) (Euler's totient)
  4. Choose e coprime to phi(n) (commonly e = 65537)
  5. Compute d = e^(-1) mod phi(n) (modular inverse)
KeyComponentsWho Knows It
Public Key(n, e)Everyone
Private Key(n, d)Only the owner

Encryption & Decryption

Encrypt: c = m^e mod n (using public key)
Decrypt: m = c^d mod n (using private key)

The Trap-door

RSA is a trap-door function: Computing c = m^e mod n is easy (encryption). Reversing it without knowing d is computationally infeasible. The "trap door" is knowing the factorization of n (i.e., p and q), which allows computing d.
Key Size Matters: As computing power grows, RSA key sizes must increase. Current recommendation is RSA-2048 minimum, with RSA-3072 for equivalence to AES-128 security level.
Professor's Tip: Understand that RSA can be used for BOTH encryption AND digital signatures. Encrypt with public key for confidentiality; sign with private key for authentication.
✍️ 4. Digital Signatures
KEY IDEA: Digital signatures provide authentication, integrity, and non-repudiation -- but NOT confidentiality.

Digital signatures are the cryptographic equivalent of a handwritten signature, but far more secure. They prove WHO sent a message and that the message was NOT altered in transit.

How Digital Signatures Work

Hash the message
→
Encrypt hash with PRIVATE key
→
Attach signature to message

Verification

Decrypt signature with PUBLIC key
→
Hash the received message
→
Compare hashes
Sign with PRIVATE key, verify with PUBLIC key -- this is the OPPOSITE of encryption (where you encrypt with public, decrypt with private).

Security Services Provided

ServiceHow Signatures Provide It
AuthenticationOnly the holder of the private key could have created the signature
IntegrityAny modification to the message changes the hash, invalidating the signature
Non-repudiationThe signer cannot deny signing because only they possess the private key
Signatures do NOT provide confidentiality. The message itself is not encrypted -- anyone can read it. Signatures only prove authenticity and integrity.
📜 5. Public Key Infrastructure (PKI)
Remember This
PKI = System for managing digital certificates and public keys

PKI is the framework of policies, procedures, and technology that manages digital certificates. It solves the fundamental problem of: "How do I know this public key really belongs to who they claim to be?"

Key Components

Chain of Trust

Why the Chain Matters: When your browser connects to a website via HTTPS, it verifies the server's certificate by tracing the chain back to a trusted Root CA in its local trust store.
Professor's Tip: Certificate revocation is critical but often overlooked. If a private key is compromised, the certificate must be revoked immediately. CRL and OCSP are the two mechanisms for this.
🚪 6. Trap-door Functions
Definition: A trap-door function is a one-way function that can be efficiently reversed IF you know a secret piece of information (the "trap door"). Without the trap door, reversal is computationally infeasible.

One-way functions are easy to compute in one direction but extremely hard to reverse. A trap-door one-way function adds a special property: there exists a secret that makes reversal easy.

RSA as a Trap-door Function

Forward (easy): Given m, e, n -- compute c = m^e mod n
Reverse (hard without trap door): Given c, e, n -- find m
Trap door: Knowing p and q (the factorization of n) allows computing d, which makes reversal trivial: m = c^d mod n
Foundation of ALL Public Key Crypto: Every public key algorithm relies on some trap-door function. RSA uses integer factorization. Diffie-Hellman and ElGamal use the discrete logarithm. Elliptic curve crypto uses the elliptic curve discrete log.
Professor's Tip: Think of a trap-door function like a mailbox: anyone can drop mail in (encrypt), but only the person with the key can open it (decrypt). The "key to the mailbox" is the trap door.
🔄 7. Hybrid Encryption
KEY IDEA: Modern systems combine asymmetric encryption (for key exchange) with symmetric encryption (for bulk data) to get the best of both worlds.

Why Hybrid?

Asymmetric encryption is 100-1000x slower than symmetric encryption. You cannot practically encrypt large amounts of data with RSA. But symmetric encryption has the key distribution problem. The solution: use both.

How It Works

Generate random AES session key
→
Encrypt data with AES key (fast)
→
Encrypt AES key with RSA public key
→
Send both

Real-World Example: TLS Handshake

TLS/HTTPS: The browser and server use RSA or Diffie-Hellman to agree on a shared AES session key. Then all bulk data flows encrypted with AES. This is why HTTPS is fast despite using public key crypto.

Envelope Encryption

Envelope encryption is the same concept applied to data at rest: encrypt data with a symmetric key (Data Encryption Key, or DEK), then encrypt the DEK with a public key (Key Encryption Key, or KEK). AWS KMS, Azure Key Vault, and GCP Cloud KMS all use this pattern.
ApproachSpeedKey DistributionUse Case
Symmetric onlyFastDifficultBulk data (after key exchange)
Asymmetric onlySlowEasySmall data, signatures
HybridFastEasyEverything (TLS, PGP, S/MIME)
🗝️ 8. Key Management
KEY IDEA: Cryptography is only as strong as key management. The algorithm can be perfect, but poor key handling breaks everything.

Key Lifecycle

PhaseRequirementsExample

StorageProtect private keys; never store in plaintextHSMs, key vaults, TPMs

RevocationInvalidate compromised or expired keysCRL, OCSP
DestructionSecurely destroy keys when no longer neededCryptographic erasure, HSM zeroization

Key Escrow

Key Escrow is when a third party holds a copy of encryption keys. This is highly controversial:
Law enforcement argument: Need access to encrypted communications for investigations
Privacy argument: Creates a single point of failure; if the escrow is breached, all keys are compromised
Professor's Tip: Key management failures cause more real-world crypto breaches than algorithm weaknesses. Always ask: "Where are the keys stored? Who has access? How are they rotated?"
😈 9. Man-in-the-Middle Attacks
KEY IDEA: MITM attacks exploit the lack of authentication in key exchange protocols. The attacker intercepts and relays communications, establishing separate keys with each party.

How MITM Works Against Diffie-Hellman

Man-in-the-Middle Attack on DH
ALICE MALLORY (Attacker) BOB | | | |--- A = g^a mod p --->| | | |--- M1 = g^m1 mod p ---->| | | | | |<--- B = g^b mod p -------| |<-- M2 = g^m2 mod p --| | | | | Alice thinks she Mallory has TWO Bob thinks he shares key with Bob shared keys: shares key with Alice but shares with one with Alice but shares with Mallory one with Bob Mallory Mallory decrypts, reads, re-encrypts, and forwards all messages!

Prevention Methods

  • Digital signatures: Sign DH parameters so the other party can verify authenticity
  • Certificates (PKI): Verify the identity of the other party through a trusted CA
  • Authenticated key exchange: Protocols like Station-to-Station (STS) that build authentication into DH

Double Key Creation (Law Enforcement Scenario)

"Double Key Creation": In some lawful intercept scenarios, a session key is encrypted once for the intended server AND once with law enforcement's public key. This allows law enforcement to decrypt the session while the communication appears normal to both parties.
Professor's Tip: Always remember -- Diffie-Hellman provides KEY EXCHANGE but NOT AUTHENTICATION. That is its fundamental weakness and why it must be combined with signatures or certificates.

🔢 11. Elliptic Curve Cryptography (ECC)
Remember This
ECC = lighter, more agile alternative to RSA with much smaller key sizes

Elliptic Curve Cryptography (ECC) is a modern public key cryptographic approach that offers equivalent security to RSA but with significantly smaller key sizes. This makes it ideal for constrained environments where processing power, memory, or battery life are limited.

Why ECC?

  • Smaller key sizes for equivalent security: ECC-256 provides roughly the same security as RSA-3072
  • Lighter and more agile: Less computational overhead means faster operations
  • Ideal for constrained devices: IoT sensors, mobile phones, smart cards, and other battery-powered or low-power devices
  • Lower bandwidth requirements: Smaller keys and signatures mean less data to transmit

Mathematical Foundation

ECC security is based on the Elliptic Curve Discrete Logarithm Problem (ECDLP). Given a point P on an elliptic curve and a point Q = kP (where k is an integer), it is computationally infeasible to determine k. This is analogous to the discrete logarithm problem used in Diffie-Hellman, but over elliptic curve groups instead of multiplicative groups of integers.

Professor's Tip: ECC is the modern choice for constrained environments. When you need public key cryptography on IoT devices, mobile platforms, or any resource-limited system, ECC is the answer. The key size advantage only grows as security requirements increase.
👻 12. "RSA Is Dead" Discussion
Despite the hype, 90% of internet SSL connections still use RSA in the handshake. But the trend is clear -- RSA faces mounting challenges.

Why RSA Is Under Pressure

  • Key length must keep growing: The CA/Browser Forum now requires a minimum of 3072 bits for RSA certificates. As computing power increases, keys must grow exponentially to maintain security.
  • Key scaling problem: RSA key sizes need to grow exponentially to keep pace with attackers, while ECC key sizes remain comparatively small. RSA-15360 for 256-bit security is impractical for most applications.
  • CSPRNG seeding vulnerability: If the cryptographically secure pseudo-random number generator (CSPRNG) used to generate RSA primes is poorly seeded or weak, the resulting RSA keys become predictable and breakable.

The Quantum Threat

Shor's Algorithm: A quantum algorithm that can factor large numbers in polynomial time. If a sufficiently powerful quantum computer is built, it would break RSA entirely -- no matter the key size. This is not a theoretical concern; it is a question of when, not if.

RSA vs ECC Trajectory

Professor's Tip: RSA is not dead yet, but the writing is on the wall. The real killer is quantum computing -- Shor's algorithm breaks both RSA and ECC. The future belongs to post-quantum cryptography.
🔮 13. Post-Quantum Cryptography (PQC)
Remember This
Shor's algorithm breaks RSA, DH, and ECC. NIST is standardizing quantum-resistant replacements.

The Quantum Threat Explained

Shor's Algorithm is a quantum algorithm that can efficiently factor large numbers and solve the discrete logarithm problem in polynomial time. This means it breaks:

  • RSA -- based on factoring large prime products
  • Diffie-Hellman -- based on the discrete logarithm problem
  • ECC -- based on the elliptic curve discrete logarithm problem

NIST PQC Standardization

NIST has been running a multi-year effort to select and standardize quantum-resistant algorithms. The five candidate categories are:

#CategoryExamplesStatus
1Code-based cryptographyMcElieceLong-standing, large keys
2Lattice-based cryptographyCRYSTALS-Kyber (encryption), CRYSTALS-Dilithium (signatures)NIST winners -- primary standards
3Hash-based signaturesSPHINCS+NIST selected (conservative choice)
4Multivariate polynomialRainbow (broken), GeMSSUnder continued research
5Super-singular isogeny-basedSIKEBroken in 2022
SIKE Warning: Super-singular isogeny key encapsulation (SIKE) was a NIST PQC candidate, but it was catastrophically broken in 2022 by classical (non-quantum) attacks. This shows that even "quantum-resistant" candidates need rigorous vetting.

"Harvest Now, Decrypt Later" Threat

Critical Threat Model: Adversaries (especially nation-states) are collecting encrypted data today with the plan to decrypt it later when quantum computers become available. This means data encrypted with RSA or ECC today may have a limited shelf life for confidentiality.

Transition Timeline

NIST expects organizations to complete migration to PQC algorithms by 2035. Given the complexity of cryptographic transitions (remember how long it took to move from DES to AES, or SHA-1 to SHA-2), organizations should begin planning now.

Professor's Tip: The "harvest now, decrypt later" threat is why PQC matters TODAY, not just when quantum computers arrive. Any data that needs to remain confidential for 10+ years is already at risk.
Exam-Tested Details from Homework

Diffie-Hellman Calculation Steps (Exam Problem Format)

You MUST be able to do these by hand or in Excel. The professor tests actual DH calculation problems on the exam.
Given: g = 2, p = 19, Alice's secret a = 6, Bob's secret b = 3

Step 1 -- Alice computes her public value:
Y = ga mod p = 26 mod 19 = 64 mod 19 = 7

Step 2 -- Bob computes his public value:
C = gb mod p = 23 mod 19 = 8 mod 19 = 8

Step 3 -- Shared secret (both arrive at the same value):
Alice: S = Ca mod p = 86 mod 19
Bob: S = Yb mod p = 73 mod 19 = 343 mod 19 = 1

Repeated Squaring Method (for larger exponents)

Example: 86 mod 19
82 = 64 mod 19 = 7
84 = 72 = 49 mod 19 = 11
86 = 84 * 82 = 11 * 7 = 77 mod 19 = 1

This technique breaks large exponents into powers of 2, making modular exponentiation manageable by hand.
EXAM TRAP: Both parties MUST arrive at the same shared secret. If your calculations give different values for Alice and Bob, you made an arithmetic error. Always verify by computing S both ways.

"One-way function is ___ to compute"

Professor's Tip (Fill-in-blank tested): The correct fill-in answers are: "easy", "simple", or "feasible". Do NOT answer "efficient" -- the textbook specifically uses "easy to compute, hard to reverse."
Remember This
DH formula: Y = g^a mod p. Shared secret: S = (other party's public)^(my secret) mod p. One-way function = "easy" to compute, "hard" to reverse. Always verify both sides get the same S.
