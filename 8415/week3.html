1. Why Johnny Can't Encrypt (Whitten & Tygar, 1999)
LANDMARK STUDY: Usability evaluation of PGP 5.0 email encryption that demonstrated even technically competent users made critical security errors.

Background: Whitten and Tygar conducted a cognitive walkthrough and user study of PGP 5.0, one of the most widely available email encryption tools at the time.

Key Findings

  • The "Quill Pen" icon problem: Failed to communicate that the private key was being used for signing
  • Users consistently confused encryption with signing — thinking one operation did both
  • 1/3 of participants sent the secret without encrypting it
  • Even technically competent users could not use the system correctly
Professor's Insight: The quill pen icon is the classic example of a metaphor failure in security UI. Users saw "quill pen" and thought "writing/sending" — they had no mental model connecting it to cryptographic signing with a private key.
Key Insight: Security software must be usable or people won't use it correctly. The most secure system in the world is useless if users bypass or misuse it.
Remember This
"If Johnny can't encrypt, the crypto doesn't matter."
2. Why Cryptosystems Fail (Ross Anderson, 1993)
KEY FINDING: Most failures were NOT from broken algorithms but from implementation and configuration errors.

Study Focus: Anderson studied real-world failures of banking cryptographic systems, examining why systems with mathematically sound algorithms still failed in practice.

Major Findings

  • Over 90% of computer security failures attributed to configuration/implementation errors, not cryptanalysis
  • The cryptography community lacks a "learning mechanism" found in aeronautical engineering
  • Government agencies' secretive nature prevents shared learning from failures
  • Banking systems had "phantom withdrawals" — banks blamed customers rather than investigating system flaws
Caution: Anderson argued that security bugs should be tracked and published like aviation incidents. Without transparency, the same mistakes are repeated across organizations.
Aviation IndustryCrypto/Security Industry
Mandatory incident reportingSecrecy around failures
Shared learning databaseNo equivalent mechanism
Blame-free investigationBlame customers ("phantom withdrawals")
Continuous improvementRepeated same mistakes
Professor's Insight: This paper was revolutionary because it shifted focus from "is the math secure?" to "is the system secure?" Implementation quality matters more than algorithm strength.
3. The "U" in Crypto Stands for Usable
Study Focus: Usability evaluation of mobile cryptocurrency wallets, examining how interface design causes real financial losses.

Key Findings

  • "Uninformed people" gave 1-star reviews for issues the developer had no control over (e.g., network fees)
  • Primary cause of "double-spends": Poor interface design where the Send button fails to provide immediate clear feedback
  • Users apply a "traditional payment system" mental model — expecting reversibility that doesn't exist in blockchain
  • A single UX mistake = permanent financial loss with no recovery
The Barn Door Property: Once a secret is exposed, you can't un-expose it. This is amplified by blockchain irreversibility — errors are permanent.
Why UX Errors Are Catastrophic in Crypto
Traditional Payment: User Error --> Bank Reversal --> Recovery Possible Blockchain Payment: User Error --> Transaction Confirmed --> PERMANENT LOSS (Barn Door Property) No undo. No customer service. No reversal.
Professor's Insight: The "double-spend" problem in wallets isn't a cryptographic failure — it's a UX failure. Users tap Send, see no feedback, tap again, and send twice. The fix is UI design, not better cryptography.
4. The Abstraction Property of Security
Core Concept: Security management involves abstract rules and policies that are often alien to the general user population.
  • Users don't think about security until something goes wrong
  • Security concepts (keys, certificates, trust models) are inherently abstract
  • General users lack mental models for cryptographic operations
  • Good design makes security invisible and automatic
Design Implication: The best security is security that users never have to think about. When security is visible, users find ways to bypass it. When it's invisible and automatic, it actually protects them.
Remember This
"The best lock is one the user doesn't know is there."

Professor's Insight: "Earn or Give, But Never Assume, Trust" is the one that catches students. It means: if a client says "I'm authorized," the server should NEVER just believe it. Trust must be earned (verified) or explicitly given (by the server), never assumed.

6. OWASP Cryptographic Failures (Top 10 #2)
Three Primary Categories of Cryptographic Failures:
CategoryDescriptionExample
Loss of ConfidentialityData exposure to unauthorized partiesUnencrypted PII in transit
Non-repudiation FailureCannot prove who performed an actionMissing digital signatures on transactions
Failed Integrity ChecksCannot verify data hasn't been tampered withNo hash verification on downloads
Exam Trap: "Access control vulnerabilities" is NOT one of the three primary categories of OWASP cryptographic failures. Access control is a separate OWASP Top 10 category (#1: Broken Access Control).

Common Cryptographic Mistakes

  • Using weak algorithms: MD5, SHA-1, DES
  • Hardcoded keys in source code
  • Improper key management (no rotation, shared keys)
  • Using encryption without authentication (no HMAC/AEAD)
Best Practice: Use AES-256-GCM (provides both encryption and authentication), rotate keys regularly, never hardcode secrets, use a key management service (KMS).
7. Cognitive Walkthrough Method
Definition: A usability evaluation technique where an evaluator mentally simulates a novice user's understanding of an interface — particularly fitting for evaluating security software.

Key Characteristics

  • Concerned with learnability — can a new user figure out the interface?
  • Can be done WITHOUT actual users (expert evaluation method)
  • Evaluator asks at each step:
    • "Will the user know what to do?"
    • "Will they notice the correct action?"
    • "Will they understand the feedback?"
Professor's Insight: Cognitive walkthrough is "particularly fitting" for security evaluation because security tasks are often infrequent (users don't practice them) and high-stakes (mistakes have serious consequences). You need learnability evaluation for tasks users rarely perform.
Why It Works for Security: You don't need to recruit users and expose them to real security risks. An expert can identify where novice users will fail by systematically walking through each step of a security task.
8. The Barn Door Property
Core Principle: Once a secret is accidentally exposed, there's no way to be sure an attacker hasn't already accessed it.

The metaphor: Once the barn door is open and the horse has bolted, closing the door doesn't bring the horse back. Similarly, once a cryptographic key or sensitive data is exposed, you cannot "un-expose" it.

Implications

  • Makes PREVENTION of high-cost errors a design priority (not recovery)
  • Especially critical in crypto wallets: blockchain irreversibility means errors are permanent
  • Design guardrails BEFORE mistakes happen, not recovery mechanisms after
  • Assume any exposed key/secret is compromised — rotate immediately
The Barn Door Property
BEFORE exposure: Secret is SAFE (Prevention is possible) AFTER exposure: Secret is COMPROMISED FOREVER (No way to guarantee attacker didn't copy it) Design Priority: BUILD GUARDRAILS BEFORE THE DOOR OPENS Not recovery mechanisms after.
Remember This
"You can't un-ring a bell. You can't un-expose a key."
9. Designing Usable Security

Key Design Principles for Usable Security

  • "Authorize After You Authenticate" — Identity verification is separate from permission checking
  • "Earn or Give, But Never Assume, Trust" — Don't trust client-side validation
  • Make the secure path the easiest path — If the insecure way is easier, users will choose it
  • Users have misconceptions about transaction reversibility
  • Provide safe staging and practice environments for irreversible actions
Design Guidelines:
PrincipleImplementation
Secure path = easiest pathDefault to secure options; require effort to downgrade
Immediate feedbackShow transaction status clearly; prevent double-clicks
Confirmation for irreversible actionsMulti-step confirmation for high-value transactions
Practice environmentsTestnets, sandboxes for learning without risk
Clear mental modelsUse metaphors users understand; avoid jargon
Professor's Insight: The "Double Key Creation" scenario in law enforcement access involves encrypting a symmetric session key once for the server and once with a law enforcement public key. This is how key escrow works — and it's a usability challenge because users don't understand what's happening behind the scenes.
10. Key Design Principles Summary
Summary of Core Principles from All Readings:
  • Security should be invisible to users when possible
  • Never sacrifice usability for security or vice versa
  • Test with real (non-expert) users

11. The Clipper Chip & Key Escrow Debate
CRYPTO POLICY LANDMARK: In 1993, the US government proposed the Clipper Chip — a hardware encryption device with a built-in government backdoor. This became one of the defining battles in cryptographic policy.

What Was the Clipper Chip?

  • A hardware encryption device proposed by the US government in 1993
  • Used the Skipjack algorithm (classified at the time)
  • Built-in key escrow: government holds copies of encryption keys
  • Intended for use in telecommunications equipment

Key Escrow: The Core Mechanism

Key escrow means a copy of every encryption key is held by a trusted third party (in this case, the government). Law enforcement could obtain escrowed keys with a warrant to decrypt communications.

Arguments For and Against

Argument FORArgument AGAINST
Law enforcement needs access to encrypted communicationsBackdoors weaken security for everyone
National security requires surveillance capabilitySingle point of failure — if escrow keys leak, all communications compromised
Warrant-based access is constitutional"Who watches the watchers?" — no accountability guarantees

What Killed the Clipper Chip

  • Matt Blaze found a vulnerability in the Clipper Chip protocol, demonstrating the escrow mechanism could be bypassed
  • Massive public backlash and crypto community opposition
  • The proposal was eventually abandoned
Professor Fossaceca's Emphasis: This is a recurring theme in crypto policy — you cannot have strong encryption AND guaranteed government access. This is a fundamental trade-off, not a solvable engineering problem.
Remember This
"You can't build a door that only the good guys can walk through."
12. Law Enforcement Access to Encrypted Data
THE "GOING DARK" PROBLEM: Law enforcement agencies argue they are "going dark" — unable to access encrypted communications even with a valid warrant.

Apple vs FBI (2015-2016)

  • FBI demanded Apple create a backdoor to unlock the San Bernardino shooter's iPhone
  • Apple refused, citing it would set a dangerous precedent
  • Creating a tool to bypass encryption would put all iPhone users at risk
  • FBI eventually used a third-party tool (Cellebrite) to access the phone
  • The case was dropped, but the legal and policy questions remain unresolved

Double Key Creation Scenario

One proposed solution: encrypt the session key once for the server AND once with law enforcement's public key. This gives law enforcement the ability to decrypt communications when needed.

The Fundamental Tension: Individual privacy vs. public safety. There is no known technical solution that provides access only to "good guys" — any backdoor can potentially be exploited by attackers.
The Encryption Access Dilemma
Strong Encryption (No Backdoor): Citizens: PROTECTED Law Enforcement: LOCKED OUT Weak Encryption (With Backdoor): Citizens: VULNERABLE Law Enforcement: CAN ACCESS Attackers: CAN ALSO ACCESS No middle ground exists.
Professor's Insight: The Apple vs FBI case is the modern version of the Clipper Chip debate. The technology changes, but the fundamental trade-off remains identical.
13. Ronin Network Hack — Usability Failure Case Study
CASE STUDY: In March 2022, $620 million was stolen from the Ronin Network (Axie Infinity blockchain bridge) — one of the largest crypto hacks in history.

What Happened

  • Root cause: Compromised private keys — attackers gained control of 5 of 9 validator nodes
  • The organization had reduced security validators from 9-of-9 to 5-of-9 for "convenience"
  • A temporary permission given to Sky Mavis was never revoked
  • Attackers exploited these relaxed controls to sign fraudulent transactions

Why This Is a Usability Failure

  • Security configuration was weakened to improve operational convenience
  • Demonstrates the Barn Door Property in action — once keys were compromised, funds were irrecoverable
  • Blockchain irreversibility amplified the damage — no "undo" button
  • Temporary elevated permissions became permanent attack surface
Ronin Network: How Convenience Killed Security
Original Design: 9-of-9 validators required (Very secure, but slow) | v "Convenience" Change: 5-of-9 validators required (Faster, but lower threshold) | v Forgotten Permission: Sky Mavis still had validator access (Temporary became permanent) | v Attack: Attacker compromised 5 nodes $620M stolen. Irreversible.
Key Lesson: Security configuration shortcuts have permanent consequences. Reducing security for convenience is a form of technical debt that can result in catastrophic, irreversible loss.
Remember This
"Temporary permissions that aren't revoked become permanent vulnerabilities."
14. Exam-Tested Details from Homework
HIGH-YIELD: These concepts have appeared on homework assignments and are likely to be tested on exams. Know them precisely.

OWASP Rename

"Sensitive Data Exposure" was renamed to "Cryptographic Failures" in the 2021 OWASP Top 10 to shift focus from the broad symptom (exposure) to the root cause (cryptographic failure).

"Domain-Specific" UX Issue

In crypto wallets, users assume transactions are reversible or can be cancelled like traditional banking. This is a domain-specific misunderstanding unique to cryptocurrency.

IEEE: Flaw vs Bug Distinction

  • FLAW = result of a mistake or oversight during the DESIGN process
  • BUG = an implementation-level issue
  • Flaws are harder to fix because they're architectural

"Replace-by-Fee" (RBF)

Method to "overwrite" a stuck Bitcoin transaction by sending a new one with a higher fee. This is a UX mechanism to handle stuck transactions, not a security flaw.

Hard-Coded Passwords

Using hard-coded passwords in configuration files is a significant failure mode because it increases the risk of unauthorized access if the config file or source control is compromised. Tested on HW3.

Anderson's "Paradigm Shift"

Anderson argued the overdue paradigm shift in computer security is fusing security with software engineering and focusing on implementation/management — not just algorithm design.

"Unmotivated User Property"

Users don't actively seek out security controls because their primary intent is to complete a different task (browsing, emailing, etc.). Security is never the user's goal.

"Lack of Feedback Property"

Security software can't perform useful error checking because only the user knows what they "truly want." The system can't distinguish between intentional and accidental actions.

Salting vs Seeding

  • SEEDING = provides a starting point for random series generation
  • SALTING = ensures hash values are unique for the same input
  • Different purposes — tested on HW3

96% Negative Reviews

In the "U in Crypto" study, 96% of app reviews pertaining to user experience were negative (NOT 94%). Know the exact number.

Most Common PGP Error

Users who "figured out how to encrypt" made the mistake of encrypting with their OWN public keys instead of the RECIPIENT'S public key. So recipients couldn't decrypt.

Security Specification (Anderson)

Should not only list failure modes but ALSO detail the strategy adopted to prevent each failure mode or make it acceptably unlikely.

"Agility" (IEEE)

The capability to change layers and algorithms as needed. Design crypto systems so components can be swapped when algorithms become broken.

"Political Campaign Coordinator" (Johnny Study)

The role was assigned to provide a plausible, motivating context that mirrored the real-world value of protecting secrets. It wasn't testing political knowledge.

Professor's Insight: These homework-tested details test precise recall. Pay attention to exact numbers (96%, not 94%), exact terminology (flaw vs bug), and the reasoning behind study design choices.
Remember This
"Flaws are by design, bugs are by implementation. Salting is for hashes, seeding is for randomness."
