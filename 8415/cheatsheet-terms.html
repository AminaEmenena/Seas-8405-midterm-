W1 - Ciphers, Fundamentals & Hashing
  • Caesar cipher: shift each letter by a fixed number (monoalphabetic, broken by frequency analysis)
  • Vigenere cipher: poly-alphabetic substitution using a repeating keyword (broken by Kasiski exam)
  • Bifid cipher: uses a 5x5 Polybius square grid, combines substitution + transposition
  • Rail Fence: transposition cipher -- write plaintext in zigzag rows, read off by row
  • Substitution vs Transposition: sub CHANGES letters, trans REARRANGES positions
  • Shannon's perfect secrecy: P(M|C)=P(M) -- ciphertext reveals nothing. Key must be >= message length
  • One-Time Pad (OTP): only perfectly secure cipher. Key as long as message, truly random, never reuse. Impractical
  • Symmetric encryption: same key to encrypt and decrypt. Fast (100-1000x). AES, DES, 3DES
  • Asymmetric encryption: key pair (public/private). Slow. Solves key distribution. RSA, ECC, DH
  • Hybrid encryption: asymmetric for key exchange + symmetric for bulk data (TLS model)
  • Kerckhoffs' principle: security must reside in the KEY, not the algorithm. All modern algos are public
  • Computational security: breaking is theoretically possible but takes too long to be practical
  • Hashing: one-way function, fixed-size output, collision resistant, avalanche effect. NOT encryption
  • SHA-256: current standard hash (256-bit). MD5 (128-bit): BROKEN. SHA-1 (160-bit): deprecated
  • Salting: random value added before hashing -- prevents rainbow table attacks. NOT same as seeding
  • HMAC: keyed hash -- provides integrity + authentication. NOT confidentiality. NOT non-repudiation
  • Confusion: each ciphertext bit depends on several parts of the key (S-boxes provide this)
  • Diffusion: changing one plaintext bit changes ~half of ciphertext bits (ShiftRows/MixColumns)
  • Data states: at rest (AES), in transit (TLS), in use (enclaves, HE) -- protect all three
  • Block cipher: encrypts fixed-size blocks (AES = 128-bit blocks)
  • Stream cipher: encrypts one bit/byte at a time (RC4, ChaCha20)
  • PRNG/CSPRNG: pseudo-random number generator. Crypto needs CSPRNG (unpredictable)
  • Nonce: number used ONCE -- prevents replay attacks
W2 - Asymmetric Crypto & Key Exchange
  • Diffie-Hellman (1976): first public key exchange protocol. Shared secret = g^(ab) mod p
  • DH vulnerability: no authentication built in -- vulnerable to man-in-the-middle attack
  • RSA (1977): based on difficulty of factoring N = p*q. Encrypt: C = M^e mod n. Decrypt: M = C^d mod n
  • RSA key generation: pick primes p,q. n=pq. phi=(p-1)(q-1). Pick e coprime to phi. d = e^-1 mod phi
  • Public key: (e, n) -- shared with everyone. Private key: (d, n) -- kept secret
  • Trap-door function: easy one way (multiply primes), computationally hard to reverse (factor product)
  • Digital signature: sign with PRIVATE key, verify with PUBLIC key. Hash message first, then encrypt hash
  • Non-repudiation: signer cannot deny signing. Only asymmetric sigs provide this (not HMAC)
  • Signature provides: authentication + integrity + non-repudiation (NOT confidentiality)
  • PKI: Public Key Infrastructure -- Certificate Authority issues X.509 certificates, chain of trust
  • Certificate revocation: CRL (periodic published list) or OCSP (online real-time check)
  • X.509: standard format for digital certificates. Contains public key + identity + CA signature
  • Man-in-the-middle (MITM): attacker intercepts key exchange, impersonates both parties
  • Key escrow: third party holds copy of key. Controversial (Clipper Chip). Backdoor risk
  • N users symmetric keys: N(N-1)/2 keys needed. Asymmetric solves this: just 2N keys
W3 - Number Theory & Math Foundations
  • Modular arithmetic: remainder after division. "Clock arithmetic." a mod n = remainder
  • GCD: greatest common divisor. Euclidean algorithm computes it efficiently
  • Coprime: two numbers with GCD = 1. Critical for RSA (e must be coprime to phi)
  • Euler's totient phi(n): count of integers 1..n coprime to n. phi(p) = p-1 for prime p
  • Fermat's Little Theorem: a^(p-1) = 1 mod p (where p is prime and gcd(a,p)=1)
  • CRT (Chinese Remainder Theorem): solve system of modular equations simultaneously
  • Discrete Logarithm Problem (DLP): given g, p, and g^x mod p, find x. HARD. Basis for DH/ElGamal
  • Prime factorization: no efficient algorithm for large numbers -- this is why RSA works
  • Extended Euclidean algorithm: finds modular inverse. Used in RSA to compute d
  • Key space: n-bit key = 2^n possibilities. Brute force average = 2^(N-1) attempts
  • Primes > 3: always of the form 6k +/- 1
W4 - Symmetric Encryption Deep Dive
  • DES: 56-bit key, BROKEN. Deep Crack brute-forced it in 22 hours (1998)
  • 3DES (Triple DES): apply DES three times. 112-bit effective security. Deprecated, 3x slower
  • AES (Rijndael): won NIST competition (2001). 128/192/256-bit keys. Current standard
  • AES rounds: 10 rounds (128-bit), 12 rounds (192-bit), 14 rounds (256-bit)
  • AES four operations: SubBytes (S-box) -> ShiftRows -> MixColumns (NOT in final round) -> AddRoundKey
  • State array: 4x4 matrix of bytes that AES operates on. Block size = 128 bits
  • GF(2^8): Galois Field -- the math space for AES byte-level operations
  • S-box: nonlinear substitution lookup table. Provides confusion
  • ECB mode: deterministic. Same plaintext block = same ciphertext. NEVER USE (penguin pattern leak)
  • CBC mode: XOR plaintext with previous ciphertext block. Needs IV. Sequential (not parallelizable)
  • CTR mode: counter mode. Parallelizable. Turns block cipher into stream cipher. No padding needed
  • GCM mode: authenticated encryption = confidentiality + integrity. Gold standard. CTR + auth tag
  • Feistel structure: DES uses this -- split block in half, round function, swap halves
  • SPN: Substitution-Permutation Network -- AES uses this (NOT Feistel). Full block transformation
  • IV (Initialization Vector): random starting value for CBC/CTR. Must not repeat with same key
W5 - Zero Knowledge Proofs & Trust
  • ZKP: prove you know a secret WITHOUT revealing the secret itself
  • Completeness: honest prover always convinces honest verifier
  • Soundness: cheater cannot fool verifier (except negligible probability)
  • Zero-knowledge: verifier learns nothing beyond the truth of the statement
  • Cheating probability: 1/2^n after n rounds. 20 rounds ~ 1 in a million
  • Ali Baba Cave: classic ZKP example. Peggy proves secret word to Victor interactively
  • Fiat-Shamir heuristic: converts interactive ZKP to non-interactive via hash function
  • zk-SNARKs: ~100 bytes, ~10ms, needs trusted setup, quantum VULNERABLE
  • zk-STARKs: ~100s KB, 50-100ms, NO trusted setup, quantum RESISTANT
  • "Trusting Trust" (Ken Thompson 1984): compiler can hide backdoor. Trust is fundamental. Turing Award
  • "Why Cryptosystems Fail" (Anderson): >90% failures = implementation bugs, NOT broken algorithms
  • "Why Johnny Can't Encrypt": PGP usability study. 1/3 sent secrets unencrypted. Crypto must be usable
  • OWASP Top 10 crypto failures (#2): insecure algos, hardcoded keys, weak random, missing encryption
  • Side-channel attacks: timing, power analysis -- exploit implementation, not the math
W6 - AES & Algorithm Selection
  • AES competition: 15 candidates -> 5 finalists -> Rijndael selected (Daemen & Rijmen, Belgium)
  • Selection criteria: security, performance, flexibility, implementation simplicity
  • Key schedule: RotWord, SubWord, Rcon XOR to generate round keys from original key
  • Deep Crack (1998): custom hardware brute-forced DES in 22 hours. Proved 56-bit insufficient
  • SKIPJACK/EES: NSA cipher with key escrow (Clipper Chip). Matt Blaze found vulnerability. Abandoned
  • Key escrow lesson: cannot have strong encryption AND guaranteed government access
  • PQC NIST standards: FIPS 203 (ML-KEM/Kyber), FIPS 204 (ML-DSA/Dilithium), FIPS 205 (SLH-DSA/SPHINCS+)
  • Grover's algorithm: halves effective key length. AES-128 -> 64-bit (broken). AES-256 -> 128-bit (safe)
  • Shor's algorithm: breaks RSA, DH, ECC on quantum computer. "Harvest now, decrypt later" threat
  • PQC migration target: 2035. SIKE was candidate but BROKEN in 2022
W8 - Blockchain & Digital Cash
  • Digital cash (Schneier): anonymous, untraceable. 4 protocols (#1 basic -> #4 secret splitting with XOR identity reveal)
  • 6 properties (Okamoto & Ohta): Independence, Security, Privacy, Off-line, Transferability, Divisibility
  • DigiCash: David Chaum 1989. First practical digital cash. Bankruptcy 1998
  • Byzantine Generals Problem (Lamport): achieving consensus with malicious/faulty nodes
  • Byzantine solution: solvable if >2/3 loyal (oral messages), ANY number (written/signed messages)
  • Paxos: consensus for unreliable networks. Less robust but cheaper than Byzantine
  • Blockchain: tamper-evident/resistant distributed ledger (NISTIR 8202). No central authority
  • DLT: Distributed Ledger Technology -- all participants access immutable records
  • Smart contracts: rules encoded on blockchain that auto-execute when conditions met
  • Full node: stores entire blockchain. Publishing node: full + creates new blocks
  • Lightweight node: no copy of chain, passes transactions to full nodes
  • Blockchain virtues: Verifiable, Immutable, Tamper-resistant
  • Double-spend problem: blockchain solves this without needing a central authority
  • Ronin hack (2022): $620M stolen -- largest blockchain theft
W9 - Elliptic Curve Cryptography
  • ECC: discovered 1985 by Koblitz and Miller independently. Levchin Prize 2021
  • Elliptic curve equation: y^2 = x^3 + ax + b (Weierstrass form). Symmetric about x-axis
  • Curve validity condition: 4a^3 + 27b^2 != 0 (ensures no singularities)
  • Point at Infinity: identity element in ECC (like zero in addition)
  • Point Addition: line through P and Q, find third intersection, reflect over x-axis = P+Q
  • Point Doubling: tangent at P, find intersection, reflect = 2P
  • ECDLP: given P and Q=kP, find k. Computationally hard. NO sub-exponential algorithm known
  • Key size advantage: 160-bit ECC = 1024-bit RSA. 256-bit ECC = 3072-bit RSA
  • Why shorter keys: no sub-exponential attack on ECDLP (unlike factoring for RSA)
  • ECDH: ECC version of Diffie-Hellman key exchange
  • ECDSA: ECC digital signatures. Used in Bitcoin and TLS 1.3
  • Finite field / Galois field: GF(p^n) -- set of integers with modular arithmetic operations
  • Algebraic hierarchy: Group -> Ring -> Field (each adds operations)
  • Index-calculus: powerful DLP attack but NOT applicable to EC groups (why ECC is stronger)
  • ECC weaknesses: vulnerable to quantum computers (like RSA). More dependent on true randomness
W10 - Homomorphic Encryption & MPC
  • Homomorphic Encryption (HE): compute on encrypted data WITHOUT decrypting first
  • PHE (Partial): one operation, unlimited times. RSA = multiply. Paillier = add
  • SWHE (Somewhat): both add and multiply, but limited number of times (noise grows)
  • FHE (Fully): both operations, unlimited times. The "holy grail" of encrypted computation
  • RSA is multiplicatively homomorphic: E(m1)*E(m2) = E(m1*m2). But NOT additive
  • Paillier: additively homomorphic + probabilistic (random r). Used for secure voting
  • Gentry (2009): first FHE scheme using ideal lattices. MacArthur Fellow 2014
  • Bootstrapping: homomorphically evaluate decryption to refresh noisy ciphertext. Solution AND bottleneck
  • RAD paper (1978): Rivest-Adleman-Dertouzos coined "privacy homomorphisms" -- the origin
  • BFV scheme: exact integer arithmetic on encrypted data
  • CKKS scheme: approximate arithmetic -- good for ML and floating point
  • MPC: multiple parties compute a function without revealing their individual inputs
  • Yao's Millionaire's Protocol: who is richer without revealing actual wealth? Uses RSA
  • Additive secret sharing: split value into random shares that sum to original
  • RevEAL: side-channel attack on Microsoft SEAL. Math security != implementation security
  • Google FHE Transpiler: converts plaintext C++ code to work on encrypted data
W11 - Real World Systems (Email, SSL/TLS)
  • 5 security services: Authentication, Key Agreement, Confidentiality, Integrity, Nonrepudiation
  • Secure email: sender UNILATERALLY chooses crypto (no negotiation with recipient)
  • S/MIME: requires X.509 certificate from a Certificate Authority
  • PGP pipeline: hash(MD5) -> sign(RSA private) -> ZIP -> encrypt(IDEA session key) -> encrypt key(RSA pub)
  • Sign-then-encrypt: PGP and SSL use this. Signature on plaintext, must decrypt before verifying
  • Encrypt-then-sign: IPsec uses this. Can verify signature before decrypting. Efficient for automation
  • SSL/TLS provides: authentication + confidentiality + integrity. Does NOT provide nonrepudiation
  • SSL deprecated: 2015. TLS 1.3 is current standard (RFC 8446)
  • TLS two protocols: Record (how to transmit data) + Handshake (negotiate keys and ciphers)
  • 6 secret keys per TLS session: 3 per direction (encryption key + HMAC key + IV)
  • Cipher suite: key exchange algo + encryption algo + hash algo + compression
  • Export-grade ciphers: deliberately weak 40-bit keys due to US export regulations
  • TLS attacks: Heartbleed, BEAST, CRIME, POODLE -- all targeted implementations, not math
  • HTTP port 80, HTTPS port 443: TLS sits between application and transport layers
  • Digital certificates: X.509 format. CA trust chain. Always check revocation status
W12 - Wireless Crypto & Stream Ciphers
  • RC4: stream cipher. Key Setup (S-box init) -> Keystream generation -> XOR with plaintext
  • RC4 key reuse: FATAL. XOR cancels the keystream, exposing plaintext
  • WEP: RC4 + 24-bit IV + 40-bit key. IV repeats in hours. FMS attack. CRC-32 (not crypto hash). Crackable in 5 hours
  • WEP bit-flipping: CRC-32 is linear (not a cryptographic hash) so attacker can modify ciphertext
  • WPA: TKIP fix -- 48-bit IV, hashed IV+key, MIC. Still RC4-based. Temporary stepping stone
  • WPA2 (802.11i): AES-CCMP replaces RC4. 4-way handshake. PSK (personal) vs Enterprise (RADIUS)
  • 4-way handshake: ANonce/SNonce exchanged -> derive PTK from PMK. Proves both sides know PMK
  • Cracking WPA2-PSK: capture handshake, offline dictionary attack. NOT cryptographically broken -- just weak passwords
  • KRACK attack: replays handshake -> key reinstallation -> nonce reuse. Targets implementation, NOT AES. Affects clients
  • WPA3: SAE/Dragonfly (forward secrecy, brute force resistant), PMF required, 128-bit personal / 192-bit enterprise
  • 802.1X + EAP + RADIUS: enterprise auth framework. PEAP (server certs) vs EAP-TLS (client certs)
  • Evil Twin: fake AP with stronger signal, intercepts traffic. VPN protects against it
  • Rogue AP: unauthorized AP on corporate network, bypasses firewall
  • Supplicant: client device that must authenticate before getting network access
  • Wireless evolution: WEP (broken) -> WPA (TKIP temp fix) -> WPA2 (AES-CCMP) -> WPA3 (SAE/Dragonfly)
KEY SIZE EQUIVALENCES
  • 80-bit symmetric = 1024-bit RSA = 160-bit ECC
  • 128-bit symmetric = 3072-bit RSA = 256-bit ECC
  • 256-bit symmetric = 15360-bit RSA = 512-bit ECC
EMAIL vs SSL/TLS
  • Email (PGP): unilateral crypto, nonrepudiation YES, sign-then-encrypt
  • SSL/TLS: negotiated cipher suite, nonrepudiation NO, 6 keys/session, sign-then-encrypt
  • IPsec: negotiated, nonrepudiation NO, encrypt-then-sign, network layer
HE TYPES AT A GLANCE
  • PHE: one op unlimited. RSA=multiply, Paillier=add, ElGamal=multiply
  • SWHE: both ops, limited depth (noise grows)
  • FHE: both ops, unlimited. Gentry 2009. Bootstrapping is the key insight
  • Schemes: BFV=exact integers. CKKS=approximate/ML. Paillier=addition only
WIRELESS EVOLUTION
  • WEP: RC4 + 24-bit IV. Broken in hours. CRC-32 linear. FMS attack
  • WPA: TKIP (RC4 + 48-bit IV + MIC). Temporary fix
  • WPA2: AES-CCMP. 4-way handshake. KRACK vuln (implementation)
  • WPA3: SAE/Dragonfly. Forward secrecy. 192-bit enterprise. Mandatory Wi-Fi 6
BLOCKCHAIN NODE TYPES

  • Publishing node: full node + creates new blocks
  • Lightweight node: no copy of chain, relies on full nodes
