🔀 1. Stream Ciphers vs Block Ciphers
KEY CONCEPT: Stream ciphers encrypt data one bit (or byte) at a time by XORing plaintext with a pseudo-random keystream. Block ciphers encrypt fixed-size blocks (e.g., 128 bits) at a time.

Comparison

Feature Stream Cipher Block Cipher
Unit of Encryption Bit or byte at a time Fixed block (64, 128 bits)
Operation XOR with keystream Substitution-permutation network or Feistel
Speed Very fast, low latency Slower, needs full block
Error Propagation Single bit (no propagation) Entire block affected
Use Case Wireless, real-time communication File encryption, TLS bulk data
Key Reuse NEVER reuse keystream -- catastrophic Key reuse with different IVs is safer
Stream Cipher Core Formula: Ci = Pi XOR Ki -- Each plaintext bit is XORed with the corresponding keystream bit. Decryption is the same operation: Pi = Ci XOR Ki.
Critical Warning -- Keystream Reuse: If the same keystream encrypts two messages, an attacker can XOR the ciphertexts to get P1 XOR P2, eliminating the key entirely. This is why nonce/IV management is essential.
Stream Cipher Operation
Key + Nonce ---> Keystream Generator ---> K1, K2, K3, K4 ... | Plaintext: P1, P2, P3, P4 ... | XOR <----------------------------+ Ciphertext: C1, C2, C3, C4 ...
⚙️ 2. LFSR -- Linear Feedback Shift Register
Definition: An LFSR is a shift register whose input bit is a linear function (XOR) of its previous state. With an n-bit register and a primitive polynomial, the maximum period is 2^n - 1.

How LFSRs Work

  • Shift register -- n flip-flops holding bits, shifting right each clock cycle
  • Feedback function -- XOR of selected "tap" positions feeds back to the input
  • Feedback polynomial -- Determines which taps are used (e.g., x^4 + x + 1)
  • Primitive polynomial -- Produces maximum-length sequence of period 2^n - 1
  • Output -- The bit shifted out each cycle becomes the keystream bit
4-bit LFSR Example (x^4 + x + 1)
+----[XOR]<-----------+ | | v | [b4] --> [b3] --> [b2] --> [b1] --> output (keystream bit) ^ | feedback taps at positions 4 and 1 +--- new bit fed back into register
FATAL FLAW -- Linearity: Because LFSRs are linear, the Berlekamp-Massey algorithm can reconstruct the entire LFSR (polynomial + state) from just 2n bits of known keystream. This is a devastating known-plaintext attack.

Fixing LFSR Vulnerabilities

Three Approaches to Nonlinearity

  • Nonlinear Combining -- Combine outputs of multiple LFSRs through a nonlinear Boolean function (e.g., majority function)
  • Clock-Controlled Generators -- Use one LFSR to control the clocking of another (irregular clocking breaks linearity)
  • Nonlinear Filters -- Apply a nonlinear function to multiple internal bits of a single LFSR to produce output
Memory Aid LFSR = "Linear = Learnable" -- 2n bits is all an attacker needs
📱 3. A5/1 -- GSM Stream Cipher
BROKEN CIPHER: A5/1 was the encryption algorithm for GSM mobile phone communications. Despite being a military secret initially, it was reverse-engineered and is now completely broken.

A5/1 Architecture

  • Three LFSRs -- R1 (19 bits), R2 (22 bits), R3 (23 bits) = 64 bits total state
  • Irregular clocking -- Each LFSR has a "clocking bit." At each step, the majority value of the 3 clocking bits is computed. Only LFSRs whose clocking bit agrees with the majority are actually clocked
  • Output -- XOR of the three LFSR output bits
  • Key -- 64-bit session key (but effectively 54 bits due to forced zero bits)
A5/1 Majority Clocking
R1 (19 bits) --clk bit 8--+ | R2 (22 bits) --clk bit 10-+--> MAJORITY --> clock only those | that match majority R3 (23 bits) --clk bit 10-+ Output = R1[18] XOR R2[21] XOR R3[22]

How A5/1 Was Broken

Attack Methods

  • Rainbow tables -- Precomputed tables allow real-time decryption of GSM calls
  • Known-plaintext -- GSM frames have predictable headers, providing known plaintext
  • Time-memory tradeoff -- Practical attack in seconds with precomputation
  • Small state space -- 64 bits total is too small by modern standards
A5/2 was even weaker -- deliberately weakened "export" version for non-Western countries. Broken in milliseconds. Both are deprecated; 3G/4G/5G use AES-based encryption.
🔒 4. RC4 -- Rivest Cipher 4
Definition: RC4 is a byte-oriented stream cipher designed by Ron Rivest in 1987. It was the most widely used stream cipher (SSL/TLS, WEP, WPA-TKIP) but is now prohibited in TLS 1.3 due to known biases.

RC4 Two-Phase Design

Phase 1: KSA (Key Scheduling Algorithm)

  • Initialize permutation array S[0..255] = {0, 1, 2, ..., 255}
  • Scramble S using the secret key (40-2048 bits)
  • Result: a key-dependent permutation of all 256 byte values

Phase 2: PRGA (Pseudo-Random Generation Algorithm)

  • For each output byte: update indices i, j using S
  • Swap S[i] and S[j]
  • Output S[(S[i] + S[j]) mod 256] as the keystream byte
  • XOR keystream byte with plaintext byte to encrypt

RC4 Vulnerabilities

Known Biases:
  • Second-byte bias -- P(second output byte = 0) = 2/256 instead of 1/256
  • Initial keystream biases -- First ~256 bytes have detectable statistical biases
  • Fluhrer-Mantin-Shamir (FMS) attack -- Exploits weak IVs in WEP to recover the key
  • Royal Holloway attack -- Statistical biases allow plaintext recovery in TLS with ~2^30 ciphertexts
Mitigation (historical): Drop the first 256 (or 3072) bytes of keystream output -- known as "RC4-drop[n]." But this is insufficient; RC4 should not be used in new systems.
Exam Note: RC4 is prohibited in TLS 1.3 (RFC 7465). Know the KSA/PRGA two-phase design and why initial byte biases make it insecure.
🏆 5. eSTREAM Competition
eSTREAM (2004-2008): European competition to identify new stream ciphers, organized by the ECRYPT network. Two profiles: software-optimized and hardware-optimized.

eSTREAM Winners

Profile Cipher Key Features
Software Rabbit 128-bit key, very fast on 32-bit CPUs
HC-128 128-bit key, large internal state (4 KB), strong security margin
Salsa20 256-bit key, by Daniel Bernstein. Basis for ChaCha20
SOSEMANUK Derived from Serpent block cipher + SNOW stream cipher
Hardware Grain 80-bit key, LFSR + nonlinear FSR combination
MICKEY 80-bit key, mutual irregular clocking of two registers
Trivium 80-bit key, elegant 3-register design, very compact in hardware
Memory Aid -- Software Winners "Rabbits Hop Smoothly on Salsa" -- Rabbit, HC-128, SOSEMANUK, Salsa20
🛡️ 6. ChaCha20-Poly1305 -- Modern AEAD
MODERN STANDARD: ChaCha20-Poly1305 is an Authenticated Encryption with Associated Data (AEAD) construction used in TLS 1.3, WireGuard, and many modern protocols. It pairs the ChaCha20 stream cipher with the Poly1305 MAC.

ChaCha20 Stream Cipher

  • Designer -- Daniel Bernstein (variant of his Salsa20 from eSTREAM)
  • Key size -- 256 bits
  • Nonce -- 96 bits (must never repeat with same key)
  • Block counter -- 32 bits (allows random access to keystream)
  • State -- 512-bit state matrix (4x4 of 32-bit words)
  • Operations -- Only ARX: Addition, Rotation, XOR (no S-boxes, no table lookups)
  • Rounds -- 20 rounds (10 column rounds + 10 diagonal rounds)

Why ChaCha20 over AES?

  • No timing side channels -- ARX operations run in constant time (no cache-timing attacks)
  • Fast in software -- Excellent performance without hardware AES-NI instructions
  • Mobile devices -- Better performance on ARM processors without AES hardware
  • Simpler implementation -- Less prone to implementation errors

Poly1305 MAC

  • One-time authenticator -- Produces a 128-bit authentication tag
  • Mathematically proven -- Based on polynomial evaluation modulo a prime (2^130 - 5)
  • Must use a unique key per message -- ChaCha20 derives a fresh Poly1305 key for each message
TLS 1.3 AEAD Suites: Only two AEAD algorithms: AES-GCM and ChaCha20-Poly1305. All non-AEAD ciphers (including RC4, CBC mode) are removed.
📡 7. Wireless Security -- WEP to WPA3
WEP IS CATASTROPHICALLY BROKEN. Understanding why it failed teaches fundamental lessons about cryptographic system design.

WEP -- Wired Equivalent Privacy (BROKEN)

WEP Design Flaws

  • 24-bit IV -- Only 16.7 million possible IVs. On a busy network, IVs repeat in hours
  • IV sent in plaintext -- Attacker can see the IV and correlate with known plaintext
  • RC4 weak keys -- Certain IV values produce weak RC4 key schedules (FMS attack)
  • CRC-32 integrity -- CRC is not cryptographically secure; attacker can modify ciphertext and fix the CRC without knowing the key
  • Static shared key -- Same key for all users, rarely changed
  • No mutual authentication -- Only client authenticates to AP, not vice versa
WEP Key (40/104 bit) + 24-bit IV --> RC4 Keystream XOR Plaintext + CRC-32

WPA -- Wi-Fi Protected Access

WPA (2003): Temporary fix using TKIP (Temporal Key Integrity Protocol) -- designed to run on existing WEP hardware with firmware updates.
  • Per-packet keys -- Mixes IV + base key + MAC address to create unique per-packet keys
  • 48-bit IV -- Extended from 24 to 48 bits (no more IV exhaustion)
  • MIC (Michael) -- Replaced CRC-32 with a cryptographic message integrity check
  • Still uses RC4 -- TKIP is a wrapper around RC4, so inherits some weaknesses

WPA2 -- AES-CCMP

WPA2 (2004, mandatory 2006): Full redesign using AES-CCMP (Counter mode with CBC-MAC Protocol).
  • AES-128 in counter mode for confidentiality
  • CBC-MAC for integrity and authentication
  • 48-bit packet number -- No IV reuse issues
  • 4-way handshake -- Derives per-session pairwise transient key (PTK)
  • Vulnerability -- KRACK attack (2017): forces nonce reuse in the 4-way handshake

WPA3 -- SAE/Dragonfly

WPA3 (2018): Major security upgrade.
  • SAE (Simultaneous Authentication of Equals) -- Replaces PSK with Dragonfly key exchange (password-authenticated key agreement)
  • Forward secrecy -- Compromising the password doesn't decrypt past traffic
  • Protected Management Frames (PMF) -- Mandatory, prevents deauth attacks
  • 192-bit enterprise mode -- CNSA suite with AES-256-GCM, SHA-384, ECDH P-384
  • OWE (Opportunistic Wireless Encryption) -- Encrypts open networks without passwords

Evolution Summary

Protocol Cipher IV Size Integrity Status
WEP RC4 24-bit CRC-32 BROKEN
WPA RC4-TKIP 48-bit Michael MIC Deprecated
WPA2 AES-CCMP 48-bit PN CBC-MAC Current
WPA3 AES-CCMP/GCMP 48-bit PN GMAC/CBC-MAC Latest
🔈 8. Bluetooth Security
Bluetooth uses the E0 stream cipher for encryption in Classic Bluetooth. Bluetooth Low Energy (BLE) uses AES-CCM. Both have known vulnerabilities.

E0 Stream Cipher

  • Four LFSRs -- Combined through a finite state machine (summation generator)
  • 128-bit key -- Derived from link key during pairing
  • Re-keyed every 2745 bits -- Limits exposure per key
  • Algebraic attacks -- Effective complexity reduced to ~2^38 (far below 128-bit security)

Pairing Modes

Mode Description Security
Just Works No user interaction Vulnerable to MITM
Numeric Comparison Both devices display 6-digit number, user confirms match MITM-protected
Passkey Entry User enters PIN on one or both devices MITM-protected
Out of Band (OOB) Uses NFC or other channel for pairing data MITM-protected

Notable Bluetooth Attacks

BlueBorne (2017): Remote code execution over Bluetooth without pairing. Affected ~5.3 billion devices across Android, iOS, Windows, Linux. Attacker just needs Bluetooth enabled and in range -- no user interaction required.
KNOB Attack (Key Negotiation of Bluetooth, 2019): Attacker forces Bluetooth devices to negotiate an encryption key with only 1 byte of entropy (8 bits), making brute-force trivial. Exploits the fact that entropy negotiation was not authenticated.
BIAS Attack (2020): Bluetooth Impersonation AttackS -- allows an attacker to impersonate a previously paired device by exploiting flaws in the Secure Connections establishment.
🛰 9. 5G Security Improvements
5G introduces significant security improvements over 4G/LTE, addressing known vulnerabilities in previous generations.

Key 5G Security Features

Feature 4G/LTE 5G
Identity Protection IMSI sent in plaintext (IMSI catchers) SUPI encrypted as SUCI using ECIES
Key Length 128-bit 128 or 256-bit
Authentication One-way (network authenticates UE) Mutual authentication (5G-AKA, EAP-AKA')
Integrity Protection User plane: optional User plane: supported
Network Slicing N/A Isolated security per slice
Roaming Security Limited inter-operator security SEPP (Security Edge Protection Proxy)
SUPI/SUCI: The Subscription Permanent Identifier (SUPI) is never sent over the air in plaintext. Instead, it is encrypted into a Subscription Concealed Identifier (SUCI) using the home network's public key with ECIES (Elliptic Curve Integrated Encryption Scheme). This prevents IMSI-catcher attacks.

5G Encryption Algorithms

  • NEA0 -- Null (no encryption, for emergency calls)
  • NEA1 -- SNOW 3G (stream cipher)
  • NEA2 -- AES-CTR (128-bit)
  • NEA3 -- ZUC (Chinese stream cipher)
Why This Matters: Each wireless generation learned from the failures of the previous one -- WEP's broken RC4 led to AES in WPA2, IMSI catchers in 4G led to SUCI in 5G. The pattern: security is iterative, driven by real-world attacks.

1 What is the fundamental difference between a stream cipher and a block cipher?

Stream ciphers use public keys while block ciphers use symmetric keys
Stream ciphers encrypt bit-by-bit using a keystream XOR, while block ciphers encrypt fixed-size blocks
Block ciphers are faster than stream ciphers
Stream ciphers provide authentication while block ciphers do not
Stream ciphers generate a pseudo-random keystream and XOR it with plaintext one bit or byte at a time. Block ciphers process fixed-size blocks (e.g., 128 bits) through substitution-permutation networks or Feistel structures.

2 Why is a basic LFSR insecure as a standalone stream cipher?

It produces too short a keystream period
It requires too much memory to implement
Its linearity allows the Berlekamp-Massey algorithm to reconstruct it from just 2n bits of known keystream
It can only generate binary output
LFSRs are linear systems, meaning the Berlekamp-Massey algorithm can determine the feedback polynomial and initial state from just 2n consecutive keystream bits (where n is the register length). This is a devastating known-plaintext attack.

3 How does A5/1 achieve nonlinearity despite using three LFSRs?

Irregular (majority-based) clocking -- only LFSRs whose clocking bit matches the majority value are clocked each cycle
Using a nonlinear S-box on the output
Applying AES encryption to the LFSR outputs
Using prime-length registers to avoid periodicity
A5/1 uses majority-based clocking: each LFSR has a designated clocking bit, and only those LFSRs whose clocking bit agrees with the majority of all three clocking bits are stepped. This irregular clocking introduces nonlinearity.

4 What are the two phases of RC4's operation?

Encryption phase and authentication phase
Key expansion and block processing
Initialization vector generation and stream output
KSA (Key Scheduling Algorithm) to initialize the permutation, then PRGA (Pseudo-Random Generation Algorithm) to produce keystream bytes
RC4 works in two phases: KSA scrambles the 256-byte permutation array S using the secret key, then PRGA generates keystream bytes by continually swapping elements and outputting S[(S[i]+S[j]) mod 256].

5 Why was WEP's use of RC4 catastrophically flawed?

RC4 was too slow for wireless networks
24-bit IVs caused rapid reuse, weak RC4 key schedules leaked key bytes, and CRC-32 is not a cryptographic integrity check
WEP used RC4 with 8-bit keys
RC4 requires hardware acceleration that access points lacked
WEP combined multiple flaws: the 24-bit IV space exhausts quickly causing keystream reuse, certain IVs produce weak RC4 key schedules (FMS attack), CRC-32 allows undetected ciphertext modification, and the static shared key is rarely changed.

6 What encryption does WPA2 use instead of RC4?

Triple DES in CBC mode
ChaCha20-Poly1305
AES-CCMP (AES in Counter mode with CBC-MAC Protocol)
Blowfish in CTR mode
WPA2 uses AES-CCMP -- AES-128 in counter mode for confidentiality combined with CBC-MAC for integrity and authentication. This was a complete redesign from WEP/WPA's RC4-based approach.

7 What key improvement does WPA3's SAE (Dragonfly) provide over WPA2-PSK?

Forward secrecy -- compromising the password does not allow decryption of previously captured traffic
Faster connection times
Support for longer passwords
Backward compatibility with WEP devices
SAE (Simultaneous Authentication of Equals) uses the Dragonfly password-authenticated key exchange, which provides forward secrecy. Even if the password is later compromised, past captured sessions cannot be decrypted because each session derives unique keys.

8 What advantage does ChaCha20 have over AES on devices without hardware AES support?

ChaCha20 uses smaller keys
ChaCha20 is a block cipher and therefore more secure
ChaCha20 uses only ARX operations (add, rotate, XOR) which run in constant time without cache-timing side channels
ChaCha20 requires less memory than AES
ChaCha20 uses only addition, rotation, and XOR (ARX) -- operations that execute in constant time on all processors. Software AES implementations without AES-NI are vulnerable to cache-timing side-channel attacks because of table lookups.

9 What is the KNOB (Key Negotiation of Bluetooth) attack?

An attack that jams Bluetooth signals
An attacker forces devices to negotiate an encryption key with only 1 byte of entropy, making brute-force trivial
A firmware exploit in Bluetooth chips
An attack that clones Bluetooth MAC addresses
The KNOB attack exploits the fact that Bluetooth's entropy negotiation for the encryption key was not authenticated. An attacker can force both devices to agree on a key with only 1 byte (8 bits) of entropy, which can be brute-forced instantly.

10 How does 5G protect subscriber identity compared to 4G?

5G uses shorter identifiers that are harder to intercept
5G rotates identifiers every 30 seconds
5G does not transmit any identifier over the air
5G encrypts the SUPI into a SUCI using the home network's public key (ECIES), preventing IMSI-catcher attacks
In 4G, the IMSI is sent in plaintext, enabling IMSI-catcher surveillance. In 5G, the Subscription Permanent Identifier (SUPI) is encrypted into a Subscription Concealed Identifier (SUCI) using Elliptic Curve Integrated Encryption Scheme (ECIES) with the home network's public key.
