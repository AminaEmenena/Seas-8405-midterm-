📡 1. Wireless Cryptography Fundamentals
KEY CONCEPT: Wireless networks use an open communication medium -- a shared broadcast channel where no physical access is required to intercept. Any device in range can eavesdrop. The fundamental trade-off is convenience vs security.

Core Wireless Components

Definitions:
  • Station (STA/IBSS) -- Any wireless device: PDA, laptop, phone
  • Access Point (AP) -- Transmitter/receiver providing basic services within ~300ft/100m range
  • Basic WLAN -- AP + STA = the simplest wireless LAN configuration
  • Supplicant -- The client device that must authenticate before gaining network access

Home vs Enterprise WiFi

Feature Home Enterprise
Architecture Single wireless router handles AP + security + auth Lightweight APs as relays + centralized backend
Auth Server None (passphrase only) RADIUS / TACACS+ backend servers
Scalability Limited (single household) Scalable credential management
Policy Per-device configuration Consistent, centralized policies
Security Implication: Because wireless is a shared broadcast channel, anyone within range (~100m) can passively capture all traffic. This makes encryption and authentication absolutely essential -- unlike wired networks where physical access to the cable is required.
🔒 2. Wireless Authentication -- 802.1X & EAP
802.1X Framework: Supports multiple authentication methods, integrates encryption keys + authentication + centralized policy enforcement. The supplicant (client) authenticates through an authenticator (AP) to a backend RADIUS server.

EAP -- Extensible Authentication Protocol

7-Step EAP Process

  • Step 1: EAP Start -- supplicant initiates
  • Step 2: EAP Request -- authenticator proposes method (e.g., smart card)
  • Step 3: EAP Response -- supplicant sends negative acknowledgment (doesn't support that method)
  • Step 4: EAP Request -- authenticator proposes alternative (e.g., MS-CHAP)
  • Step 5: EAP Response -- supplicant sends correct credentials
  • Step 6: EAP Success -- authentication approved
  • Step 7: Auth Success Notification -- access granted
EAP Architecture
Supplicant Authenticator RADIUS Server (Client) (AP) (Backend) | | | |--- EAPOL --------->| | | (EAP over LAN) |--- EAP over RADIUS ->| | (Ethernet frame) | | | |<-- RADIUS Response --| |<-- EAPOL ----------| |

EAP Transport Protocols

EAPOL (EAP over LAN): EAP encapsulated in Ethernet frames, used between the supplicant and the authenticator (AP).
EAP over RADIUS: Used between the authenticator and the RADIUS server. RADIUS limitation: no automatic key management.

RADIUS AAA

  • Authentication -- Uses EAP to verify identity
  • Authorization -- RADIUS functionality to determine access level
  • Auditing -- RADIUS functionality to log access events

EAP Variants

Variant Certificate Source Details
PEAP Server-supplied certificates Outer auth via SSL/TLS tunnel, inner auth via EAP
EAP-TLS Client-supplied certificates Mutual TLS authentication -- strongest EAP method
Memory Aid PEAP = "P for Provider (server) certs" -- EAP-TLS = "T for Two-way (mutual) certs"
⚙️ 3. RC4 in Wireless Networks
Why RC4? Early wireless devices had limited CPU and memory. Stream ciphers like RC4 are efficient -- they encrypt byte-by-byte without needing to buffer entire blocks.

RC4 Two-Phase Design

Phase 1: Key Setup

  • Takes an n-byte key and creates a 256-byte S-box
  • Initializes S-box through a series of swaps using modulo operations
  • Result: a key-dependent permutation of all 256 byte values

Phase 2: Keystream Generation

  • Uses the S-box plus internal counters to generate a pseudo-infinite keystream
  • Keystream is XORed with plaintext to produce ciphertext
  • Decryption: XOR ciphertext with the same keystream to recover plaintext
RC4 Encryption Flow
Secret Key (n bytes) | v [Key Setup] --> 256-byte S-box | v [Keystream Generator] | v Plaintext --> XOR with Keystream --> Ciphertext

The Key Reuse Problem

Critical Weakness: If the same key encrypts the same plaintext twice, XORing the two ciphertexts cancels the keystream and reveals the data. Solution: use a unique IV (nonce) for every packet so the effective key is always different.

IV Solutions

Protocol IV Size Key Management
WEP 24-bit IV Rollover vulnerability -- repeats within hours
TKIP (WPA) 48-bit IV Session key + periodic key updates
Memory Aid RC4 Key Reuse: "Same Key + Same Plaintext = XOR Reveals Everything"
🚫 4. WEP -- Wired Equivalent Privacy (BROKEN)
WEP IS CATASTROPHICALLY BROKEN. First security protocol for IEEE 802.11b. Uses RC4 stream cipher with a 40-bit key and 24-bit IV. Crackable within 5 hours on a busy network.

How WEP Works

IV + Key --> RC4 --> Pseudo-infinite Keystream XOR Plaintext

IV is incremented per packet. Simple parity-based checksum (CRC-32) for integrity -- NOT cryptographically secure.

WEP Weaknesses

Complete List of Failures

  • Small 24-bit IV -- Only 16.7M values, repeats within hours on busy networks
  • FMS weak key attacks -- Certain IVs produce weak RC4 key schedules that leak key bytes
  • No replay protection -- Attacker can re-send captured packets
  • No tampering detection -- CRC-32 is linear, not cryptographically secure
  • Single global key -- Compromise of one device = entire network compromised
  • Keys can't update dynamically -- Must be manually changed on every device

Bit-Flipping Attack

Why it works: RC4 is a stream cipher (XOR-based) and CRC-32 is a linear checksum. An attacker can flip specific bits in the IP header (e.g., change the destination address) to redirect traffic. The CRC-32 can be recalculated without knowing the key because CRC is linear.

Cracking WEP

Attack Process: When IVs repeat, XOR two ciphertexts together -- the keystream cancels out, leaving the XOR of two plaintexts. Frequency analysis on the XOR of plaintexts recovers the messages and ultimately the key. A busy network produces enough IV collisions within ~5 hours.
Memory Aid "WEP = Woefully Easy to Penetrate" -- 24-bit IV, CRC-32, static key, no replay protection
🛡️ 5. WPA & WPA2
WPA addressed WEP's failures without requiring major hardware changes. Two modes: WPA-PSK (Pre-Shared Key, home) and WPA Enterprise (802.1X + EAP + RADIUS).

WPA-PSK (Home Mode)

  • No auth server required -- key derived from alphanumeric passphrase (up to 64 ASCII chars)
  • Mutual authentication -- both sides prove knowledge of the key
  • Key never transmitted over the network -- derived independently on both sides

WPA Enterprise

Key Improvements over WEP

  • TKIP encryption -- Uses hashed IV + session key (still RC4 underneath but much safer)
  • 48-bit IV -- Eliminates the IV exhaustion problem
  • Message Integrity Check (MIC) -- Prevents bit-flipping attacks (unlike CRC-32)
  • Session keys -- Securely distributed by RADIUS server, unique per session

WPA2 (IEEE 802.11i-2004)

Major Change: Replaced TKIP/RC4 with AES-CCMP -- a block cipher mode. Two modes: Personal (PSK) and Enterprise.

Four-Way Handshake

Purpose and Steps

  • Goal: Mutual authentication without revealing the PMK (Pairwise Master Key)
  • Nonce exchange: AP sends ANonce, client sends SNonce
  • PTK derivation: PTK = f(PMK + ANonce + SNonce + MAC addresses)
  • MIC validation: Both sides compute MIC to verify integrity
  • GTK distribution: Group Temporal Key distributed for multicast/broadcast traffic
Four-Way Handshake
AP (Authenticator) Client (Supplicant) | | |--- Msg 1: ANonce --------------->| | | (derives PTK) |<-- Msg 2: SNonce + MIC ----------| | (derives PTK) | |--- Msg 3: GTK + MIC ----------->| | | |<-- Msg 4: ACK + MIC ------------| | | |====== Encrypted traffic =========|

Cracking WPA2-PSK

Attack method: Target the 4-way handshake (specifically Message 2). Perform offline dictionary attack: derive PMK from each candidate password, then compute PTK, then compute MIC, then compare to captured MIC.
Key insight: WPA2 is NOT broken cryptographically. The vulnerability is weak PSK passwords. Strong passphrases make this attack computationally infeasible.

KRACK Attack

KRACK (Key Reinstallation Attack):
  • Exploits a 4-way handshake implementation flaw (not AES itself)
  • Replays handshake messages to force key reinstallation
  • Causes reuse of nonces/encryption keys
  • Breaks confidentiality and integrity
  • Effective against clients, not APs
  • Affects both PSK and Enterprise modes
  • Mitigation: Patch clients and APs, upgrade to WPA3
Memory Aid KRACK = "Key Reinstallation" -- targets the handshake implementation, NOT the AES cipher
💪 6. WPA3 -- Next Generation WiFi Security
WPA3 provides four major improvements: brute-force protection (even with weak passwords), public network privacy (individualized encryption), IoT security, and stronger encryption (192-bit enterprise mode).

SAE -- Simultaneous Authentication of Equals (Dragonfly)

Key Properties

  • Replaces the vulnerable 4-way handshake as the initial authentication mechanism
  • Resistant to offline dictionary and brute-force attacks
  • Limits to a single password guess per interaction -- attacker must be online for each attempt
  • Forward secrecy -- protects past traffic even if the password is compromised later
  • Peer-to-peer connection -- prevents man-in-the-middle attacks

WPA3 Security Features

  • Protected Management Frames (PMF) -- Required, prevents deauthentication attacks
  • 128-bit AES -- Personal mode encryption
  • 192-bit AES -- Enterprise mode for government/financial networks

Adoption & Challenges

Aspect Details
Mandate Mandatory for Wi-Fi CERTIFIED 6 devices (July 2020)
OS Support Integrated into all modern operating systems
6 GHz Band WPA3 required for 6 GHz band operation
Legacy IoT Pre-2018 devices struggle with transition mode
Older Routers Can't upgrade due to chipset limitations
Memory Aid WPA3 SAE = "Same Authentication for Everyone" -- no server needed, brute-force resistant, forward secrecy built in
😈 7. Wireless Attacks

Evil Twin AP Attack

4-Step Attack:
  • Step 1: Attacker sets up a fake AP with a stronger signal outside the corporate site
  • Step 2: Fake AP uses the same SSID as the legitimate network
  • Step 3: Victim's device associates with the evil twin (stronger signal wins)
  • Step 4: Attacker intercepts all communication (MITM position)
Defense -- VPN: An end-to-end encrypted VPN tunnel with a pre-shared secret protects against Evil Twin attacks. Even if the attacker intercepts traffic, they cannot decrypt the VPN tunnel.

DoS -- Disassociation & Jamming

Three DoS Methods

  • Frequency flooding -- Overwhelm the entire wireless frequency band
  • AP packet flooding -- Flood the access point with packets to exhaust resources
  • Disassociation attack -- Send forged "disassociate" frames to all wireless clients, kicking them off the network

Rogue AP

Rogue AP: An unauthorized access point connected directly to the corporate network. Unlike an Evil Twin (which is external), a Rogue AP bypasses the firewall entirely because it is plugged into the internal network.
802.1X Access Control: 802.1X can control both wired and wireless access. In 802.1X mode, a device must authenticate before the switch port or wireless connection grants network access, mitigating rogue AP and unauthorized device risks.
Memory Aid Evil Twin = outside attacker (stronger signal) vs Rogue AP = inside threat (bypasses firewall)
📊 8. WiFi Security Evolution Summary

Complete Evolution

Protocol Cipher IV Size Integrity Auth Status
WEP RC4 24-bit CRC-32 Open/Shared Key BROKEN
WPA RC4-TKIP 48-bit MIC (Michael) PSK / 802.1X Deprecated
WPA2 AES-CCMP 48-bit PN CBC-MAC PSK / 802.1X Current
WPA3 AES-CCMP/GCMP 48-bit PN GMAC/CBC-MAC SAE / 802.1X Latest

Key Lessons from Each Generation

What Each Failure Taught Us

  • WEP: Small IVs + stream cipher key reuse = catastrophic. Linear checksums (CRC-32) are not integrity checks. Static global keys are unmanageable.
  • WPA: TKIP was a band-aid -- wrapping a broken cipher (RC4) only buys time, not security.
  • WPA2: Strong crypto (AES) can still fail if the protocol implementation has flaws (KRACK). Weak passwords undermine strong algorithms.
  • WPA3: Forward secrecy and brute-force resistance require fundamentally different key exchange (SAE), not just stronger ciphers.
Exam Pattern: The evolution from WEP to WPA3 demonstrates that security is iterative -- each generation addresses the specific attacks that broke the previous one. Know what broke and how it was fixed.
🔐 9. Physically Unclonable Functions (PUFs)
PUF: A hardware security primitive that exploits inherent manufacturing variations in silicon chips to create a unique, unclonable identity for each device. Each chip's microscopic physical differences produce unique challenge-response pairs.
  • Manufacturing variation -- No two chips are identical at the nano-scale, even from the same production line
  • Challenge-response -- Given an input (challenge), the PUF produces a unique output (response) based on its physical characteristics
  • Unclonable -- Cannot be duplicated because the exact physical variations cannot be reproduced
  • IoT application -- Lightweight device authentication without storing keys in memory (resistant to side-channel extraction)
Relevance to Wireless: PUFs are particularly important for IoT devices in wireless networks where traditional key storage may be vulnerable to physical attacks. They provide hardware-rooted identity without the overhead of full PKI.

KRACK (Key Reinstallation Attack) exploits a flaw in how the 4-way handshake is implemented. By replaying handshake messages, it forces the client to reinstall an already-used key, causing nonce reuse. This breaks confidentiality and integrity but is a protocol implementation bug, not a flaw in AES.

SAE limits attackers to a single password guess per online interaction, preventing offline dictionary attacks. It also provides forward secrecy -- each session derives unique keys, so compromising the password later cannot decrypt previously captured traffic.

802.1X defines three roles: the supplicant (client device requesting access), the authenticator (AP that relays auth requests), and the authentication server (RADIUS backend that makes the access decision). EAP messages travel via EAPOL between supplicant and authenticator, and EAP-over-RADIUS between authenticator and server.

6 How does an Evil Twin attack work?

The attacker jams all wireless frequencies in range

In an Evil Twin attack, the attacker places a rogue AP (often outside the building) with a stronger signal than the legitimate AP, using the same SSID. Victim devices automatically associate with the stronger signal, giving the attacker a man-in-the-middle position. A VPN with pre-shared secrets defeats this attack.

7 What happens when the same RC4 key encrypts the same plaintext twice?

XORing the two ciphertexts cancels the keystream and reveals the plaintext data
The encryption becomes stronger due to double encryption
The ciphertexts are identical but cannot be exploited
RC4 automatically detects the reuse and generates a new key
Since C = P XOR K, if the same key K encrypts two plaintexts: C1 XOR C2 = (P1 XOR K) XOR (P2 XOR K) = P1 XOR P2. The keystream cancels out entirely, leaving the XOR of the two plaintexts, which can be separated using frequency analysis.

8 Why does WEP's bit-flipping attack work?

Because AES-CCMP uses a linear encryption mode
Because the WEP key is transmitted in plaintext
Because RC4 is a stream cipher (XOR-based) and CRC-32 is a linear checksum -- both can be manipulated without knowing the key
Because WEP does not encrypt the IP header
RC4 uses XOR for encryption, meaning flipping a ciphertext bit flips the corresponding plaintext bit. CRC-32 is linear, so the attacker can recalculate the checksum for the modified data without knowing the key. This allows redirecting packets by changing the destination IP address in the encrypted header.

9 In wireless networking, what is a "supplicant"?

The client device that must authenticate before gaining network access

A supplicant is the client device (laptop, phone, PDA) that requests network access. In the 802.1X framework, the supplicant communicates via EAPOL with the authenticator (AP), which relays the authentication request to the RADIUS server.

10 What is the purpose of the WPA2 four-way handshake?

To transmit the PMK (Pairwise Master Key) securely over the air
To negotiate which encryption algorithm to use
To verify that the access point has a valid certificate
To achieve mutual authentication and derive the PTK (Pairwise Transient Key) from PMK, nonces, and MAC addresses -- without revealing the PMK
The four-way handshake allows both sides to prove they know the PMK without transmitting it. They exchange nonces (ANonce, SNonce), independently derive the PTK from PMK + nonces + MAC addresses, validate with MIC, and distribute the GTK for multicast/broadcast traffic.
