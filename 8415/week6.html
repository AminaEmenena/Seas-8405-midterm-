🔒 1. The Need for a New Standard: From DES to AES
KEY IDEA: DES became obsolete because its 56-bit key was too short for modern computing power. The search for a replacement led to AES.

DES (Data Encryption Standard, 1977)

  • Key size: 56 bits (with 8 parity bits = 64-bit key input)
  • Block size: 64 bits
  • Structure: 16-round Feistel cipher
  • Designed with NSA involvement (behind closed doors)
Problem: By the 1990s, DES was vulnerable to brute force. In 1998, the EFF's "Deep Crack" machine broke DES in 56 hours. A 56-bit key means only 2^56 possible keys — insufficient against modern hardware.

3DES (Triple DES)

  • Applied DES three times with 2 or 3 independent keys
  • 3DES-EDE: Encrypt-Decrypt-Encrypt with different keys
  • Effective key length: 112 bits (2-key) or 168 bits (3-key)
  • Much slower than DES (3x the computation)
  • A stopgap measure — not a long-term solution
Prof. Fossaceca: NIST announced the need for a new standard in 1997 because 3DES was too slow for modern applications and DES was broken. The AES competition was born.
🏆 2. The AES Competition (1997-2001)
Definition: An open, transparent, international competition run by NIST to select the next standard symmetric encryption algorithm to replace DES.

Competition Timeline

  • 1997: NIST issues call for proposals
  • 1998: 15 candidate algorithms submitted from around the world
  • 1999: Narrowed to 5 finalists after public analysis
  • 2000 (October): Rijndael selected as AES winner
  • 2001: Published as FIPS 197

Evaluation Criteria

CriterionWhat It Means
SecurityResistance to all known cryptanalytic attacks
PerformanceSpeed on diverse platforms (32-bit, 64-bit, 8-bit)
EfficiencyLow computational and memory requirements
FlexibilitySupport for multiple key and block sizes
SimplicityEasy to analyze, implement, and verify

Key Principle: The open competition model was the opposite of DES (which NSA helped design behind closed doors). Public scrutiny = more trust and better security analysis.
🌟 3. Why Rijndael Won
KEY IDEA: Rijndael offered the best balance of security, performance, and simplicity across all platforms.
  • Performance: Efficient in both hardware and software implementations
  • Low memory requirements: Suitable for constrained devices (smart cards, embedded systems)
  • Variable key sizes: 128, 192, or 256 bits
  • Variable block sizes: Originally supported 128, 192, 256-bit blocks (AES standardized on 128-bit only)
  • Clean mathematical structure: Based on Galois field arithmetic (GF(2^8))
  • Simplicity: Easier to analyze for weaknesses than complex alternatives
  • Parallelizable: Operations can be computed simultaneously in hardware
Memory AidRijndael = "Rain-Dahl" (Belgian creators Joan Daemen + Vincent Rijmen)
Prof. Fossaceca: Serpent had a larger security margin but was significantly slower. The committee valued practical performance alongside security — a real-world standard must be usable everywhere.
🔧 4. AES (Rijndael) Internals
Core Parameters:
Key SizeRoundsBlock Size
128-bit10 rounds128-bit (always)
192-bit12 rounds128-bit (always)
256-bit14 rounds128-bit (always)

Four Operations Per Round

1. SubBytes (Confusion)

Non-linear byte substitution using a fixed S-box. Each byte is independently replaced. Based on multiplicative inverse in GF(2^8). Provides Shannon's confusion property.

2. ShiftRows (Diffusion)

Cyclic left shift of each row by different offsets (row 0: no shift, row 1: shift 1, row 2: shift 2, row 3: shift 3). Spreads bytes across columns for diffusion.

3. MixColumns (Diffusion)

Matrix multiplication of each column in GF(2^8). Each output byte depends on all 4 input bytes in the column. Further diffusion. (Skipped in the final round.)

4. AddRoundKey (Key Mixing)

XOR the state with the round key derived from the key schedule. This is how the secret key enters the computation.

AES Round Structure
Plaintext (128 bits) | [AddRoundKey] (initial) | [SubBytes] --> [ShiftRows] --> [MixColumns] --> [AddRoundKey] x (Nr-1) rounds | [SubBytes] --> [ShiftRows] --> [AddRoundKey] (final round, no MixColumns) | Ciphertext (128 bits)
IMPORTANT: AES uses a Substitution-Permutation Network (SPN) — NOT a Feistel cipher like DES. The entire block is transformed each round.
🔄 5. Block Cipher Modes of Operation
CRITICAL: A block cipher alone only encrypts fixed-size blocks. Modes of operation define how to encrypt arbitrary-length messages securely.
ModeHow It WorksProsCons
ECBEach block encrypted independentlySimple, parallelizableINSECURE — patterns visible (penguin example)
CBCXOR with previous ciphertext block; IV requiredHides patterns, widely usedSequential (not parallelizable), padding needed
CTREncrypt counter values, XOR with plaintextParallelizable, no padding, stream-likeNonce reuse is catastrophic
GCMCTR mode + GHASH authentication tagConfidentiality AND integrity, fastNonce reuse breaks both properties
CFBPrevious ciphertext fed back as inputStream-like, self-synchronizingSequential, error propagation
OFBOutput of cipher fed back as inputNo error propagationSequential, bit-flipping attacks possible
NEVER use ECB for anything! The famous "ECB Penguin" shows that identical plaintext blocks produce identical ciphertext blocks, revealing image patterns even after encryption.
Best Practice: Use GCM (AES-GCM) whenever possible — it provides authenticated encryption (confidentiality + integrity) and is highly performant.

📦 7. S-Boxes (Substitution Boxes)
Definition: Non-linear lookup tables that map input bits to output bits, providing the crucial confusion property in block ciphers.
  • Purpose: Create complex, non-linear relationship between key and ciphertext
  • DES S-boxes: 6 bits in, 4 bits out (8 different S-boxes). Designed by NSA — initially controversial because design criteria were secret.
  • AES S-box: 8 bits in, 8 bits out (single S-box). Based on multiplicative inverse in GF(2^8) followed by an affine transformation. Mathematically defined and publicly verifiable.
Critical for Security: Weak S-boxes can make an entire cipher vulnerable to differential and linear cryptanalysis. The non-linearity of S-boxes is what prevents algebraic attacks.
Prof. Fossaceca: The AES S-box design is completely transparent — no "nothing up my sleeve" concerns. You can verify it yourself using the mathematical definition. This is a major advantage over DES.
🔀 8. Confusion and Diffusion (Shannon)
Claude Shannon (1949) identified two fundamental properties that secure ciphers must provide:

Confusion

Each bit of ciphertext should depend on several parts of the key. Makes the relationship between key and ciphertext as complex as possible.

Achieved by: Substitution operations (S-boxes)

In AES: SubBytes step

Diffusion

Each bit of plaintext should affect many bits of ciphertext. A single bit change in plaintext should change approximately half of ciphertext bits.

Achieved by: Permutation and transposition operations

In AES: ShiftRows and MixColumns steps

Without confusion: The relationship between key and ciphertext is too simple — attacker can deduce key bits.
Without diffusion: Local changes in plaintext only affect local ciphertext — attacker can isolate and attack small portions independently.
Memory AidConfusion = "Con-fuse the key" (S-boxes) | Diffusion = "Diff-use the plaintext" (permutations)
🔐 9. Key Size and Security Levels
AES VariantKey SpaceSecurity LevelUse Case
AES-1282^128 keys128-bit securityMost commercial applications
AES-1922^192 keys192-bit securityExtra margin applications
AES-2562^256 keys256-bit securityClassified data, long-term security

Comparative Security Strengths

  • AES-128 is approximately equivalent to RSA-3072 in security strength
  • AES-256 is approximately equivalent to RSA-15360

Quantum Computing Threat

Grover's Algorithm: Provides quadratic speedup for brute-force search. Effectively halves the key length:
  • AES-128 becomes 64-bit security (BROKEN post-quantum)
  • AES-192 becomes 96-bit security (marginal)
  • AES-256 becomes 128-bit security (still secure)
NIST Recommendation: Use AES-256 for long-term security and post-quantum resilience. It maintains 128-bit security even against quantum adversaries.
📋 10. Algorithm Selection Criteria
How to choose a cryptographic algorithm for your system:
CriterionQuestions to Ask
Security marginHow far beyond known attacks? Has it survived years of cryptanalysis?
PerformanceSpeed on target platforms? Hardware acceleration available (AES-NI)?
SimplicityIs it easy to implement correctly? Fewer implementation bugs?
FlexibilityMultiple key/block sizes? Adaptable to different use cases?
Resource requirementsMemory, power consumption, die area for embedded/IoT?
Existing cryptanalysisHow well-studied? More analysis = more confidence.
StandardizationNIST/ISO approved? Peer-reviewed? Open design?
Kerckhoffs' Principle: A cryptosystem should be secure even if everything about the system, except the key, is public knowledge. Security through obscurity is NOT security.
Prof. Fossaceca: Never roll your own crypto. Always use well-analyzed, standardized algorithms. The AES competition is the gold standard for how algorithm selection should work — open, transparent, global peer review.
