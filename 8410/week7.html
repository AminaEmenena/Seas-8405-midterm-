📜 1. What is a Log & Log Security Visualization
DEFINITION: A log is a chronological record of events, activities, and messages generated by IT components (OS, applications, network devices, security tools). Logs track behavior and state of components, providing insights into performance, security, and potential issues.

Log Entry Contents

  • Timestamp -- when the event occurred
  • Event type -- what category of event
  • Source -- which component generated it
  • Other relevant info -- user, IP, severity, etc.

Log Security Visualization

Core idea: Transforming raw log data into charts, graphs, and visual formats so security analysts can quickly identify potential incidents, track their progression, and respond accordingly.

👁 3. Gestalt 6 Principles of Visual Perception
SOURCE: Stephen Few, Information Dashboard Design
PrincipleWhat It MeansDesign Implication
ProximityNearby objects perceived as belonging to same groupDirects scanning direction (horizontal spacing = left-to-right reading, vertical = top-to-bottom)
SimilarityObjects with similar visual characteristics (color, size, shape) perceived as same groupUse same color for related data across charts
ClosureWe perceive incomplete shapes as completeAmbiguous stimuli seen as closed, whole, regular forms
ContinuityAligned objects seen as single entity extending from each otherDashed line perceived as one continuous line, not separate segments
EnclosureObjects within a visual border (line, color field) grouped togetherSTRONGEST grouping principle
ConnectionLinked objects (connected by lines) perceived as groupedStronger than proximity or similarity, but WEAKER than enclosure
GROUPING STRENGTH ORDER: Enclosure > Connection > Proximity/Similarity
Memory Aid "Every Cool Person Sees Connections Clearly" -- Enclosure (strongest), Connection, Proximity, Similarity, Continuity, Closure
🌳 4. Decision Trees -- The Flowchart Classifier
DEFINITION: A decision tree is a flowchart -- each box asks a question, each branch is an answer, follow down to a final label.

Parts of a Decision Tree

PartDescription
Root NodeTop of tree, no parent -- first question asked
Internal NodeA question that splits into branches
BranchOne answer/path from a node
Leaf NodeEnd -- no children, gives the final class label
DepthLongest path from root to leaf
Mental model: Like "Which character are you?" quizzes -- start at top, answer questions, land on a result.

How Trees Are Built

Recursive partitioning: At each node, pick the split that maximizes purity gain (reduces impurity most). Repeat on each resulting group.

Purity: A good split sends mostly one class down each branch. 100% one class = a "pure" leaf.

Why People Like Decision Trees

  • No distributional assumptions (don't need normal data)
  • Handles big data
  • Works with both numeric and categorical variables
  • Flowchart is easy to explain to non-technical people (huge for security reporting)
⚠️ 5. Overfitting & Pruning
OVERFITTING: Tree grown too deep memorizes training data including random noise. Show it fresh data and it flops. An overly large tree is over-fit and unreliable.

Fixes for Overfitting

MethodHow It WorksTrade-off
Early StoppingStop growing when node has too few observationsSaves compute but may stop too soon
PruningGrow full tree, then cut unhelpful splitsMore thorough, more common

Pruning Approaches

  • Top-down pruning: Risky -- a bad split at the top throws away whole subtree that might contain good splits below
  • Bottom-up pruning: Start at leaves, move up -- avoids that risk, more common
Memory Aid "Prune from the Bottom Up" -- like trimming a real tree: start at the tips, work inward
🤖 6. Tree Algorithms -- CART & ID3
AlgorithmYearKey Features
CART (Breiman et al.)1984Binary splits only. Handles numeric + categorical. Grows big tree, then prunes by cost-complexity
ID3 (Quinlan)1986One of the first tree algorithms. Can do multi-way splits. Later expanded into C4.5

Classification vs Regression Trees

  • Classification tree: Target is a category (spam/not spam, attack/normal). Leaves give class labels
  • Regression tree: Target is a number. Leaves give predicted values
EXAM TRAPS:
  • Confusing root (top, no parent) with leaf (bottom, no children)
  • Thinking bigger tree is always better (it overfits!)
  • Forgetting trees need NO normality assumption unlike hypothesis tests
  • Mixing up classification (categorical target) and regression (numeric target) trees
