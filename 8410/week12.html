📊 1. ANOVA -- Analysis of Variance: The Core Idea
DEFINITION: ANOVA extends the t-test from comparing 2 group means to comparing 3 or more group means simultaneously, while controlling the overall false positive rate.

The Progression

SamplesTestWhat It Tests
1 samplet-test1 mean
2 samplest-test2 means
3+ samplesANOVA3+ means

Core Question

"Are the means of 3 or more independent groups equal?"

  • H0: mu1 = mu2 = ... = muk (all group means are equal)
  • H1: At least one mean differs

Why Not Just Run Multiple t-Tests?

CRITICAL: With 3 groups at alpha = 0.05, you need 3 pairwise comparisons. The false positive probability inflates to approximately 14%. With more groups it gets worse. ANOVA controls this by testing all groups simultaneously in a single test.

Two Types of Variance

Variance TypeWhat It MeasuresRepresents
BETWEEN-group (MSB)How different group means are from grand meanSignal / effect we care about
WITHIN-group (MSW)Spread of observations inside each groupNoise / random variation
F-statistic = Between / Within = MSB / MSW. Large F means group means are more spread out than random noise would explain -- evidence against H0.
Memory Aid "F = Signal / Noise" -- large F means the signal (group differences) is louder than the noise (random variation)
⚠️ 2. ANOVA Assumptions & When They Fail

Three Core Assumptions

  1. Independence -- each measurement comes from a different unit
  2. Normality -- response is approximately normal within each group. Check with Shapiro-Wilk test or Q-Q plots
  3. Homogeneity of Variance -- all groups have approximately equal variances. Check with Levene's test or Bartlett's test

When Assumptions Fail

ProblemAlternative TestDetails
Normality failsKruskal-Wallis H-TestNon-parametric, ranks-based alternative to one-way ANOVA
Unequal variancesWelch's ANOVADoes not assume equal variances across groups
Blocked/repeated measuresFriedman's TestNon-parametric alternative for related samples
🔧 3. One-Way ANOVA -- SOC Team Response Times Example

Setup

  • Three SOC teams (A, B, C), 8 incidents each
  • Mean response times: A = 52.5 min, B = 31.8 min, C = 68.5 min
  • Grand mean = 50.9 min
  • H0: mu_A = mu_B = mu_C. H1: at least one differs. Alpha = 0.05

Results

F = 32.75, df = (2, 21), p = 0.000. F_critical(0.05, 2, 21) = 3.47. Since 32.75 >> 3.47, reject H0.

Conclusion: Strong evidence that mean response time differs across SOC teams. Next step: post-hoc tests to find WHICH teams differ.

Tukey Post-Hoc Test

Tukey HSD performs pairwise comparisons with family-wise error rate control. All three pairs were significant (p < 0.01) in this example.

Minitab Steps

  1. Reshape data: Stat > Stack > Rows
  2. Check normality: Stat > Basic Statistics > Graph Summary
  3. Check equal variances: Stat > ANOVA > Test for Equal Variances (Bartlett's test: 1.98, p = 0.372 -- variances are equal)
  4. Run ANOVA: Stat > ANOVA > One-Way
Memory Aid "ANOVA says someone is different. Tukey says WHO is different." -- always follow up a significant ANOVA with post-hoc
🔀 4. Two-Way ANOVA -- Two Factors, One Response
DEFINITION: Two-Way ANOVA tests two factors simultaneously and asks THREE questions: Does Factor A affect the response? Does Factor B? Does the effect of A depend on B (interaction)?

The Three Questions

  1. Main effect A: Does Factor A affect the response?
  2. Main effect B: Does Factor B affect the response?
  3. Interaction A*B: Does the effect of A DEPEND on the level of B?
INTERACTION is the most important concept. If interaction exists, the effect of one factor changes depending on the level of the other factor. It can mask, reverse, or amplify main effects. Always read the interaction row FIRST in Minitab output.

Security Example

  • Factor A: Training type (Online / In-Person)
  • Factor B: Experience (Junior / Senior)
  • Response: % threats correctly identified
  • 2x2 factorial design, n = 10 per cell
EffectFp-valueSignificant?
Training12.30.001Yes
Experience8.70.005Yes
Interaction9.10.004Yes
Interpretation: In-person training helps Juniors more than Seniors. You cannot simply say "in-person is better" without specifying experience level. When interaction is significant, interpret main effects with caution.

Interaction Plot

In Minitab: Stat > ANOVA > General Linear Model. Non-parallel lines on the interaction plot = interaction exists.

Additional Assumptions (beyond one-way)

  • Balanced design preferred
  • Additivity (for main effects to be interpretable independently)
📉 5. MANOVA -- Multiple Response Variables
DEFINITION: MANOVA (Multivariate Analysis of Variance) is used when you have MULTIPLE correlated response variables. ANOVA handles one response; MANOVA handles two or more.

Why Not Just Run Multiple ANOVAs?

  • Inflates Type I error rate
  • Ignores correlation between response variables
  • Cannot detect differences in COMBINATIONS of outcomes

Hypotheses

  • H0: The mean VECTOR of all response variables is equal across groups
  • H1: At least one group's mean vector differs

When to Use MANOVA

Use when: You have multiple related outcome measures (e.g., 3 SOC metrics: detection rate, false positive rate, MTTR), outcomes are correlated, and you want Type I error controlled across all outcomes.

Security Example

3 SOC teams measured on 3 metrics. Wilks' Lambda = 0.312, F(6,72) = 8.94, p < 0.001 -- Reject H0.

Follow-up Metricp-valueSignificant?
Detection rate0.003Yes
False positive rate0.041Yes
MTTR0.218No
Key insight: MANOVA reveals the overall combined profile differs across teams even though individual MTTR is not significant on its own. The multivariate perspective catches what individual ANOVAs miss.

MANOVA Assumptions

  • All ANOVA assumptions (independence, normality, equal variances)
  • Multivariate normality
  • Homogeneity of covariance matrices (Box's M test)
  • No severe multicollinearity (r > 0.9 is problematic)
  • n per group > number of response variables

🔒 7. Why Security Data is Often Non-Normal
KEY INSIGHT: Non-parametric tests ask the SAME questions as parametric tests but use ranks/signs instead of raw values, so they do not need normality. This makes them especially suited for security data.

Common Reasons for Non-Normality in Security

  • Zero-inflated counts -- most days zero incidents, rare days many
  • Skewed response times -- few major incidents take 10x longer than typical
  • Ordinal severity scores -- CVSS: Low/Med/High/Critical are ordered but have unequal intervals
  • Heavy-tailed distributions -- cyber losses follow power-law/Pareto distributions
  • Small sample sizes -- breach investigations, red team exercises: n = 5 to n = 15
  • Categorical variables -- attack types, threat actor classifications
Memory Aid "Security data is almost NEVER bell-shaped" -- zero-inflated, skewed, heavy-tailed, ordinal. When in doubt, go non-parametric
