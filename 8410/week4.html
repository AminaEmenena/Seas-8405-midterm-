👤 1. What is a User?
Definition: A user is any entity (human or non-human) that possesses a user ID and system permissions. This includes human users, service accounts, bots, and APIs.
KEY INSIGHT: Non-human users (bots, APIs, service accounts) often have elevated privileges and are prime targets for attackers. They are harder to monitor because their behavior is automated.

⚖️ 5. Hypothesis Testing -- The Courtroom Analogy
Remember This Analogy
Hypothesis Test = Courtroom Trial | H0 = Innocent (default) | H1 = Guilty (your claim)
H0 (Null Hypothesis): The boring default. "Nothing interesting is happening." Always contains the equals sign (=, ≤, ≥).
H1 (Alternative Hypothesis): Your claim. "Something IS happening." Contains the inequality (≠, <, >).
CRITICAL RULE: You NEVER "accept H0." You can only fail to reject it. Just as a defendant is never "proven innocent" -- there is just "not enough evidence to convict."
H0 always has the = sign. H1 has the inequality. H1 is what the researcher is trying to PROVE.

🚨 7. Type I & Type II Errors
ErrorSymbolWhat HappensSecurity Analogy
Type IalphaReject a TRUE H0 (false alarm)IDS screams "ATTACK!" during normal traffic
Type IIbetaFail to reject a FALSE H0 (missed detection)Real attack slips through silently
Power = 1 - beta = the probability of correctly detecting a real effect. Higher power = better at catching real attacks.

The Fundamental Tradeoff

More sensitivity (lower threshold) → more false alarms (Type I)
Quieter alarms (higher threshold) → miss real attacks (Type II)

Solution: Bigger samples reduce BOTH error types simultaneously.
IDS Analogy
Type I = False Positive (crying wolf) | Type II = False Negative (sleeping through a break-in)
📝 8. The 6-Step Hypothesis Testing Procedure
  1. State H0 and H1 -- define what you are testing
  2. Pick alpha -- significance level (0.01, 0.05, or 0.10). MUST be chosen BEFORE looking at data
  3. Choose the test statistic -- Z, t, chi-square, F, etc.
  4. Find its distribution -- under assumption that H0 is true
  5. Locate rejection region and critical point -- based on H1 direction and alpha
  6. Compute test statistic and decide -- if test stat falls in rejection region, reject H0

🎯 9. Significance Levels & Decision Rules
AlphaConfidenceStrictnessUse Case
0.0199%Very strictMedical, safety-critical
0.0595%StandardMost research, security thresholds
0.1090%LenientExploratory, low-stakes
Decision Rule: If the test statistic falls in the rejection region (beyond the critical point), reject H0. Otherwise, fail to reject H0.
Security Application: Setting alpha for an IDS is like choosing sensitivity. Alpha = 0.01 means fewer false alarms but you might miss attacks. Alpha = 0.10 catches more threats but triggers more false positives.
⚠️ 10. Common Exam Traps
Watch out for these mistakes:
  1. Saying "accept H0" -- WRONG. You can only "fail to reject H0." The absence of evidence is not evidence of absence.
  2. Mixing up Type I and Type II -- Type I = false alarm (reject true H0). Type II = missed detection (fail to reject false H0).
  3. Putting rejection region in wrong tail -- H1 determines direction. H1: mu > value = right tail. H1: mu < value = left tail.
  4. Choosing alpha AFTER seeing data -- alpha must be set before analysis begins. Otherwise it is p-hacking.
  5. Confusing alpha with beta -- alpha = P(Type I error). beta = P(Type II error). Power = 1 - beta.
  6. Forgetting that bigger samples help -- larger n reduces both Type I and Type II error rates.
