W7 - Log Analysis, Gestalt Principles & Decision Trees
  • LOG: Chronological record of events from IT components (OS, apps, network devices, security tools). Entry contains: timestamp, event type, source, user/IP/severity.
  • LOG TYPES (SANS-AWD): System (OS/hardware events, startups, shutdowns, driver failures), Application (app errors, user activities, config changes, crashes), Network (traffic from routers/switches/firewalls/IDS, connection attempts, bandwidth), Security (antivirus/IDS/SIEM events - CRUCIAL for incident response, malware detection, policy violations), Audit (compliance, forensics, user logins, file access, privilege escalation tracking), Web Server (client requests, server responses from IIS/Apache, HTTP status codes, referrer tracking), Database (queries, data modifications, schema changes, SQL injection detection, failed auth attempts).
  • LOG USE CASES: System logs catch hardware failures before cascading outages. Security logs feed SIEM correlation rules. Audit logs prove compliance to regulators. Web server logs reveal scanning/enumeration. Database logs detect data exfiltration attempts.
  • LOG BEST PRACTICES: Centralize (send all to SIEM), set retention policies (some regulations require 3yr, some 7yr, some indefinite), protect integrity (tamper-proof storage, hash chains), normalize formats (different vendors different formats), correlate across sources (single event in multiple logs = richer picture), alert on anomalies (baseline normal, flag deviations), implement log rotation to manage data size.
  • LOG VISUALIZATION: Transforming raw log data into charts/graphs so analysts can quickly identify potential incidents, track progression, and respond. Essential for forensics, compliance, anomaly detection. Timeline charts for temporal patterns, heat maps for density, network graphs for connections.
  • GESTALT - PROXIMITY: Near objects = grouped. Directs scanning direction -- horizontal spacing encourages left-to-right scanning, vertical spacing encourages top-to-bottom scanning. Use whitespace deliberately in dashboards to create logical groupings.
  • GESTALT - SIMILARITY: Objects alike in color/size/shape perceived as grouped. Use same color for related data across multiple charts. Consistent color coding across dashboard = instant pattern recognition.
  • GESTALT - CLOSURE: Brain completes incomplete shapes into whole/closed/regular forms. Ambiguous stimuli perceived as complete. Allows sparse design -- don't need to draw everything, viewer's brain fills gaps.
  • GESTALT - CONTINUITY: Aligned objects perceived as following smooth continuous paths. Dashed line perceived as single continuous line, not separate segments. Use for trend lines, flow indicators.
  • GESTALT - ENCLOSURE: STRONGEST principle. Bounded region = group. Use borders/shading for MOST important groupings in dashboards. Overrides all other principles.
  • GESTALT - CONNECTION: Objects linked by lines perceived as grouped. Stronger than proximity but WEAKER than enclosure. Use for flowcharts, network diagrams, org charts, attack path visualization.
  • STRENGTH ORDER: Enclosure > Connection > Proximity/Similarity. Use enclosure for critical groupings, connection for relationships, proximity for layout.
  • DECISION TREES: Flowchart classifier. Root node (top, no parent, first question), Internal nodes (splits/questions), Branches (answers/paths), Leaf nodes (bottom, no children, final class label). Depth = longest path root to leaf. Handles BOTH numeric and categorical predictors.
  • TREE TYPES: Classification tree = categorical target (spam/not-spam, attack/normal). Regression tree = numeric target (predicted response time, predicted loss amount). Same splitting logic, different leaf output.
  • HOW TREES BUILD: Recursive partitioning -- at each node pick split that maximizes purity gain (reduces impurity most). 100% one class = pure leaf. No distributional assumptions needed (unlike hypothesis tests). Works with missing data, mixed types.
  • OVERFITTING: Tree too deep memorizes training noise, flops on fresh data. Fixes: Early stopping (stop when node too few obs) or Pruning (grow full tree, cut unhelpful splits). Bottom-up pruning preferred (avoids throwing away good splits below bad one). Top-down pruning risky.
  • CART vs ID3 vs C4.5: CART (Breiman 1984) = binary splits only, handles numeric+categorical, prunes by cost-complexity. ID3 (Quinlan 1986) = can do multi-way splits, uses information gain. C4.5 = improved ID3, uses gain ratio (normalizes for number of splits), handles continuous attributes and missing values.
  • SECURITY USE: Trees easy to explain to non-technical people (huge for security reporting to executives/board). Flowchart format is universally understood. Works with big data, both numeric and categorical. No need to justify distributional assumptions to auditors.
W8 - Cloud Security, Parametric vs Non-Parametric & Sign Test
  • CLOUD MODELS: IaaS (you manage OS/apps/data - AWS EC2), PaaS (you manage apps/data only - Heroku), SaaS (just use it - Office 365). Shared responsibility model: provider secures infrastructure, customer secures what they put on it. More managed = less customer responsibility.
  • IAAS SECURITY: Customer responsible for OS patching, firewall rules, access controls, encryption. Provider handles physical security, hypervisor. PAAS: Customer handles app code, data, user access. Provider handles OS, runtime, middleware. SAAS: Customer handles user access, data classification. Provider handles almost everything else.
  • CLOUD DATA SOURCES: CloudWatch (AWS monitoring/metrics), GuardDuty (AWS threat detection), CloudTrail (AWS API call logging), Defender (Azure threat protection), Sentinel (Azure SIEM), VPC Flow Logs (network traffic), Access Advisor (IAM usage). Audit logs, access logs, API call logs, network flow logs.
  • CLOUD VIZ CHALLENGES: Scale (enormous volume from distributed resources), Multi-tenancy (shared infra complicates attribution), Ephemeral infrastructure (resources spin up/down rapidly, persistent monitoring hard), geographic distribution, API-driven changes harder to track than physical.
  • CROWDSTRIKE 2025: Avg breakout time 48 min (fastest 51 sec). Vishing up 442%. Initial access via vulns 52%. Access broker ads up 50%. China-nexus activity up 150%. FAMOUS CHOLLIMA (DPRK) using GenAI for fake IT worker campaigns.
  • PARAMETRIC: Assume normal distribution, test MEAN, use means/SDs. Examples: Z-test (known sigma, large n), t-test (unknown sigma, small n). More power when assumptions hold. NOT robust to outliers. Use when bell-shaped, large n, continuous ratio/interval data.
  • NON-PARAMETRIC: Distribution-free, test MEDIAN, use ranks/signs. Sign test, Wilcoxon, Kruskal-Wallis. Robust to outliers. Slightly lower power but fewer assumptions. Use when skewed, ordinal, outliers, small n, non-normal. Still need continuous + at least ordinal scale. NOT "assumption-free" -- just fewer assumptions.
  • KEY INSIGHT: Non-parametric tests ask the SAME questions as parametric tests but use ranks/signs instead of raw values. Sign test is non-parametric analog of one-sample t-test. Kruskal-Wallis is non-parametric analog of one-way ANOVA.
  • SIGN TEST: Simplest non-parametric. Tests claim about MEDIAN (NOT mean). H0: M=m0. Step 1: State H0/H1. Step 2: Set alpha. Step 3: For each Xi, compute sign of (Xi-m0). Record + if positive, - if negative. DISCARD ties (Xi=m0) and SHRINK n. Step 4: R = count of pluses. Step 5: Under H0, R ~ Binomial(n, 0.5) -- coin flip model. Step 6: Compare R to critical value. Decide.
  • SIGN TEST TAILS: Left-sided: H1: Mm0 (many pluses = reject, most values above). Two-sided: H1: M!=m0 (too few OR too many pluses = reject).
  • SIGN TEST INTUITION: If true median is m0, about half should be above and half below (50/50 coin flip). Way off from half = median probably not m0.
  • SECURITY RELEVANCE: Login times, packet sizes, dwell times, incident response durations have heavy tails and skewed distributions. Can't assume normality for this data. Non-parametric tests are almost always more appropriate for security analytics.
  • DECISION RULE: Bell-shaped, large n, continuous -> parametric (more power). Skewed, ordinal, outliers, small n -> non-parametric. When in doubt, non-parametric is safer (valid even if data IS normal, just slightly less powerful).
W10 - APTs, Kill Chain & Linear Regression
  • PERSISTENT THREATS: Ongoing, recurring attack vectors. Common: phishing, ransomware, DDoS, botnets, malware (viruses/trojans/worms), MITM, brute force, insider threats.
  • APT: Advanced (custom malware, zero-day exploits) + Persistent (months/years undetected, not deterred by failures) + Threat (data theft, service disruption, infrastructure damage). "Slow and low." State-sponsored or organized crime.
  • THREAT ACTORS: Cybercriminals (financial gain), State-sponsored (espionage/disruption), Hacktivists (political/social causes), Insiders (grievance/personal gain), Terrorists (fear/destruction), Competitors (business advantage).
  • TIER I (Script Kiddies): Rely on others' code, use pre-built exploit tools, minimal skill. Budget ~$10s. TIER II: Develop own tools from KNOWN vulnerabilities, more skilled but still limited to published CVEs.
  • TIER III: DISCOVER unknown vulnerabilities, develop rootkits, target executives and high-value individuals, sell stolen data on dark markets. TIER IV: Organized teams, well-funded ($Ms), sustained campaigns, develop sophisticated custom toolkits.
  • TIER V: Influence manufacturing and supply chain -- insert backdoors BEFORE products ship. Budget $Bs. TIER VI: Full spectrum operations -- cyber + military + intelligence combined. Nation-state elite. CREATE vulnerabilities upstream.
  • TIER PROGRESSION: I-II EXPLOIT known vulns ($10s) -> III-IV DISCOVER unknown vulns ($Ms) -> V-VI CREATE vulns through supply chain ($Bs). TRAP: V-VI CREATE, not just discover.
  • KILL CHAIN (7 steps): Recon (research target) -> Weaponize (build payload) -> Deliver (phishing/USB/web) -> Exploit (trigger vulnerability) -> Install (establish persistence) -> C2 (command and control channel) -> Actions on Objectives (exfil/destroy). Break ANY link to stop the attack. Defense works at every stage.
  • KASPERSKY 5-STAGE: Gain Access -> Establish Foothold -> Deepen Access -> Move Laterally -> Look, Learn, Remain. TRAP: Kill Chain has 7 steps, Kaspersky has 5 -- don't confuse.
  • APT DETECTION: Continuous monitoring + rapid incident response essential. Look for: unusual outbound traffic, beaconing patterns (regular C2 check-ins), lateral movement, credential harvesting, data staging before exfil. APT groups NOT globally standardized naming: Mandiant uses numbers (APT28, APT29), CrowdStrike uses animals (Fancy Bear, Cozy Bear).
  • CROWDSTRIKE NAMING: Bear=Russia, Chollima=DPRK, Kitten=Iran, Leopard=Pakistan, Panda=China, Buffalo=Vietnam, Crane=South Korea, Hawk=Syria, Jackal=Hacktivists, Spider=eCrime, Ocelot=Colombia.
  • LINEAR REGRESSION: Y=b0+b1X+e. Y=response/dependent (what you predict). X=predictor/independent. b0=intercept (Y when X=0). b1=slope (change in Y per 1-unit increase in X -- THE NUMBER YOU CARE ABOUT MOST). e=error term (random scatter, assumed to average zero). Simple=one predictor. Multiple=more than one predictor. Linear=straight line relationship.
  • SLOPE INTERPRETATION: Positive slope = X and Y rise together. Negative slope = one rises, other falls. Near-zero slope = X tells little about Y. Security example: regress failed logins on hour -- slope of 5 means each additional hour = 5 more failed logins. Slope of -3 for patching = each patch reduces incidents by 3.
  • RESIDUAL: Vertical distance from observed point to the fitted line. Residual = actual Y - predicted Y. Positive residual = point above line. Negative = below. Sum of residuals = 0 by design. Pattern in residuals = model is wrong.
  • LEAST SQUARES: Finds best line by minimizing sum of SQUARED residuals. Why square? Prevents positive and negative errors from canceling. Penalizes large errors more than small ones.
  • GAUSS-MARKOV: Least squares = BLUE (Best Linear Unbiased Estimator). Best straight-line fit without extra assumptions. Normality needed ONLY for confidence intervals and hypothesis tests on slope/intercept -- NOT for fitting the line itself.
  • ALWAYS CHECK: Is the relationship actually linear? Scatter plot FIRST. Non-linear data with linear fit = misleading conclusions. Check for outliers, patterns, curvature, clusters.
W11 - Collaboration Tools & Logistic Regression
  • COLLABORATION: Two or more people/orgs working toward common goal. Characteristics: shared goals, mutual respect, open communication, shared decision-making, shared accountability. People + training + data-driven culture matter as much as tools.
  • COLLABORATION FEATURES: Sharing/access controls (view/comment/edit per user), Real-time editing (like Google Docs), Commenting/annotation on data points, Version control (track changes/revert), Interactive dashboards (filters/drill-down), Data integration/sync across sources, Security features (encryption/secure auth), User-friendly interface, Alerts/notifications, Mobile access, Ecosystem integration (Excel critical for finance sector).
  • POWER BI: Publish Excel to workspace, create interactive reports/dashboards, embed live in PowerPoint (interactive in BOTH edit AND slideshow modes), mobile apps with annotation and sharing, sharing permissions (org-wide/existing access/specific people). Tight Microsoft ecosystem integration.
  • TABLEAU: Publish to Tableau Cloud, subscriptions (scheduled email delivery of views), metrics tracking, threshold alerts (get notified when KPI crosses boundary), commenting on visualizations, mobile-responsive layouts. KEY DIFF: Power BI = Excel/PowerPoint embedding. Tableau = threshold alerting + subscriptions.
  • LOGISTIC REGRESSION: Predicts probability (0-1) of binary yes/no outcome using S-shaped SIGMOID curve. Always stays within [0,1] unlike linear regression. Formula: P(Y=1) = 1/(1+e^-(b0+b1X)). Use for binary outcomes (attack/normal, malware/benign, fraud/legit). NOT for continuous Y.
  • WHY NOT LINEAR FOR YES/NO? Straight line shoots below 0 or above 1 -- nonsensical for probability. You can't have -0.3 probability of attack. Logistic S-curve stays in valid [0,1] range naturally.
  • SIGMOID SHAPE: Flattens near 0 at one end, flattens near 1 at other end, smooth S-shaped transition in middle. Small changes in X near the center produce big changes in probability. Changes at extremes barely move the probability.
  • CHALLENGER EXAMPLE: Logistic regression predicted O-ring failure probability from launch temp. At 53F = 0.86 (very risky). At 81F = 0.05 (safe). Launched at 36F (even colder). Warning was ignored -- catastrophic result. The model worked; the decision-making failed.
  • CUTOFF IS A DIAL: Not a fixed setting. Default 0.5 but adjustable. Lower cutoff (0.20) = catch more true positives BUT more false alarms. Higher cutoff (0.70) = fewer false alarms BUT miss more real cases. NO FREE LUNCH.
  • O-RING CUTOFF EXAMPLE: At cutoff 0.70 they got zero class-0 errors but 0.57 class-1 error rate (missed 57% of real failures). At cutoff 0.20 they caught more real failures but class-0 errors jumped. When missing a real failure is CATASTROPHIC, use LOWER cutoff -- accept more false alarms to avoid deadly misses.
  • CONFUSION MATRIX: 2x2 table: TP (predicted attack, WAS attack), TN (predicted normal, WAS normal). FP = flagged something fine = Type I = false alarm (annoying but not catastrophic). FN = missed something real = Type II = dangerous miss (catastrophic in security). Diagonal = correct predictions. Off-diagonal = errors. Point is to see WHICH WAY you're wrong.
  • SENSITIVITY (TPR) = TP/(TP+FN) "of real attacks, how many caught?" SPECIFICITY (TNR) = TN/(TN+FP) "of normal, how many correctly cleared?" ACCURACY = (TP+TN)/total. ERROR RATE = (FP+FN)/total.
  • ACCURACY TRAP: 99% normal data -> lazy model predicts all normal -> 99% accuracy BUT 0% sensitivity. Catches ZERO attacks. USELESS. Security cares about sensitivity far more than raw accuracy.
  • ROC CURVE: Plots sensitivity (y) vs 1-specificity (x) across ALL cutoff values. Each point on curve = one cutoff setting. Perfect classifier hugs top-left corner (shoots up y-axis then across). Useless classifier sits on diagonal (coin flip).
  • AUC SCALE: 0.5 = random/coin flip (BAD/useless), 0.6-0.7 = poor, 0.7-0.8 = fair/acceptable, 0.8-0.9 = good, 0.9-1.0 = excellent, 1.0 = perfect. Single number in [0.5, 1.0] summarizing classifier quality across all cutoffs. Higher = better.
W12 - ANOVA Family & Non-Parametric Alternatives
  • PROGRESSION: 1 sample -> one-sample t-test. 2 samples -> two-sample t-test. 3+ samples -> ANOVA. Each step up handles more groups while controlling Type I error.
  • ANOVA: Extends t-test from 2 groups to 3+ groups. H0: mu1=mu2=...=muk (all means equal). H1: at least one differs. Controls false positive rate (multiple t-tests inflate Type I error -- 3 groups at alpha=0.05 inflates to ~14%).
  • F-STATISTIC: F = MSB/MSW = Between-group variance / Within-group variance = Signal/Noise. MSB = SS_Between/(k-1). MSW = SS_Within/(N-k). k = number of groups. N = total observations. Large F -> reject H0 (groups differ). TRAP: F = between/within, NOT within/between.
  • DECISION: Reject H0 if F > F_critical OR if p-value <= alpha. Both methods give same answer. F_critical comes from F-distribution table with df1=k-1, df2=N-k.
  • ASSUMPTIONS: Independence (each measurement from different unit), Normality (approx normal within each group -- check with Shapiro-Wilk test or Q-Q plots), Equal variance/homoscedasticity (check with Levene's test or Bartlett's test). Bartlett's is more powerful but more sensitive to non-normality.
  • MINITAB: Stat > ANOVA > One-Way. Read F-statistic, p-value, R-squared from output. R-squared = proportion of variance explained by groups. Also: Stat > Stack > Rows for reshaping, Stat > Basic Stats > Graph Summary for normality check, Stat > ANOVA > Test for Equal Variances.
  • POST-HOC: Tukey HSD after significant F to find WHICH groups differ. "ANOVA says someone is different. Tukey says WHO is different." Pairwise comparisons with family-wise error control.
  • SOC EXAMPLE: 3 SOC teams, 8 incidents each. Means: A=52.5min, B=31.8min, C=68.5min. Grand mean=50.9min. F=32.75, df=(2,21), p=0.000. F_crit(0.05,2,21)=3.47. Since 32.75>>3.47, reject H0. Tukey: all pairwise comparisons significant (p<0.01). Team B is fastest, Team C is slowest.
  • TWO-WAY ANOVA: 2 factors, tests THREE things: Main effect A, Main effect B, and INTERACTION (A*B). Asks THREE questions. Read INTERACTION FIRST in output -- it's the most important concept.
  • INTERACTION: Effect of one factor DEPENDS on other factor's level. Non-parallel lines in interaction plot = interaction EXISTS. Parallel lines = no interaction. If interaction significant: interpret main effects WITH CAUTION -- can't make blanket statements like "method A is better" without specifying the level of the other factor.
  • SECURITY 2-WAY EXAMPLE: Factor A: Training type (Online/In-Person). Factor B: Experience (Junior/Senior). Response: % threats detected. Interaction p=0.004 (significant). In-person helps juniors MORE than seniors. Cannot say "in-person is better" without specifying experience level.
  • MANOVA: Multiple correlated response variables simultaneously. Why not multiple ANOVAs? 1) Inflates Type I error, 2) Ignores correlations between responses, 3) Can't detect differences in COMBINATIONS of outcomes that individual tests miss.
  • MANOVA DETAILS: H0: mean VECTOR equal across groups. Test stat: Wilks' Lambda (smaller = more evidence against H0). Extra assumptions: multivariate normality, homogeneity of covariance matrices (Box's M test -- sensitive to non-normality), no severe multicollinearity (r>0.9 problematic), n per group must > number of response variables.
  • MANOVA EXAMPLE: 3 SOC teams, 3 metrics (detection rate, FP rate, MTTR). Wilks' Lambda=0.312, F(6,72)=8.94, p<0.001. Follow-up: detection p=0.003, FP rate p=0.041, MTTR p=0.218. MANOVA reveals combined profile differs even when individual MTTR is not significant alone.
  • NON-PARAMETRIC ALTERNATIVES: Kruskal-Wallis (replaces one-way ANOVA, ranks-based), Friedman (replaces two-way/repeated measures ANOVA). Use when non-normal.
  • SECURITY DATA NON-NORMAL REASONS: Zero-inflated counts (most days 0 incidents), skewed response times (few take 10x longer), ordinal severity (CVSS 0-10), heavy tails (power-law losses), small samples (breach investigations n=5-15), categorical variables (severity levels). Almost NEVER bell-shaped.
  • WHEN ASSUMPTIONS FAIL: Normality fails -> Kruskal-Wallis. Unequal variances -> Welch's ANOVA. Blocked/repeated measures non-normal -> Friedman.

PARAMETRIC vs NON-PARAMETRIC DECISION TABLE
  • 1 SAMPLE: t-test (parametric, tests mean) vs Sign test (non-parametric, tests MEDIAN). TRAP: sign test = median NOT mean.
  • 2 GROUPS: 2-sample t-test vs Wilcoxon rank-sum (Mann-Whitney U).
  • 3+ GROUPS: ANOVA vs Kruskal-Wallis. TRAP: non-normal -> Kruskal-Wallis, NOT ANOVA.
  • BLOCKED/REPEATED: Two-way ANOVA vs Friedman test.
  • CORRELATION: Pearson r (parametric, linear, continuous) vs Spearman rho (non-parametric, monotonic, ordinal OK).
  • MULTIPLE RESPONSES: MANOVA (2+ correlated responses). No non-parametric direct equivalent -- transform or use permutation tests.
  • DECISION: Bell-shaped, large n, continuous -> parametric. Skewed, small n, ordinal, outliers, heavy tails -> non-parametric. Security data is almost NEVER bell-shaped.
CONFUSION MATRIX & CLASSIFICATION METRICS
  • TP: Predicted attack, WAS attack (correct catch). TN: Predicted normal, WAS normal (correct clear).
  • FP (Type I): Predicted attack, was NORMAL (false alarm -- annoying but not catastrophic). FN (Type II): Predicted normal, was ATTACK (missed detection -- DANGEROUS in security).
  • Sensitivity/Recall/TPR = TP/(TP+FN) -- "of all real attacks, how many caught?" THE metric security cares about most.
  • Specificity/TNR = TN/(TN+FP) -- "of all normal traffic, how many correctly identified?"
  • Accuracy = (TP+TN)/total. MISLEADING with imbalanced data. 99% normal -> lazy "all normal" model = 99% accuracy, 0% sensitivity. USELESS.
  • Cutoff tradeoff: Lower cutoff -> higher sensitivity (catch more) but lower specificity (more false alarms). Higher cutoff -> reverse. No free lunch. Security prefers low cutoff.
  • ROC/AUC: Plot sensitivity vs 1-specificity across all cutoffs. Hugs top-left = good. Diagonal = coin flip. AUC: 0.5=random (BAD), 0.7-0.8=fair, 0.8-0.9=good, >0.9=excellent, 1.0=perfect.
ANOVA FAMILY COMPARISON
  • t-test: 2 groups, 1 factor, 1 response. Compares two means.
  • One-Way ANOVA: 3+ groups, 1 factor, 1 response. F=MSB/MSW. Tukey post-hoc for pairwise. Assumptions: independence, normality, equal variance.
  • Two-Way ANOVA: 2 factors, 1 response. Tests main effects + INTERACTION (read FIRST). Non-parallel lines = interaction. Balanced design preferred.
  • Repeated Measures: 1+ factors, 1 response, same subjects measured multiple times.
  • MANOVA: 1+ factors, 2+ CORRELATED responses. Uses Wilks' Lambda. Extra assumptions: multivariate normality, homogeneous covariance (Box's M), no multicollinearity. Avoids inflated Type I from multiple ANOVAs.
  • NON-PARAMETRIC: Kruskal-Wallis (replaces 1-way ANOVA), Friedman (replaces 2-way/blocked). For non-normal security data.
  • WHY NOT MULTIPLE t-TESTS? 3 groups = 3 comparisons. Alpha inflates from 0.05 to ~14%. ANOVA controls family-wise error rate.
REGRESSION & CLASSIFICATION MODELS
  • LINEAR: Y=b0+b1X+e. Continuous Y. b1=slope=most important (unit change in X -> b1 change in Y). Least squares minimizes sum of squared residuals. Gauss-Markov = BLUE. Scatter plot FIRST. Normality only for CI/tests, not fitting.
  • LOGISTIC: Binary Y (0/1). Sigmoid curve P(Y=1)=1/(1+e^-(b0+b1X)). Always stays [0,1]. Cutoff tradeoff: lower = more catches + more false alarms. Challenger example: 0.86 failure prob at 53F.
  • DECISION TREE: Root/internal/leaf/branch. Recursive partitioning for purity. Overfitting -> pruning (bottom-up preferred). CART=binary splits, cost-complexity pruning. ID3=multi-way, info gain. C4.5=gain ratio. No distributional assumptions. Classification (categorical) vs regression (numeric) tree.
  • WHEN TO USE: Continuous outcome -> linear regression. Binary outcome -> logistic regression. Non-linear/categorical splits, need explainability -> decision tree. Non-normal 3+ groups -> Kruskal-Wallis (not ANOVA).
WHAT MODEL TO USE - QUICK DECISION GUIDE
  • Predict continuous number? -> Linear regression (Y=b0+b1X+e). Check linearity with scatter plot first.
  • Predict yes/no probability? -> Logistic regression (sigmoid). NOT linear regression (goes outside [0,1]).
  • Classify with explainable rules? -> Decision tree. No distributional assumptions. Easy to show executives.
  • Compare 2 group means, normal data? -> Two-sample t-test.
  • Compare 3+ group means, normal data? -> One-way ANOVA + Tukey post-hoc.
  • Compare 3+ groups, NON-normal? -> Kruskal-Wallis (non-parametric ANOVA).
  • Test median, non-parametric? -> Sign test. R~Binomial(n,0.5). Discard ties.
  • 2 factors + interaction? -> Two-way ANOVA. Read interaction FIRST.
  • Multiple correlated outcomes? -> MANOVA. Don't run separate ANOVAs.
  • Non-normal correlation? -> Spearman rho (ranks). Normal -> Pearson r.
  • Blocked/repeated, non-normal? -> Friedman test (replaces repeated measures ANOVA).

GESTALT & DASHBOARD DESIGN
  • GESTALT STRENGTH: Enclosure (STRONGEST, borders/shading) > Connection (lines linking) > Proximity (near=group) / Similarity (alike=group). Also: Closure (complete shapes), Continuity (smooth paths).
  • FEW'S PRINCIPLES: "Single screen at a glance." Anti-patterns: exceeding single screen, no context ("compared to WHAT?"), excessive precision, wrong chart type, meaningless variety, 3D charts, Y-axis not at 0, clutter, misused color.
  • MACKINLAY: Expressiveness (ALL and ONLY the facts) + Effectiveness (readily perceived by viewer). Perception: Position > Length > Angle > Area > Color. Bar > pie always.
  • DESIGN: Top-left = prime real estate. Related metrics together. Consistent color coding. Bar charts for categories (gaps between bars). Histograms for distributions (bars touch). Pre-attentive features processed <200ms (color, size, orientation, shape). Max ~4 distinct features.
HYPOTHESIS TESTING - POST-MIDTERM CONTEXT
  • SETUP: H0 has = sign. H1 has inequality. H1 decides WHERE rejection region. Alpha decides HOW BIG. Never "accept H0" -- "fail to reject."
  • ERRORS: Type I = alpha = false alarm (reject true H0). Type II = beta = missed detection. Power = 1-beta. In security, Type II usually WORSE (missed attack). Bigger samples reduce BOTH.
  • SIGN TEST: H0: M=m0. Count pluses. R~Binomial(n,0.5). Discard ties, shrink n. Non-parametric analog of t-test for median.
  • ANOVA H-TEST: H0: all group means equal. F=MSB/MSW. Large F = reject. Post-hoc Tukey for which groups differ.
  • SECURITY: H0 = "system normal." Type I = false alarm (wastes time). Type II = missed attack (catastrophic). Lower cutoff = catch more but more false alarms.
  • P-VALUE: P(data this extreme | H0 true). p reject. Two-sided: DOUBLE the one-tail probability. p=2*P(Z>=|z|). P-value is NOT P(H0 is true). P-value is NOT the probability the null is true.

EXAM TRAPS - FINAL SPECIFIC (25 TRAPS)
  • 1. Sensitivity = TP/(TP+FN) catches attacks. Specificity = TN/(TN+FP) clears normals. Don't swap numerators/denominators.
  • 2. AUC=0.5 is BAD (random coin flip), NOT good. AUC=1.0 is perfect. 0.7=fair, 0.8=good, 0.9=excellent.
  • 3. ANOVA F=MSB/MSW (between/within), NOT within/between. Large F = reject.
  • 4. Two-way ANOVA: read INTERACTION first. Non-parallel lines = interaction exists. Can't interpret main effects alone when interaction significant.
  • 5. Non-normal data -> Kruskal-Wallis, NOT regular ANOVA. Security data is almost NEVER bell-shaped.
  • 6. Binary outcome (yes/no) -> logistic regression, NOT linear. Linear produces values outside [0,1].
  • 7. APT Tiers V-VI CREATE vulnerabilities (supply chain), not just discover them. I-II exploit, III-IV discover, V-VI CREATE.
  • 8. CrowdStrike Bear=RUSSIA. Panda=China. Kitten=Iran. Chollima=DPRK. Don't mix up. Bear is NOT China.
  • 9. "Accept H0" is WRONG. Say "fail to reject H0." Never proven, just insufficient evidence.
  • 10. Accuracy misleading with imbalanced data. 99% normal -> 99% accurate model with 0% sensitivity = useless.
  • 11. Gestalt: Enclosure is STRONGEST, not proximity. Use borders/shading for key groupings.
  • 12. Sign test: discard TIES, count only pluses. R~Binomial(n,0.5) where n EXCLUDES ties. Tests MEDIAN not mean.
  • 13. Non-parametric is NOT "assumption-free" -- still needs continuous + ordinal. Just fewer assumptions.
  • 14. Kill Chain = 7 steps (Lockheed Martin). Kaspersky = 5 stages. Don't confuse the two models.
  • 15. MANOVA uses Wilks' Lambda. Box's M test checks homogeneity of covariance matrices. Multiple ANOVAs inflate Type I error.
  • 16. Decision tree root = top (no parent). Leaf = bottom (no children). Bigger tree is NOT always better (overfits). Prune bottom-up.
  • 17. Scatter plot FIRST before fitting regression. Check linearity. b1 (slope) matters most, not b0 (intercept).
  • 18. Lower cutoff = catch more true positives AND more false alarms. Higher cutoff = miss more. No free lunch.
  • 19. P-value is NOT the probability H0 is true. It's P(data this extreme | H0 true). Common exam trick.
  • 20. CART = binary splits only. ID3 = can do multi-way splits. C4.5 = gain ratio (improved ID3). Don't confuse algorithms.
  • 21. Residual = actual - predicted (vertical distance to line). Pattern in residuals = model is WRONG (non-linearity).
  • 22. Normality needed for CI/tests on regression coefficients, NOT for fitting the line. Gauss-Markov = BLUE regardless.
  • 23. In security: FN (Type II, missed attack) is WORSE than FP (Type I, false alarm). Opposite of most textbook emphasis.
  • 24. Naming conventions NOT globally standardized. CrowdStrike=animals, Mandiant=numbers (APT28), Microsoft=weather (Blizzard/Typhoon).
  • 25. MANOVA requires n per group > number of response variables. Box's M is sensitive to non-normality. Wilks' Lambda: smaller = more evidence against H0.
QUICK DECISION GUIDE - EXAM Q&A
  • "Binary outcome model?" -> Logistic regression (sigmoid, [0,1]). "Continuous outcome model?" -> Linear regression (Y=b0+b1X+e).
  • "3+ group comparison, normal?" -> ANOVA. "3+ groups, NOT normal?" -> Kruskal-Wallis.
  • "Test median, non-parametric?" -> Sign test. R~Binomial(n,0.5). Discard ties.
  • "2 factors, check interaction?" -> Two-way ANOVA. Read interaction FIRST. Non-parallel lines = interaction.
  • "Multiple correlated responses?" -> MANOVA. Don't run separate ANOVAs (inflates Type I).
  • "IDS misses attack?" -> Type II (FN). "IDS false alert?" -> Type I (FP). Which worse in security? -> Type II.
  • "AUC=0.52?" -> Terrible (near random). "99% accuracy, 0% sensitivity?" -> Useless model, imbalanced data.
  • "Non-parallel interaction plot?" -> Interaction exists, interpret BEFORE main effects.
  • "APT tier that CREATES vulns?" -> V-VI ($Bs, supply chain). "Uses others' tools?" -> I-II ($10s).
  • "Strongest Gestalt principle?" -> Enclosure. "Tree too deep?" -> Overfitting. Fix: prune bottom-up.
  • "Avg breakout time (CS 2025)?" -> 48 minutes (fastest 51 sec). "Bear = which country?" -> Russia.
  • "Power BI vs Tableau strength?" -> Power BI = PowerPoint embedding. Tableau = threshold alerting.
  • "Why not multiple ANOVAs?" -> Inflates Type I, ignores correlations, misses combination differences. Use MANOVA.
  • "Challenger O-ring lesson?" -> Model predicted danger at cold temps (0.86 at 53F). Warning ignored. Decision failure, not model failure.
  • "Expressiveness principle?" -> Mackinlay. ALL and ONLY the data. "Data-ink ratio?" -> Tufte. Max data, min junk.
KEY FORMULAS - POST-MIDTERM
  • LINEAR REG: Y=b0+b1X+e. b1=slope (most important). Least squares minimizes sum(residual^2). Gauss-Markov: BLUE. Residual = Y_actual - Y_predicted.
  • LOGISTIC: P(Y=1) = 1/(1+e^-(b0+b1X)). Sigmoid [0,1]. Output is probability, not class. Apply cutoff to get class.
  • SENSITIVITY: TP/(TP+FN). SPECIFICITY: TN/(TN+FP). ACCURACY: (TP+TN)/total. ERROR RATE: (FP+FN)/total.
  • ANOVA: F=MSB/MSW. MSB=SS_between/(k-1). MSW=SS_within/(N-k). df_between=k-1. df_within=N-k. Large F -> reject H0.
  • SIGN TEST: R = count of pluses. Under H0: R ~ Binomial(n, 0.5). n excludes ties. Compare to binomial table or use p-value.
  • MANOVA: Wilks' Lambda (smaller = more evidence against H0). H0: mean vectors equal across groups. Box's M for covariance homogeneity.
  • DECISION TREE: Purity gain at each split. CART: cost-complexity pruning parameter alpha. Information gain (ID3). Gain ratio (C4.5).
  • TYPE I INFLATION: With c comparisons at alpha, family-wise error = 1-(1-alpha)^c. 3 groups: 1-(0.95)^3 = 0.143 (~14%). ANOVA controls this.
