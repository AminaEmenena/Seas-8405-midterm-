W7 - Log Analysis & Gestalt Principles
  • LOG: Chronological record of events from IT components (OS, apps, network devices, security tools). Entry contains: timestamp, event type, source, user/IP/severity.
  • LOG TYPES (SANS-AWD): System (OS/hardware events, startups, shutdowns), Application (app errors, user activities, config changes), Network (traffic from routers/switches/firewalls/IDS), Security (antivirus/IDS/SIEM events - CRUCIAL for incident response), Audit (compliance, forensics, user logins, file access), Web Server (client requests, server responses from IIS/Apache), Database (queries, data modifications, schema changes, SQL injection detection).
  • LOG VISUALIZATION: Transforming raw log data into charts/graphs so analysts can quickly identify potential incidents, track progression, and respond. Essential for forensics, compliance, anomaly detection.
  • GESTALT 6 PRINCIPLES: Proximity (near=grouped, directs scanning direction), Similarity (alike in color/size/shape=grouped), Closure (brain completes incomplete shapes into whole forms), Continuity (aligned objects follow smooth paths), Enclosure (STRONGEST - bounded region=group, use borders/shading), Connection (linked by lines=grouped, stronger than proximity but WEAKER than enclosure).
  • STRENGTH ORDER: Enclosure > Connection > Proximity/Similarity. Use enclosure (borders, shading) for MOST important groupings in dashboards.
  • DECISION TREES: Flowchart classifier. Root node (top, no parent, first question), Internal nodes (splits/questions), Branches (answers/paths), Leaf nodes (bottom, no children, final class label). Depth = longest path root to leaf.
  • HOW TREES BUILD: Recursive partitioning -- at each node pick split that maximizes purity gain (reduces impurity most). 100% one class = pure leaf. No distributional assumptions needed (unlike hypothesis tests).
  • OVERFITTING: Tree too deep memorizes training noise, flops on fresh data. Fixes: Early stopping (stop when node too few obs) or Pruning (grow full tree, cut unhelpful splits). Bottom-up pruning preferred (avoids throwing away good splits below bad one). Top-down pruning risky.
  • CART vs ID3: CART (Breiman 1984) = binary splits only, handles numeric+categorical, prunes by cost-complexity. ID3 (Quinlan 1986) = can do multi-way splits, expanded into C4.5. Classification tree = categorical target (attack/normal). Regression tree = numeric target (predicted values).
  • SECURITY USE: Trees easy to explain to non-technical people (huge for security reporting). Works with big data, both numeric and categorical.
W8 - Cloud Security, Parametric vs Non-Parametric & Sign Test
  • CLOUD: IaaS (you manage OS/apps/data - AWS EC2), PaaS (you manage apps/data only - Heroku), SaaS (just use it - Office 365). Cloud security data: audit logs, access logs, API call logs, network flow logs.
  • CLOUD VIZ CHALLENGES: Scale (enormous volume from distributed resources), Multi-tenancy (shared infra complicates attribution), Ephemeral infrastructure (resources spin up/down rapidly, persistent monitoring hard).
  • CROWDSTRIKE 2025: Avg breakout time 48 min (fastest 51 sec). Vishing up 442%. Initial access via vulns 52%. Access broker ads up 50%. China-nexus activity up 150%. FAMOUS CHOLLIMA (DPRK) using GenAI for fake IT worker campaigns.
  • PARAMETRIC: Assume normal distribution, test MEAN, use means/SDs. Z-test, t-test. More power when assumptions hold. NOT robust to outliers. Use when bell-shaped, large n, continuous ratio/interval.
  • NON-PARAMETRIC: Distribution-free, test MEDIAN, use ranks/signs. Sign test. Robust to outliers. Slightly lower power but fewer assumptions. Use when skewed, ordinal, outliers, small n, non-normal. Still need continuous + at least ordinal. NOT "assumption-free" - just fewer assumptions.
  • SIGN TEST: Simplest non-parametric. Tests claim about MEDIAN (NOT mean). H0: M=m0. Step 1: For each Xi, record + if Xi-m0>0, - if negative. DISCARD ties (Xi=m0) and SHRINK n. Step 2: R = count of pluses. Step 3: Under H0, R ~ Binomial(n, 0.5) -- coin flip model. Too few or too many pluses (depending on tail) = reject H0.
  • SIGN TEST INTUITION: If true median is m0, about half should be above and half below (50/50 coin flip). Way off from half = median probably not m0.
  • DECISION RULE: Bell-shaped, large n, continuous -> parametric (more power). Skewed, ordinal, outliers, small n -> non-parametric. Security data (login times, packet sizes, dwell times) is often skewed with heavy tails -> non-parametric preferred.
W10 - APTs, Kill Chain & Linear Regression
  • PERSISTENT THREATS: Ongoing, recurring attack vectors. Common: phishing, ransomware, DDoS, botnets, malware (viruses/trojans/worms), MITM, brute force, insider threats.
  • APT: Advanced (custom malware, zero-day exploits) + Persistent (months/years undetected, not deterred by failures) + Threat (data theft, service disruption, infrastructure damage). "Slow and low." State-sponsored or organized crime.
  • THREAT ACTORS: Cybercriminals (financial gain), State-sponsored (espionage/disruption), Hacktivists (political/social causes), Insiders (grievance/personal gain), Terrorists (fear/destruction), Competitors (business advantage).
  • 6 TIERS (Board, 2013): I-II ($10s, EXPLOIT known vulns, use others' tools), III-IV ($Millions, DISCOVER unknown vulns, develop own tools, target executives), V-VI ($Billions, CREATE vulns through supply chain, influence manufacturing, full spectrum cyber+military+intel). TRAP: V-VI CREATE, not just discover.
  • KILL CHAIN (7 steps): Recon -> Weaponize -> Deliver -> Exploit -> Install -> C2 -> Actions on Objectives. Break any link to stop attack. Defense works at every stage.
  • KASPERSKY 5-STAGE: Gain Access -> Establish Foothold -> Deepen Access -> Move Laterally -> Look, Learn, Remain. TRAP: Kill Chain has 7 steps, Kaspersky has 5 -- don't confuse.
  • CROWDSTRIKE NAMING: Bear=Russia, Chollima=DPRK, Kitten=Iran, Leopard=Pakistan, Panda=China, Buffalo=Vietnam, Crane=South Korea, Hawk=Syria, Jackal=Hacktivists. TRAP: Bear=Russia NOT China. Naming is NOT globally standardized (FireEye/Mandiant uses numbers: APT28, APT29).
  • LINEAR REGRESSION: Y=b0+b1X+e. Y=response/dependent (what you predict). X=predictor/independent. b0=intercept (Y when X=0). b1=slope (change in Y per 1-unit increase in X -- THE NUMBER YOU CARE ABOUT MOST). e=error term (random scatter, assumed to average zero). "Simple"=one predictor X. "Linear"=straight line.
  • SLOPE: Positive = X and Y rise together. Negative = one rises, other falls. Near-zero = X tells little about Y. Security example: regress failed logins on hour -- slope of 5 means each hour = 5 more failed logins.
  • LEAST SQUARES: Finds best line by minimizing sum of SQUARED residuals (vertical distances from points to line). Why square? Prevents positive and negative errors from canceling. Residual = prediction error for specific point.
  • GAUSS-MARKOV: Least squares = BLUE (Best Linear Unbiased Estimator). Best straight-line fit without extra assumptions. Normality needed ONLY for confidence intervals and hypothesis tests on slope/intercept -- NOT for fitting the line itself.
  • ALWAYS SCATTER PLOT FIRST to check linearity before fitting regression. Check for outliers, patterns, non-linearity.
W11 - Collaboration & Logistic Regression
  • COLLABORATION: Two or more people/orgs working toward common goal. Characteristics: shared goals, mutual respect, open communication, shared decision-making, shared accountability.
  • KEY FEATURES: Sharing/access controls (view/comment/edit per user), Real-time collaboration (like Google Docs), Commenting/annotation on data points, Version control (track changes/revert), Interactive dashboards (filters/drill-down), Data integration/sync, Security (encryption/secure auth), Mobile access, Ecosystem integration (Excel critical for finance), Alerts/notifications, Training/support.
  • POWER BI: Publish Excel to workspace, create interactive reports/dashboards, embed live in PowerPoint (interactive in both edit AND slideshow modes), mobile apps with annotation, sharing permissions (org/existing/specific people).
  • TABLEAU: Publish to Tableau Cloud, alerting (subscriptions, metrics tracking, threshold alerts), commenting on visualizations, mobile-responsive layouts. KEY DIFF: Power BI = Excel/PowerPoint embedding. Tableau = threshold alerting.
  • LOGISTIC REGRESSION: Predicts probability (0-1) of binary yes/no outcome using S-shaped SIGMOID curve. Always stays within [0,1] unlike linear regression. Formula: P(Y=1) = 1/(1+e^-(b0+b1X)). Use for binary outcomes (attack/normal, malware/benign). NOT for continuous Y (use linear).
  • WHY NOT LINEAR FOR YES/NO? Straight line shoots below 0 or above 1 -- nonsensical for probability. Logistic S-curve stays in valid [0,1] range.
  • CHALLENGER EXAMPLE: Logistic regression predicted O-ring failure probability from launch temp. At 53F = 0.86 (very risky). At 81F = 0.05 (safe). Launched at 36F. Warning was ignored -- catastrophic result.
  • CUTOFF (THRESHOLD): Probability above which you label "yes." Default 0.5 but it's a dial you can turn. Lower cutoff (0.2) = catch more true positives BUT more false alarms. Higher cutoff (0.7) = fewer false alarms BUT miss more real cases. NO FREE LUNCH. In security, lower cutoff preferred -- missing real attack (FN) is worse than false alarm (FP).
  • CONFUSION MATRIX: 2x2 table: TP (predicted attack, WAS attack), TN (predicted normal, WAS normal), FP (predicted attack, was NORMAL = false alarm = Type I), FN (predicted normal, was ATTACK = missed detection = Type II). Diagonal = correct. Off-diagonal = errors.
  • SENSITIVITY (TPR) = TP/(TP+FN) "of real attacks, how many caught?" SPECIFICITY (TNR) = TN/(TN+FP) "of normal, how many correctly cleared?" ACCURACY = (TP+TN)/total. ERROR RATE = (FP+FN)/total.
  • ACCURACY TRAP: 99% normal data -> lazy model predicts all normal -> 99% accuracy BUT 0% sensitivity. Catches ZERO attacks. USELESS. Security cares about sensitivity far more than raw accuracy.
  • ROC CURVE: Plots sensitivity (y) vs 1-specificity (x) across ALL cutoff values. Perfect classifier hugs top-left corner. Useless classifier sits on diagonal (coin flip).
  • AUC: 0.5=coin flip (BAD/useless), 0.7-0.8=acceptable, 0.8-0.9=good, 0.9-1.0=excellent, 1.0=perfect. Single number [0.5,1.0] summarizing classifier quality. Higher=better.
W12 - ANOVA & Non-Parametric Alternatives
  • ANOVA: Extends t-test from 2 groups to 3+ groups. H0: mu1=mu2=...=muk (all means equal). H1: at least one differs. Controls false positive rate (multiple t-tests inflate Type I error -- 3 groups at alpha=0.05 inflates to ~14%).
  • F-STATISTIC: F = MSB/MSW = Between-group variance / Within-group variance = Signal/Noise. Large F -> reject H0 (groups differ). TRAP: F = between/within, NOT within/between.
  • MSB (Between): How different group means are from grand mean (signal/effect). MSW (Within): Spread of observations inside each group (noise/random variation).
  • ASSUMPTIONS: Independence (each measurement from different unit), Normality (approx normal within each group -- Shapiro-Wilk test or Q-Q plots), Equal variance/homoscedasticity (Levene's test or Bartlett's test).
  • POST-HOC: Tukey HSD after significant F to find WHICH groups differ. "ANOVA says someone is different. Tukey says WHO is different." Pairwise comparisons with family-wise error control.
  • SOC EXAMPLE: 3 SOC teams, 8 incidents each. Means: A=52.5, B=31.8, C=68.5 min. Grand mean=50.9. F=32.75, df=(2,21), p=0.000. F_crit(0.05,2,21)=3.47. Since 32.75>>3.47, reject H0. All pairwise Tukey p<0.01.
  • MINITAB STEPS: 1) Reshape: Stat>Stack>Rows. 2) Normality: Stat>Basic Stats>Graph Summary. 3) Equal variance: Stat>ANOVA>Test for Equal Variances. 4) Run: Stat>ANOVA>One-Way.
  • TWO-WAY ANOVA: 2 factors, tests THREE things: Main effect A, Main effect B, and INTERACTION (A*B). Interaction = MOST IMPORTANT, read FIRST in output. Interaction means effect of one factor DEPENDS on level of other. Non-parallel lines in interaction plot = interaction exists. Parallel lines = no interaction.
  • SECURITY 2-WAY EXAMPLE: Factor A: Training type (Online/In-Person). Factor B: Experience (Junior/Senior). Response: % threats detected. Interaction p=0.004 (significant). In-person helps juniors MORE than seniors. Cannot say "in-person is better" without specifying experience level.
  • MANOVA: Multiple correlated response variables simultaneously. Why not multiple ANOVAs? Inflates Type I error, ignores correlations between responses, misses differences in COMBINATIONS. H0: mean VECTOR equal across groups. Test stat: Wilks' Lambda. Extra assumptions: multivariate normality, homogeneity of covariance matrices (Box's M test), no severe multicollinearity (r>0.9 problematic), n per group > number of response variables.
  • MANOVA EXAMPLE: 3 SOC teams, 3 metrics (detection rate, FP rate, MTTR). Wilks' Lambda=0.312, F(6,72)=8.94, p<0.001. Follow-up: detection p=0.003 (sig), FP rate p=0.041 (sig), MTTR p=0.218 (not sig). MANOVA reveals combined profile differs even though individual MTTR is not significant alone.
  • NON-PARAMETRIC ALTERNATIVES: Kruskal-Wallis (replaces one-way ANOVA, ranks-based), Friedman (replaces two-way/repeated measures ANOVA). Use when non-normal: zero-inflated counts, skewed response times, ordinal severity (CVSS), heavy-tailed distributions (power-law/Pareto), small n (breach investigations n=5-15).
  • WHEN ASSUMPTIONS FAIL: Normality fails -> Kruskal-Wallis. Unequal variances -> Welch's ANOVA. Blocked/repeated measures non-normal -> Friedman.

PARAMETRIC vs NON-PARAMETRIC DECISION TABLE
  • 1 SAMPLE: t-test (parametric, tests mean) vs Sign test (non-parametric, tests MEDIAN). TRAP: sign test = median NOT mean.
  • 2 GROUPS: 2-sample t-test vs Wilcoxon rank-sum.
  • 3+ GROUPS: ANOVA vs Kruskal-Wallis. TRAP: non-normal -> Kruskal-Wallis, NOT ANOVA.
  • BLOCKED/REPEATED: Two-way ANOVA vs Friedman test.
  • CORRELATION: Pearson r (parametric, linear, continuous) vs Spearman rho (non-parametric, monotonic, ordinal OK).
  • MULTIPLE RESPONSES: MANOVA (2+ correlated responses). No non-parametric direct equivalent -- transform or use permutation tests.
  • DECISION: Bell-shaped, large n, continuous -> parametric. Skewed, small n, ordinal, outliers, heavy tails -> non-parametric. Security data is almost NEVER bell-shaped.
CONFUSION MATRIX & CLASSIFICATION METRICS
  • TP: Predicted attack, WAS attack (correct catch). TN: Predicted normal, WAS normal (correct clear).
  • FP (Type I): Predicted attack, was NORMAL (false alarm -- annoying but not catastrophic). FN (Type II): Predicted normal, was ATTACK (missed detection -- DANGEROUS in security).
  • Sensitivity/Recall/TPR = TP/(TP+FN) -- "of all real attacks, how many caught?" THE metric security cares about most.
  • Specificity/TNR = TN/(TN+FP) -- "of all normal traffic, how many correctly identified?"
  • Accuracy = (TP+TN)/total. MISLEADING with imbalanced data. 99% normal -> lazy "all normal" model = 99% accuracy, 0% sensitivity. USELESS.
  • Cutoff tradeoff: Lower cutoff -> higher sensitivity (catch more) but lower specificity (more false alarms). Higher cutoff -> reverse. No free lunch. Security prefers low cutoff.
  • ROC/AUC: Plot sensitivity vs 1-specificity across all cutoffs. Hugs top-left = good. Diagonal = coin flip. AUC: 0.5=random (BAD), 0.7-0.8=fair, 0.8-0.9=good, >0.9=excellent, 1.0=perfect.
ANOVA FAMILY COMPARISON
  • t-test: 2 groups, 1 factor, 1 response. Compares two means.
  • One-Way ANOVA: 3+ groups, 1 factor, 1 response. F=MSB/MSW. Tukey post-hoc for pairwise. Assumptions: independence, normality, equal variance.
  • Two-Way ANOVA: 2 factors, 1 response. Tests main effects + INTERACTION (read FIRST). Non-parallel lines = interaction. Balanced design preferred.
  • Repeated Measures: 1+ factors, 1 response, same subjects measured multiple times.
  • MANOVA: 1+ factors, 2+ CORRELATED responses. Uses Wilks' Lambda. Extra assumptions: multivariate normality, homogeneous covariance (Box's M), no multicollinearity. Avoids inflated Type I from multiple ANOVAs.
  • NON-PARAMETRIC: Kruskal-Wallis (replaces 1-way ANOVA), Friedman (replaces 2-way/blocked). For non-normal security data.
  • WHY NOT MULTIPLE t-TESTS? 3 groups = 3 comparisons. Alpha inflates from 0.05 to ~14%. ANOVA controls family-wise error rate.
REGRESSION & CLASSIFICATION MODELS
  • LINEAR: Y=b0+b1X+e. Continuous Y. b1=slope=most important (unit change in X -> b1 change in Y). Least squares minimizes sum of squared residuals. Gauss-Markov = BLUE. Scatter plot FIRST. Normality only for CI/tests, not fitting.
  • LOGISTIC: Binary Y (0/1). Sigmoid curve P(Y=1)=1/(1+e^-(b0+b1X)). Always stays [0,1]. Cutoff tradeoff: lower = more catches + more false alarms. Challenger example: 0.86 failure prob at 53F.
  • DECISION TREE: Root/internal/leaf/branch. Recursive partitioning for purity. Overfitting -> pruning (bottom-up preferred). CART=binary splits, cost-complexity pruning. ID3=multi-way, info gain. No distributional assumptions. Classification (categorical) vs regression (numeric) tree.
  • WHEN TO USE: Continuous outcome -> linear regression. Binary outcome -> logistic regression. Non-linear/categorical splits, need explainability -> decision tree. Non-normal 3+ groups -> Kruskal-Wallis (not ANOVA).

HYPOTHESIS TESTING - POST-MIDTERM CONTEXT
  • SETUP: H0 has = sign. H1 has inequality. H1 decides WHERE rejection region. Alpha decides HOW BIG. Never "accept H0" -- "fail to reject."
  • ERRORS: Type I = alpha = false alarm (reject true H0). Type II = beta = missed detection. Power = 1-beta. In security, Type II usually WORSE (missed attack). Bigger samples reduce BOTH.
  • SIGN TEST: H0: M=m0. Count pluses. R~Binomial(n,0.5). Discard ties, shrink n. Non-parametric analog of t-test for median.
  • ANOVA H-TEST: H0: all group means equal. F=MSB/MSW. Large F = reject. Post-hoc Tukey for which groups differ.
  • SECURITY: H0 = "system normal." Type I = false alarm (wastes time). Type II = missed attack (catastrophic). Lower cutoff = catch more but more false alarms.
  • P-VALUE: P(data this extreme | H0 true). p reject. Two-sided: DOUBLE the one-tail probability. p=2*P(Z>=|z|). P-value is NOT P(H0 is true).

QUICK DECISION GUIDE
  • "Binary outcome model?" -> Logistic regression (sigmoid, [0,1]). "Continuous outcome model?" -> Linear regression (Y=b0+b1X+e).
  • "3+ group comparison, normal?" -> ANOVA. "3+ groups, NOT normal?" -> Kruskal-Wallis.
  • "Test median, non-parametric?" -> Sign test. R~Binomial(n,0.5). Discard ties.
  • "2 factors, check interaction?" -> Two-way ANOVA. Read interaction FIRST. Non-parallel lines = interaction.
  • "Multiple correlated responses?" -> MANOVA. Don't run separate ANOVAs (inflates Type I).
  • "IDS misses attack?" -> Type II (FN). "IDS false alert?" -> Type I (FP). Which worse in security? -> Type II.
  • "AUC=0.52?" -> Terrible (near random). "99% accuracy, 0% sensitivity?" -> Useless model, imbalanced data.
  • "Non-parallel interaction plot?" -> Interaction exists, interpret BEFORE main effects.
  • "APT tier that CREATES vulns?" -> V-VI ($Bs, supply chain). "Uses others' tools?" -> I-II ($10s).
  • "Strongest Gestalt principle?" -> Enclosure. "Tree too deep?" -> Overfitting. Fix: prune bottom-up.
  • "Avg breakout time (CS 2025)?" -> 48 minutes (fastest 51 sec). "Bear = which country?" -> Russia.
  • "Power BI vs Tableau strength?" -> Power BI = PowerPoint embedding. Tableau = threshold alerting.
KEY FORMULAS - POST-MIDTERM
  • LINEAR REG: Y=b0+b1X+e. b1=slope (most important). Least squares minimizes sum(residual^2). Gauss-Markov: BLUE.
  • LOGISTIC: P(Y=1) = 1/(1+e^-(b0+b1X)). Sigmoid [0,1]. Output is probability, not class.
  • SENSITIVITY: TP/(TP+FN). SPECIFICITY: TN/(TN+FP). ACCURACY: (TP+TN)/total. ERROR RATE: (FP+FN)/total.
  • ANOVA: F=MSB/MSW. MSB=SS_between/df_between. MSW=SS_within/df_within. df_between=k-1. df_within=N-k. Large F -> reject H0.
  • SIGN TEST: R = count of pluses. Under H0: R ~ Binomial(n, 0.5). n excludes ties. Compare to binomial table.
  • MANOVA: Wilks' Lambda. H0: mean vectors equal across groups. Box's M for covariance homogeneity.
  • DECISION TREE: Purity gain at each split. CART: cost-complexity pruning parameter alpha. Information gain (ID3/C4.5).
