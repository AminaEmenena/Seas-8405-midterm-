W7 - Log Analysis, Gestalt Principles & Decision Trees
  • LOG: Chronological record of events from IT components (OS, apps, network devices, security tools). Entry contains: timestamp, event type, source, user/IP/severity.
  • LOG ENTRY EXAMPLE: 2024-03-15 14:23:01 | WARNING | AuthService | Failed login attempt for user admin from IP 192.168.1.105 | Attempt 3 of 5
  • LOG TYPES (7): System (OS/hardware), Application (app errors/crashes), Network (routers/firewalls/IDS), Security (SIEM/IDS - CRUCIAL for IR), Audit (compliance/forensics), Web Server (HTTP requests/responses), Database (queries/SQL injection).
  • SYSTEM LOGS: Detect unauthorized access, system failures, hardware issues, software crashes. Generated by OS kernel and system services.
  • APPLICATION LOGS: Detect unusual user behavior, app vulnerabilities, performance degradation. Each app generates its own log format.
  • NETWORK LOGS: Record data transmissions, connections from routers/switches/firewalls/IDS/IPS. Useful for detecting data exfiltration and lateral movement.
  • SECURITY LOGS: From antivirus, IDS, SIEM. Crucial for incident response and forensics. Aggregated view of security events across the enterprise.
  • AUDIT LOGS: Track user logins, file access, config changes. Required for regulatory compliance (SOX, HIPAA, PCI-DSS). Immutable trail for forensic investigations.
  • WEB SERVER LOGS: Identify web app attacks (SQL injection, XSS), unauthorized access attempts, server errors (4xx/5xx). Apache/Nginx access and error logs.
  • DATABASE LOGS: Track data modifications, schema changes, detect SQL injection attempts. Transaction logs for rollback and recovery.
  • LOG PRACTICES: Centralize to SIEM, set retention (3-7yr+), protect integrity (tamper-proof), normalize formats, correlate across sources, alert on anomalies, log rotation. Viz: timeline charts, heat maps, network graphs.
  • GESTALT PRINCIPLES: Proximity (near=grouped), Similarity (alike=grouped), Closure (brain completes shapes), Continuity (smooth paths), Enclosure (STRONGEST - borders/shading), Connection (linked by lines, stronger than proximity but weaker than enclosure).
  • PROXIMITY DETAIL: Horizontal spacing drives left-to-right scanning. Vertical spacing drives top-to-bottom scanning. Use whitespace intentionally to create logical groups.
  • SIMILARITY DETAIL: Use same color for related data across DIFFERENT charts on a dashboard. Consistent encoding helps users link information across views.
  • ENCLOSURE DETAIL: Use borders, background shading, or color fields to create the STRONGEST visual grouping. Overrides all other Gestalt principles.
  • CONNECTION DETAIL: Use lines/arrows for flowcharts, network diagrams, process flows. Stronger than proximity but weaker than enclosure.
  • STRENGTH ORDER: Enclosure > Connection > Proximity/Similarity. Use enclosure for critical groupings.
  • DECISION TREES: Flowchart classifier. Root node (top, no parent, first question), Internal nodes (splits/questions), Branches (answers/paths), Leaf nodes (bottom, no children, final class label). Depth = longest path root to leaf. Handles BOTH numeric and categorical predictors.
  • TREE TYPES: Classification tree = categorical target (spam/not-spam, attack/normal). Regression tree = numeric target (predicted response time, predicted loss amount). Same splitting logic, different leaf output.
  • HOW TREES BUILD: Recursive partitioning -- at each node pick split that maximizes purity gain (reduces impurity most). 100% one class = pure leaf. No distributional assumptions needed (unlike hypothesis tests). Works with missing data, mixed types.
  • TREE ADVANTAGE: No normality assumption needed -- huge advantage for security data which is almost never normal. Handles mixed types, missing data, outliers gracefully.
  • OVERFITTING: Tree too deep memorizes training noise, flops on fresh data. Fixes: Early stopping (stop when node too few obs) or Pruning (grow full tree, cut unhelpful splits). Bottom-up pruning preferred (avoids throwing away good splits below bad one). Top-down pruning risky.
  • PRUNING DETAIL: Cost-complexity pruning in CART uses alpha parameter to balance tree size vs accuracy. Higher alpha = more aggressive pruning = simpler tree.
  • CART vs ID3 vs C4.5: CART (Breiman 1984) = binary splits only, handles numeric+categorical, prunes by cost-complexity. ID3 (Quinlan 1986) = can do multi-way splits, uses information gain. C4.5 = improved ID3, uses gain ratio (normalizes for number of splits), handles continuous attributes and missing values.
  • INFO GAIN vs GAIN RATIO: Information gain (ID3) measures reduction in entropy after split. Gain ratio (C4.5) normalizes for number of branches -- prevents bias toward attributes with many values.
  • SECURITY USE: Trees easy to explain to non-technical people (huge for security reporting to executives/board). Flowchart format is universally understood. Works with big data, both numeric and categorical. No need to justify distributional assumptions to auditors.
W8 - Cloud Security, Parametric vs Non-Parametric & Sign Test
  • CLOUD MODELS: IaaS (you manage OS/apps/data - AWS EC2), PaaS (you manage apps/data only - Heroku), SaaS (just use it - Office 365). Shared responsibility model: provider secures infrastructure, customer secures what they put on it. More managed = less customer responsibility.
  • SHARED RESPONSIBILITY: IaaS=customer manages OS/patching/firewall. PaaS=customer manages app/data. SaaS=customer manages user access/data classification. More managed=less customer responsibility.
  • CLOUD TOOLS: CloudWatch (AWS metrics), GuardDuty (threat detection), CloudTrail (API logging), Defender/Sentinel (Azure), VPC Flow Logs. CHALLENGES: Scale, multi-tenancy, ephemeral infra, geographic distribution.
  • CROWDSTRIKE 2025: Avg breakout time 48 min (fastest 51 sec). Vishing up 442%. Initial access via vulns 52%. Access broker ads up 50%. China-nexus activity up 150%. FAMOUS CHOLLIMA (DPRK) using GenAI for fake IT worker campaigns.
  • PARAMETRIC: Assume normal distribution, test MEAN, use means/SDs. Examples: Z-test (known sigma, large n), t-test (unknown sigma, small n). More power when assumptions hold. NOT robust to outliers. Use when bell-shaped, large n, continuous ratio/interval data.
  • NON-PARAMETRIC: Distribution-free, test MEDIAN, use ranks/signs. Sign test, Wilcoxon, Kruskal-Wallis. Robust to outliers. Slightly lower power but fewer assumptions. Use when skewed, ordinal, outliers, small n, non-normal. Still need continuous + at least ordinal scale. NOT "assumption-free" -- just fewer assumptions.
  • KEY INSIGHT: Non-parametric tests ask the SAME questions as parametric tests but use ranks/signs instead of raw values. Sign test is non-parametric analog of one-sample t-test. Kruskal-Wallis is non-parametric analog of one-way ANOVA.
  • SIGN TEST: Simplest non-parametric. Tests claim about MEDIAN (NOT mean). H0: M=m0. Step 1: State H0/H1. Step 2: Set alpha. Step 3: For each Xi, compute sign of (Xi-m0). Record + if positive, - if negative. DISCARD ties (Xi=m0) and SHRINK n. Step 4: R = count of pluses. Step 5: Under H0, R ~ Binomial(n, 0.5) -- coin flip model. Step 6: Compare R to critical value. Decide.
  • SIGN TEST WORKED: Claim median response=30min. Data: 25,18,35,42,30,28,45,22,31,27. Remove tie (30). n=9. Pluses (>30): 35,42,45,31=4. Under H0: R~Bin(9,0.5). Is 4 extreme? Compare to binomial table. Not extreme enough to reject at alpha=0.05.
  • SIGN TEST TAILS: Left-sided: H1: M<m0 (few pluses = reject, most values below claimed median). Right-sided: H1: M>m0 (many pluses = reject, most values above). Two-sided: H1: M!=m0 (too few OR too many pluses = reject).
  • SIGN TEST INTUITION: If true median is m0, about half should be above and half below (50/50 coin flip). Way off from half = median probably not m0.
  • PARAMETRIC vs NON-PARAMETRIC: Parametric = more powerful IF assumptions met. Non-parametric = safer choice when unsure about distribution. Trade-off: power vs robustness.
  • SECURITY DATA NON-NORMAL EXAMPLES: Login attempt counts (zero-inflated), incident response times (right-skewed), CVSS scores (ordinal, not continuous), financial losses from breaches (heavy-tailed/Pareto distribution).
  • CLOUD SECURITY ARCH: Logs flow from cloud resources -> cloud-native SIEM -> dashboards -> alerts. Centralized visibility across multi-cloud environments.
  • AWS SECURITY STACK: CloudWatch (metrics) + CloudTrail (API audit) + GuardDuty (threat detection) + Security Hub (aggregation). Layered defense-in-depth approach.
  • AZURE SECURITY STACK: Defender (threat protection) + Sentinel (SIEM/SOAR) + Activity Log (audit trail) + Azure Monitor (telemetry). Integrates with Microsoft 365.
  • CROWDSTRIKE DETAIL: Access broker ads up 50%. GenAI in social engineering attacks increasing. 52% of initial access through vulnerability exploitation. China-nexus activity up 150%.
  • SECURITY RELEVANCE: Login times, packet sizes, dwell times, incident response durations have heavy tails and skewed distributions. Can't assume normality for this data. Non-parametric tests are almost always more appropriate for security analytics.
  • DECISION RULE: Bell-shaped, large n, continuous -> parametric (more power). Skewed, ordinal, outliers, small n -> non-parametric. When in doubt, non-parametric is safer (valid even if data IS normal, just slightly less powerful).
W10 - APTs, Kill Chain & Linear Regression
  • PERSISTENT THREATS: Ongoing, recurring attack vectors. Common: phishing, ransomware, DDoS, botnets, malware (viruses/trojans/worms), MITM, brute force, insider threats.
  • APT: Advanced (custom malware, zero-day exploits) + Persistent (months/years undetected, not deterred by failures) + Threat (data theft, service disruption, infrastructure damage). "Slow and low." State-sponsored or organized crime.
  • APT DURATION: Can last months to YEARS. SolarWinds APT lasted 14+ months before detection. Persistence is the defining characteristic.
  • THREAT ACTORS: Cybercriminals (financial gain), State-sponsored (espionage/disruption), Hacktivists (political/social causes), Insiders (grievance/personal gain), Terrorists (fear/destruction), Competitors (business advantage).
  • TIER I EXAMPLE: Script kiddies using Metasploit, downloaded exploit kits, no custom development. Minimal skill, pre-built tools only.
  • TIER II EXAMPLE: Modify existing exploits, develop simple tools, target specific organizations. Limited to published CVEs but adapt them.
  • TIER III EXAMPLE: Discover zero-days, install kernel rootkits, target corporate executives and key government officials, sell stolen data to criminal elements.
  • TIER IV EXAMPLE: Organized crime/state actors with teams of specialists, well-funded research labs ($Ms). Sustained campaigns with custom toolkits.
  • TIER V EXAMPLE: State actors who influence commercial products DURING manufacturing to create backdoors. Supply chain compromise BEFORE products ship. Budget $Bs.
  • TIER VI EXAMPLE: Nation-states executing full spectrum operations combining cyber + military + intelligence. CREATE vulnerabilities upstream. Elite capability.
  • TIER PROGRESSION: I-II EXPLOIT known vulns ($10s) -> III-IV DISCOVER unknown vulns ($Ms) -> V-VI CREATE vulns through supply chain ($Bs). TRAP: V-VI CREATE, not just discover.
  • KILL CHAIN (7 steps): Recon (research target) -> Weaponize (build payload) -> Deliver (phishing/USB/web) -> Exploit (trigger vulnerability) -> Install (establish persistence) -> C2 (command and control channel) -> Actions on Objectives (exfil/destroy). Break ANY link to stop the attack. Defense works at every stage.
  • KILL CHAIN DEFENSE: You only need to break ONE link to stop the attack. Early detection (recon/delivery phase) is cheapest. Later detection (C2/actions) is most expensive and damaging.
  • KASPERSKY 5-STAGE: Gain Access -> Establish Foothold -> Deepen Access -> Move Laterally -> Look, Learn, Remain. TRAP: Kill Chain has 7 steps, Kaspersky has 5 -- don't confuse.
  • APT DETECTION: Continuous monitoring + rapid incident response essential. Look for: unusual outbound traffic, beaconing patterns (regular C2 check-ins), lateral movement, credential harvesting, data staging before exfil. APT groups NOT globally standardized naming: Mandiant uses numbers (APT28, APT29), CrowdStrike uses animals (Fancy Bear, Cozy Bear).
  • CROWDSTRIKE NAMING: Bear=Russia, Chollima=DPRK, Kitten=Iran, Leopard=Pakistan, Panda=China, Buffalo=Vietnam, Crane=South Korea, Hawk=Syria, Jackal=Hacktivists, Spider=eCrime, Ocelot=Colombia.
  • LINEAR REGRESSION: Y=b0+b1X+e. Y=response/dependent (what you predict). X=predictor/independent. b0=intercept (Y when X=0). b1=slope (change in Y per 1-unit increase in X -- THE NUMBER YOU CARE ABOUT MOST). e=error term (random scatter, assumed to average zero). Simple=one predictor. Multiple=more than one predictor. Linear=straight line relationship.
  • REGRESSION ASSUMPTIONS: Y values independent. Errors have mean zero and constant variance (sigma^2). For CI and hypothesis tests: errors must be normally distributed.
  • SLOPE INTERPRETATION: Positive slope = X and Y rise together. Negative slope = one rises, other falls. Near-zero slope = X tells little about Y. Security example: regress failed logins on hour -- slope of 5 means each additional hour = 5 more failed logins. Slope of -3 for patching = each patch reduces incidents by 3.
  • RESIDUAL: Vertical distance from observed point to the fitted line. Residual = actual Y - predicted Y. Positive residual = point above line. Negative = below. Sum of residuals = 0 by design. Pattern in residuals = model is wrong.
  • RESIDUAL ANALYSIS: Plot residuals vs fitted values. Pattern = model problem (nonlinearity, heteroscedasticity). Random scatter = good fit. Fan shape = non-constant variance.
  • R-SQUARED: Proportion of variance in Y explained by X. R^2=0 means X explains nothing. R^2=1 means perfect fit. In security: R^2=0.6 means 60% of variation in incidents explained by predictor. Remaining 40% is unexplained.
  • MULTIPLE REGRESSION: Y = b0 + b1*X1 + b2*X2 + ... + e. Multiple predictors. Each slope = effect of that X holding others constant (partial effect).
  • REGRESSION SECURITY EXAMPLES: Predict number of incidents from patch age. Predict response time from team size. Predict breach cost from time-to-detection. Predict malware volume from phishing campaign frequency.
  • LEAST SQUARES: Finds best line by minimizing sum of SQUARED residuals. Why square? Prevents positive and negative errors from canceling. Penalizes large errors more than small ones.
  • GAUSS-MARKOV: Least squares = BLUE (Best Linear Unbiased Estimator). Best straight-line fit without extra assumptions. Normality needed ONLY for confidence intervals and hypothesis tests on slope/intercept -- NOT for fitting the line itself.
  • ALWAYS CHECK: Is the relationship actually linear? Scatter plot FIRST. Non-linear data with linear fit = misleading conclusions. Check for outliers, patterns, curvature, clusters.
W11 - Collaboration Tools & Logistic Regression
  • COLLABORATION: Shared goals, open communication, shared accountability. Features: access controls, real-time editing, version control, interactive dashboards, alerts, mobile access.
  • POWER BI: Excel/PowerPoint embedding (interactive in edit AND slideshow), sharing permissions. TABLEAU: Threshold alerts, subscriptions (scheduled email). KEY DIFF: Power BI=PowerPoint. Tableau=alerting+subscriptions.
  • LOGISTIC REGRESSION: Predicts probability (0-1) of binary yes/no outcome using S-shaped SIGMOID curve. Always stays within [0,1] unlike linear regression. Formula: P(Y=1) = 1/(1+e^-(b0+b1X)). Use for binary outcomes (attack/normal, malware/benign, fraud/legit). NOT for continuous Y.
  • LOG-ODDS (LOGIT): ln(P/(1-P)) = b0 + b1*X. The logistic regression is actually LINEAR in log-odds. The sigmoid is just the inverse transformation back to probability.
  • ODDS RATIO: e^b1 = multiplicative change in odds for 1-unit increase in X. If e^b1=2.5, odds of attack are 2.5x higher per unit increase in X. Key interpretation tool.
  • WHY NOT LINEAR FOR YES/NO? Straight line shoots below 0 or above 1 -- nonsensical for probability. You can't have -0.3 probability of attack. Logistic S-curve stays in valid [0,1] range naturally.
  • SIGMOID SHAPE: Flattens near 0 at one end, flattens near 1 at other end, smooth S-shaped transition in middle. Small changes in X near the center produce big changes in probability. Changes at extremes barely move the probability.
  • CHALLENGER EXAMPLE: Logistic regression predicted O-ring failure probability from launch temp. At 53F = 0.86 (very risky). At 81F = 0.05 (safe). Launched at 36F (even colder). Warning was ignored -- catastrophic result. The model worked; the decision-making failed.
  • CUTOFF IS A DIAL: Not a fixed setting. Default 0.5 but adjustable. Lower cutoff (0.20) = catch more true positives BUT more false alarms. Higher cutoff (0.70) = fewer false alarms BUT miss more real cases. NO FREE LUNCH.
  • O-RING CUTOFF EXAMPLE: At cutoff 0.70 they got zero class-0 errors but 0.57 class-1 error rate (missed 57% of real failures). At cutoff 0.20 they caught more real failures but class-0 errors jumped. When missing a real failure is CATASTROPHIC, use LOWER cutoff -- accept more false alarms to avoid deadly misses.
  • CONFUSION MATRIX: 2x2 table: TP (predicted attack, WAS attack), TN (predicted normal, WAS normal). FP = flagged something fine = Type I = false alarm (annoying but not catastrophic). FN = missed something real = Type II = dangerous miss (catastrophic in security). Diagonal = correct predictions. Off-diagonal = errors. Point is to see WHICH WAY you're wrong.
  • SENSITIVITY (TPR) = TP/(TP+FN) "of real attacks, how many caught?" SPECIFICITY (TNR) = TN/(TN+FP) "of normal, how many correctly cleared?" ACCURACY = (TP+TN)/total. ERROR RATE = (FP+FN)/total.
  • CONFUSION MATRIX WORKED: 100 network connections. Model predicts: 85 TN, 5 FP, 3 FN, 7 TP. Sensitivity=7/(7+3)=70%. Specificity=85/(85+5)=94%. Accuracy=(85+7)/100=92%. But we MISSED 3 real attacks (FN=3). High accuracy masks dangerous misses.
  • WHY SECURITY PREFERS HIGH SENSITIVITY: Missing a real attack (FN) can cost millions. False alarms (FP) are just annoying. Lower the cutoff to catch more attacks even at cost of more false alarms.
  • ACCURACY TRAP: 99% normal data -> lazy model predicts all normal -> 99% accuracy BUT 0% sensitivity. Catches ZERO attacks. USELESS. Security cares about sensitivity far more than raw accuracy.
  • ROC CURVE: Plots sensitivity (y) vs 1-specificity (x) across ALL cutoff values. Each point on curve = one cutoff setting. Perfect classifier hugs top-left corner (shoots up y-axis then across). Useless classifier sits on diagonal (coin flip).
  • AUC INTERPRETATION: 0.5=random (BAD, no better than guessing). 0.6-0.7=poor. 0.7-0.8=fair (acceptable for initial triage). 0.8-0.9=good (production-ready). 0.9-1.0=excellent (suspicious -- check for data leakage). Single number summarizing classifier quality.
  • COLLABORATION TOOLS: Power BI = Microsoft ecosystem (Excel/PowerPoint/Teams/SharePoint integration). Tableau = data-first philosophy (publish to Tableau Cloud/Server, Tableau Prep for ETL). Both support real-time dashboards, scheduled refreshes, role-based access.
  • POWER BI DAX: Formula language for calculated columns and measures. Similar to Excel formulas but works on data models. Used for KPIs and custom metrics.
  • TABLEAU CALCULATED FIELDS: Create new fields from existing data, similar to feature engineering. Drag-and-drop visual analytics with computed columns.
W12 - ANOVA Family & Non-Parametric Alternatives
  • PROGRESSION: 1 sample -> one-sample t-test. 2 samples -> two-sample t-test. 3+ samples -> ANOVA. Each step up handles more groups while controlling Type I error.
  • ANOVA: Extends t-test from 2 groups to 3+ groups. H0: mu1=mu2=...=muk (all means equal). H1: at least one differs. Controls false positive rate (multiple t-tests inflate Type I error -- 3 groups at alpha=0.05 inflates to ~14%).
  • F-STATISTIC: F = MSB/MSW = Between-group variance / Within-group variance = Signal/Noise. MSB = SS_Between/(k-1). MSW = SS_Within/(N-k). k = number of groups. N = total observations. Large F -> reject H0 (groups differ). TRAP: F = between/within, NOT within/between.
  • DECISION: Reject H0 if F > F_critical OR if p-value <= alpha. Both methods give same answer. F_critical comes from F-distribution table with df1=k-1, df2=N-k.
  • ASSUMPTIONS: Independence (each measurement from different unit), Normality (approx normal within each group -- check with Shapiro-Wilk test or Q-Q plots), Equal variance/homoscedasticity (check with Levene's test or Bartlett's test). Bartlett's is more powerful but more sensitive to non-normality.
  • MINITAB: Stat > ANOVA > One-Way. Read F-statistic, p-value, R-squared from output. R-squared = proportion of variance explained by groups. Also: Stat > Stack > Rows for reshaping, Stat > Basic Stats > Graph Summary for normality check, Stat > ANOVA > Test for Equal Variances.
  • POST-HOC: Tukey HSD after significant F to find WHICH groups differ. "ANOVA says someone is different. Tukey says WHO is different." Pairwise comparisons with family-wise error control.
  • SOC EXAMPLE DETAIL: 3 SOC teams, 8 incidents each. Team A=52.5min, B=31.8min, C=68.5min. Grand mean=50.9. SS_Between=5432, SS_Within=1741. MSB=5432/2=2716. MSW=1741/21=82.93. F=2716/82.93=32.75. p<0.001. df=(2,21).
  • F-CRITICAL VALUES: F(0.05,2,21)=3.47. F(0.01,2,21)=5.78. Our F=32.75 far exceeds both -- reject H0 at any reasonable alpha.
  • TUKEY RESULTS: Team B-A: diff=-20.75, p=0.000. Team C-A: diff=16.00, p=0.006. Team C-B: diff=36.75, p=0.000. All pairs significantly different. Team B fastest, C slowest.
  • BARTLETT'S TEST: Test for equal variances. p>0.05 = variances are equal (assumption met). In SOC example: Bartlett=1.98, p=0.372 (equal variances confirmed).
  • MINITAB STEPS: Stat > Stack > Rows (reshape data). Stat > Basic Stats > Graph Summary (check normality). Stat > ANOVA > One-Way (run test). Options > Tukey (post-hoc). Stat > ANOVA > Test for Equal Variances.
  • TWO-WAY ANOVA: 2 factors, tests THREE things: Main effect A, Main effect B, and INTERACTION (A*B). Asks THREE questions. Read INTERACTION FIRST in output -- it's the most important concept.
  • TWO-WAY OUTPUT READING: Look at interaction row FIRST. If p<alpha, the interaction is significant. Then interpret main effects WITH CAUTION because they are conditional on the other factor.
  • INTERACTION: Effect of one factor DEPENDS on other factor's level. Non-parallel lines in interaction plot = interaction EXISTS. Parallel lines = no interaction. If interaction significant: interpret main effects WITH CAUTION -- can't make blanket statements like "method A is better" without specifying the level of the other factor.
  • INTERACTION PLOT READING: Parallel lines = no interaction (factors act independently). Non-parallel = interaction (effect of one factor DEPENDS on the other). Crossing lines = strong interaction.
  • SECURITY 2-WAY DETAIL: Training type (Online/In-Person) x Experience (Junior/Senior). Response: % threats detected. Training F=12.3 p=0.001 (sig). Experience F=8.7 p=0.005 (sig). Interaction F=9.1 p=0.004 (sig). In-person helps Juniors MORE than Seniors. Cannot make blanket statement.
  • MANOVA: Multiple correlated response variables simultaneously. Why not multiple ANOVAs? 1) Inflates Type I error, 2) Ignores correlations between responses, 3) Can't detect differences in COMBINATIONS of outcomes that individual tests miss.
  • MANOVA: H0: mean VECTOR equal. Wilks' Lambda (smaller=more evidence against H0). Assumptions: multivariate normality, covariance homogeneity (Box's M), no multicollinearity (r>0.9 bad), n per group > number of responses. Reveals combined profile differences individual tests miss.
  • MANOVA OUTPUT: Wilks' Lambda (closer to 0 = more difference between groups). F-statistic. df. p-value. If significant: follow up with individual ANOVAs per response variable.
  • MANOVA vs MULTIPLE ANOVAs: MANOVA controls family-wise Type I error. Accounts for correlations between responses. Can detect differences that individual ANOVAs miss (differences in COMBINATIONS of variables).
  • WHEN TO USE WHICH: 1 response + 2 groups = t-test. 1 response + 3+ groups = ANOVA. 2+ responses + 2+ groups = MANOVA. Non-normal = Kruskal-Wallis/Friedman. Blocked = Repeated Measures or Friedman.
  • NON-PARAMETRIC ALTERNATIVES: Kruskal-Wallis (replaces one-way ANOVA, ranks-based), Friedman (replaces two-way/repeated measures ANOVA). Use when non-normal.
  • SECURITY DATA NON-NORMAL REASONS: Zero-inflated counts (most days 0 incidents), skewed response times (few take 10x longer), ordinal severity (CVSS 0-10), heavy tails (power-law losses), small samples (breach investigations n=5-15), categorical variables (severity levels). Almost NEVER bell-shaped.
  • WHEN ASSUMPTIONS FAIL: Normality fails -> Kruskal-Wallis. Unequal variances -> Welch's ANOVA. Blocked/repeated measures non-normal -> Friedman.
W13 - Course Recap, Data Pipeline & Integration
  • VIZ HISTORY: John Snow 1849 cholera map -- mapped deaths to trace outbreak to contaminated water pump. Original security data visualization.
  • FULL DATA PIPELINE: Sources (logs, auth events, network flow) -> Storage (NoSQL, time-series DBs) -> Exploration (Step Zero, df.describe()) -> Preprocessing (GIGO, cleaning, imputation -- garbage in = garbage out) -> Feature Engineering (secret sauce -- creating useful variables from raw data) -> Visualization (charts, dashboards) -> Analysis (statistical tests, ML models) -> Action (incident response, policy changes).
  • SPLUNK PIPELINE: Raw Data (logs ingested) -> Searches (SPL queries retrieve from indexes) -> Table (data model for consumption) -> Report (aggregation/pivot of search results) -> Dashboard (putting it all together).
  • SPL COMMANDS: eval (build new fields, like Excel formula columns), stats (count, avg, sum, min, max grouped by fields), search, where, table, timechart, rex (regex extraction). Each command pipes into the next with | character.
  • SOURCE TYPE: Arbitrary categorization of events -- many sources across hosts can share same type. Determines how Splunk parses and indexes data.
  • TRANSFORM: Config file on Splunk server defining field transformations and lookups. PROPS.CONF: Connects Source Type to transformation. Handles line breaking, timestamp recognition, field extraction.
  • LANL DATASET: Los Alamos National Laboratory. Windows-based auth events from individual computers AND centralized AD domain controllers, process start/stop events, DNS lookups from internal servers, network flow data from key routers, red team events over 58 days. 12GB, 1.6 BILLION events, 12,425 users, 17,684 computers.
  • CIC DATASET: Canadian Institute for Cybersecurity. Bot detection dataset (CICRealBot.csv). Used with Weka in HW8. Labeled network traffic for ML classification.
  • WEKA WORKFLOW: Download tool -> Explorer -> Open file (CSV->ARFF conversion) -> Preprocess tab -> Visualize tab (matrix plot, Label column selected) -> Classify tab (decision stump as baseline). Java-based, GUI-friendly.
  • SECURITY DOMAINS COVERED: Endpoints (any device on network), Users (human+non-human, auth/access logs), Code (Von Neumann CPU+Memory+I/O, separation of instructions+data, CI/CD pipeline), Logs (7 types from W7), APTs (6 tiers, kill chain from W10).
  • STATISTICAL METHODS COVERED: Descriptive (mean/median/mode/SD/IQR). Inferential (Z-test, t-test, hypothesis testing). Predictive (linear regression for continuous, logistic regression for binary, decision trees for both). Comparison (ANOVA for means, MANOVA for multiple outcomes, Kruskal-Wallis for non-normal).
  • DATA PIPELINE END-TO-END: Sources (logs, auth, network) -> Storage (SQL/NoSQL/HDFS/cloud) -> Exploration (Step Zero, df.describe()) -> Preprocessing (cleaning, imputation, GIGO) -> Feature Engineering (secret sauce) -> Visualization (charts, dashboards) -> Statistical Analysis -> Decision/Action.
  • KEY INTEGRATION: Visualization + statistics + security domain knowledge = effective security analytics. No single skill is sufficient. Must understand the data (domain), present it clearly (viz), and test claims rigorously (stats).
  • KEY COURSE THEMES: 1) Visualization must tell a story (not just show data). 2) Security data is almost never normal (use non-parametric when in doubt). 3) The outlier might BE the attack. 4) Garbage in = garbage out. 5) Tools are means to an end -- domain knowledge is what matters.
  • KEY PRINCIPLES: Garbage in garbage out. Step Zero = explore first. Scatter plot before regression. Sensitivity > accuracy in security. Interaction before main effects in 2-way ANOVA. Non-parallel lines = interaction. "Fail to reject" not "accept" H0. Non-parametric when in doubt.
PARAMETRIC vs NON-PARAMETRIC DECISION TABLE
  • 1 SAMPLE: t-test (parametric, tests mean) vs Sign test (non-parametric, tests MEDIAN). TRAP: sign test = median NOT mean.
  • 2 GROUPS: 2-sample t-test vs Wilcoxon rank-sum (Mann-Whitney U).
  • 3+ GROUPS: ANOVA vs Kruskal-Wallis. TRAP: non-normal -> Kruskal-Wallis, NOT ANOVA.
  • BLOCKED/REPEATED: Two-way ANOVA vs Friedman test.
  • CORRELATION: Pearson r (parametric, linear, continuous) vs Spearman rho (non-parametric, monotonic, ordinal OK).
  • MULTIPLE RESPONSES: MANOVA (2+ correlated responses). No non-parametric direct equivalent -- transform or use permutation tests.
  • DECISION: Bell-shaped, large n, continuous -> parametric. Skewed, small n, ordinal, outliers, heavy tails -> non-parametric. Security data is almost NEVER bell-shaped.
  • POWER TRADE-OFF: Parametric tests have MORE statistical power when assumptions hold. Non-parametric sacrifice ~5% power for robustness. When in doubt, non-parametric is the safer choice.
  • COMMON MISTAKE: Ordinal data (severity 1-5, risk Low/Med/High) is NOT interval. Cannot compute meaningful mean. Must use non-parametric (median, ranks).
  • SCALE TYPES: Nominal (categories, no order: attack type). Ordinal (ranked: severity Low/Med/High). Interval (equal spacing, no true zero: temperature). Ratio (true zero: response time in seconds). Higher scale = more tests available.
CONFUSION MATRIX QUICK REF
  • TP: Predicted attack, WAS attack. TN: Predicted normal, WAS normal. FP (Type I): False alarm. FN (Type II): Missed attack (DANGEROUS).
  • Sensitivity=TP/(TP+FN) "how many attacks caught?" Specificity=TN/(TN+FP). Accuracy=(TP+TN)/total (misleading if imbalanced). ROC: sensitivity vs 1-specificity. AUC: 0.5=bad, 0.8=good, 1.0=perfect.
  • WORKED EXAMPLE: 100 connections: 85 TN, 5 FP, 3 FN, 7 TP. Sensitivity=7/10=70%. Specificity=85/90=94%. Accuracy=92/100=92%. Missed 3 attacks despite 92% accuracy.
  • Cutoff: Lower=catch more+more false alarms. Higher=miss more. Security prefers low cutoff (catch attacks, accept false alarms).
  • PRECISION: TP/(TP+FP) = "of predicted attacks, how many were real?" F1 SCORE: 2*(Precision*Sensitivity)/(Precision+Sensitivity) = harmonic mean balancing both.
  • BASE RATE FALLACY: With rare events (attacks=0.1%), even a 99% accurate test produces mostly false alarms. Low prevalence makes precision drop dramatically. This is why accuracy alone is misleading in security.
ANOVA FAMILY COMPARISON
  • t-test: 2 groups. 1-Way ANOVA: 3+ groups, F=MSB/MSW, Tukey post-hoc. 2-Way: 2 factors, tests main effects+INTERACTION (read first). MANOVA: 2+ correlated responses, Wilks' Lambda, Box's M for covariance.
  • NON-PARAMETRIC: Kruskal-Wallis (replaces 1-way), Friedman (replaces 2-way/blocked). WHY NOT MULTIPLE t-TESTS? 3 groups at alpha=0.05 inflates to ~14%. ANOVA controls family-wise error.
  • ASSUMPTIONS CHECK: Normality: Shapiro-Wilk or Q-Q plot. Equal variance: Levene's (robust) or Bartlett's (more powerful). Independence: study design (no repeated measures unless accounted for).
  • EFFECT SIZE: F-statistic tells IF groups differ. R-squared (eta-squared) tells HOW MUCH. Small/medium/large benchmarks differ by field.
MODELS QUICK REF
  • LINEAR: Y=b0+b1X+e. Continuous Y. b1=slope (most important). Least squares=BLUE. Scatter plot FIRST. R^2=proportion of variance explained. Residual=Y_actual-Y_predicted.
  • LOGISTIC: Binary Y. P=1/(1+e^-(b0+b1X)). Sigmoid [0,1]. Challenger: 0.86 at 53F. Log-odds: ln(P/(1-P))=b0+b1X. Odds ratio: e^b1.
  • TREE: Root/internal/leaf. Recursive partitioning. CART=binary, ID3=multi-way, C4.5=gain ratio. Prune bottom-up. No normality assumption needed.
  • MODEL SELECTION: Continuous Y -> linear regression. Binary Y -> logistic regression. Explainable to executives -> decision tree. Non-normal 3+ groups -> Kruskal-Wallis. Multiple correlated responses -> MANOVA.
APT QUICK REF
  • TIERS: I-II=EXPLOIT known ($10s) | III-IV=DISCOVER unknown ($Ms) | V-VI=CREATE via supply chain ($Bs). KILL CHAIN (7): Recon->Weaponize->Deliver->Exploit->Install->C2->Actions. KASPERSKY (5): Access->Foothold->Deepen->Lateral->Remain.

GESTALT & DASHBOARD DESIGN
  • GESTALT STRENGTH: Enclosure (STRONGEST, borders/shading) > Connection (lines linking) > Proximity (near=group) / Similarity (alike=group). Also: Closure (complete shapes), Continuity (smooth paths).
  • FEW'S PRINCIPLES: "Single screen at a glance." Anti-patterns: exceeding single screen, no context ("compared to WHAT?"), excessive precision, wrong chart type, meaningless variety, 3D charts, Y-axis not at 0, clutter, misused color.
  • MACKINLAY: Expressiveness (ALL and ONLY the facts) + Effectiveness (readily perceived by viewer). Perception: Position > Length > Angle > Area > Color. Bar > pie always.
  • DESIGN: Top-left = prime real estate. Related metrics together. Consistent color coding. Bar charts for categories (gaps between bars). Histograms for distributions (bars touch). Pre-attentive features processed <200ms (color, size, orientation, shape). Max ~4 distinct features.
  • CHART SELECTION: Comparison -> bar chart. Distribution -> histogram/box plot. Trend over time -> line chart. Composition -> stacked bar (NOT pie). Relationship -> scatter plot. Geographic -> map/choropleth.
  • DASHBOARD ANTI-PATTERNS: 1) Exceeding single screen. 2) No context (compared to WHAT?). 3) Excessive decimal precision. 4) Wrong chart type. 5) Meaningless color variety. 6) 3D charts (distort perception). 7) Y-axis not at zero. 8) Too much clutter (low data-ink ratio).
HYPOTHESIS TESTING QUICK REF
  • SETUP: H0 has = sign. H1 has inequality. Never "accept H0" -- "fail to reject." P-value = P(data this extreme | H0 true). NOT P(H0 true). p<alpha -> reject. Two-sided: double one-tail p.
  • ERRORS: Type I=alpha=false alarm. Type II=beta=missed detection. Power=1-beta. Security: Type II WORSE (missed attack). Bigger samples reduce BOTH.
  • SIGN TEST: H0: M=m0. Count pluses. R~Binomial(n,0.5). Discard ties, shrink n. ANOVA: H0: all means equal. F=MSB/MSW. Post-hoc Tukey for which differ.
  • ALPHA LEVELS: 0.10=weak evidence, 0.05=standard, 0.01=strong evidence. In security: may use higher alpha (0.10) because cost of missing attack (Type II) exceeds cost of false alarm (Type I).
  • STEPS: 1) State H0/H1. 2) Choose alpha. 3) Collect data. 4) Compute test statistic. 5) Find p-value or compare to critical value. 6) Decide: reject or fail to reject. 7) Interpret in context.
EXAM TRAPS - FINAL (15 KEY TRAPS)
  • 1. Sensitivity=TP/(TP+FN) catches attacks. Specificity=TN/(TN+FP) clears normals. Don't swap.
  • 2. AUC=0.5 is BAD (coin flip). 0.7=fair, 0.8=good, 0.9=excellent, 1.0=perfect.
  • 3. F=MSB/MSW (between/within), NOT within/between. Large F=reject.
  • 4. Two-way ANOVA: read INTERACTION first. Non-parallel lines=interaction. Can't interpret main effects alone.
  • 5. Non-normal -> Kruskal-Wallis, NOT ANOVA. Security data almost NEVER bell-shaped.
  • 6. Binary outcome -> logistic (sigmoid [0,1]), NOT linear (goes outside [0,1]).
  • 7. APT Tiers V-VI CREATE vulns (supply chain). I-II exploit, III-IV discover, V-VI CREATE.
  • 8. Bear=RUSSIA. Panda=China. Kitten=Iran. Chollima=DPRK. Bear is NOT China.
  • 9. "Accept H0" is WRONG. Say "fail to reject." P-value is NOT P(H0 true).
  • 10. Accuracy misleading with imbalanced data. 99% normal -> 0% sensitivity = useless.
  • 11. Sign test: discard TIES, shrink n. R~Binomial(n,0.5). Tests MEDIAN not mean.
  • 12. Non-parametric NOT "assumption-free" -- still needs continuous+ordinal. Just fewer assumptions.
  • 13. Kill Chain=7 steps (Lockheed Martin). Kaspersky=5 stages. Don't confuse.
  • 14. In security: FN (Type II, missed attack) WORSE than FP (Type I, false alarm).
  • 15. Normality needed for CI/tests on coefficients, NOT for fitting regression line. Gauss-Markov=BLUE regardless.
  • 16. MANOVA uses Wilks' Lambda (closer to 0 = more evidence). NOT closer to 1. Box's M tests covariance homogeneity.
  • 17. R^2=0.6 means 60% explained, NOT 60% accuracy. R^2 near 0 = model useless. R^2 near 1 = check for overfitting.
  • 18. Tukey comes AFTER significant ANOVA. Never skip ANOVA and go straight to pairwise. ANOVA first, THEN Tukey.
  • 19. Log-odds is LINEAR in logistic regression. The S-curve is the probability transformation, not the model itself.
  • 20. Bartlett's test: p>0.05 = equal variances (GOOD, assumption met). p<0.05 = unequal variances (use Welch's).

KEY FORMULAS - POST-MIDTERM
  • LINEAR REG: Y=b0+b1X+e. b1=slope (most important). Least squares minimizes sum(residual^2). Gauss-Markov: BLUE. Residual = Y_actual - Y_predicted.
  • LOGISTIC: P(Y=1) = 1/(1+e^-(b0+b1X)). Sigmoid [0,1]. Output is probability, not class. Apply cutoff to get class.
  • SENSITIVITY: TP/(TP+FN). SPECIFICITY: TN/(TN+FP). ACCURACY: (TP+TN)/total. ERROR RATE: (FP+FN)/total.
  • ANOVA: F=MSB/MSW. MSB=SS_between/(k-1). MSW=SS_within/(N-k). df_between=k-1. df_within=N-k. Large F -> reject H0.
  • SIGN TEST: R = count of pluses. Under H0: R ~ Binomial(n, 0.5). n excludes ties. Compare to binomial table or use p-value.
  • MANOVA: Wilks' Lambda (smaller = more evidence against H0). H0: mean vectors equal across groups. Box's M for covariance homogeneity.
  • DECISION TREE: Purity gain at each split. CART: cost-complexity pruning parameter alpha. Information gain (ID3). Gain ratio (C4.5).
  • TYPE I INFLATION: With c comparisons at alpha, family-wise error = 1-(1-alpha)^c. 3 groups: 1-(0.95)^3 = 0.143 (~14%). ANOVA controls this.
  • SIGN TEST: R ~ Binomial(n, 0.5) under H0. Discard ties, shrink n. Count pluses. Compare to binomial critical value.
  • AUC SCALE: 0.5=random, 0.7=fair, 0.8=good, 0.9=excellent, 1.0=perfect. Higher=better discrimination.
  • PIE ANGLE: Relative frequency * 360 degrees. IQR FENCES: Mild outlier: Q1-1.5*IQR to Q3+1.5*IQR. Extreme: Q1-3*IQR to Q3+3*IQR.
  • ODDS RATIO: e^b1 in logistic regression. Multiplicative change in odds per 1-unit increase in X.
