📊 3. Power BI vs Tableau -- Collaboration Capabilities

Power BI Collaboration

  • Publish Excel workbooks to Power BI workspace
  • Create interactive reports and dashboards from published data
  • Embed live Power BI in PowerPoint -- interactive in both edit and slideshow modes
  • Mobile apps -- annotate and share via email
  • Sharing permissions -- people in org, existing access, or specific people

Tableau Collaboration

  • Publish to Tableau Cloud for shared access
  • Alerting -- subscriptions, metrics tracking, threshold alerts
  • Commenting on visualizations directly
  • Mobile-responsive layouts for on-the-go access
Key difference: Power BI excels at Excel/Office ecosystem integration (embed in PowerPoint). Tableau excels at alerting and threshold-based notifications.
🔀 4. Logistic Regression -- Predicting Yes/No with Probabilities
DEFINITION: Logistic regression predicts the probability (0-1) of a yes/no outcome using an S-shaped (sigmoid) curve. Unlike linear regression, it always stays within [0, 1].

Why Not Linear Regression for Yes/No?

Problem: A straight line can shoot below 0 or above 1 -- nonsensical for probability. Logistic regression bends into an S-curve that always stays in the valid [0, 1] range.

Challenger O-Ring Example

Real-world consequence of ignoring the model: Logistic regression predicted O-ring failure probability from launch temperature.
  • At 53 degrees F (cold) -- predicted failure probability = 0.86 (very risky)
  • At 81 degrees F (warm) -- predicted failure probability = 0.05 (safe)
The Challenger launched at 36 degrees F. The model's warning was ignored.
Memory Aid "Linear = straight line that escapes [0,1]. Logistic = S-curve that stays put."
🎓 5. Cutoff (Threshold) -- The Dial You Control
DEFINITION: The cutoff is the probability above which you label a case "yes" (class 1). Default is 0.5, but it's a dial you can turn.

Cutoff Tradeoff

CutoffEffectResult
Lower (e.g., 0.2)Flag more as "yes"Catch more true positives BUT more false alarms
Higher (e.g., 0.7)Flag fewer as "yes"Fewer false alarms BUT miss more real cases
No free lunch: You can't reduce false alarms AND catch more real cases at the same time. Tune the cutoff to match what's costly in your situation.
Security implication: In intrusion detection, missing a real attack (false negative) is usually far more costly than a false alarm (false positive). So you lower the cutoff to catch more threats, accepting more noise.
💲 6. Confusion Matrix -- The 2x2 Table
DEFINITION: A confusion matrix is a 2x2 table comparing predicted vs actual outcomes.
Predicted No Predicted Yes Actual No TN (correct) FP (false alarm) Actual Yes FN (miss) TP (correct)
CellNameMeaning
TNTrue NegativeCorrectly identified as negative
TPTrue PositiveCorrectly identified as positive
FPFalse Positive (Type I)False alarm -- said yes, actually no
FNFalse Negative (Type II)Dangerous miss -- said no, actually yes
KEY: Diagonal = correct predictions. Off-diagonal = errors. The point is to see WHICH WAY you tend to be wrong.
In security: FN (Type II error) is the dangerous miss. "Of real attacks, I missed this one." FP is just a false alarm -- annoying but not catastrophic.
Memory Aid "FP = False alarm (Type I). FN = Failed to Notice (Type II) -- the dangerous one in security."
📈 7. Four Key Metrics -- Accuracy, Error Rate, Sensitivity, Specificity
MetricFormulaPlain English
Accuracy(TP + TN) / Total% correct overall
Error Rate(FP + FN) / Total% wrong overall
Sensitivity (TPR)TP / (TP + FN)"Of real attacks, how many did I detect?"
Specificity (TNR)TN / (TN + FP)"Of normal traffic, how much did I leave alone?"
WHY ACCURACY ALONE CAN FOOL YOU: If 99% of traffic is normal, a lazy model saying "normal" every time scores 99% accuracy but 0% sensitivity -- it catches ZERO attacks. Security cares about sensitivity far more than raw accuracy.
Memory Aid "Sensitivity = of the SICK, how many did I catch? Specificity = of the HEALTHY, how many did I clear?"
📈 8. ROC Curve & AUC -- Evaluating Classifier Quality
DEFINITION: The ROC (Receiver Operating Characteristic) curve plots sensitivity (true positive rate) vs 1-specificity (false positive rate) across ALL possible cutoff values.

Reading the ROC Curve

  • Perfect classifier -- hugs the top-left corner (high sensitivity, low false positive rate)
  • Useless classifier -- sits on the diagonal (no better than a coin flip)

AUC (Area Under the ROC Curve)

AUC ValueInterpretation
0.5No better than coin flip -- useless
0.7-0.8Acceptable
0.8-0.9Good
0.9-1.0Excellent
1.0Perfect classifier
AUC is a single number [0.5, 1.0] that summarizes overall classifier quality. Higher = better. It tells you how well the model separates classes across all possible thresholds.
Memory Aid "ROC hugs top-left = good. Diagonal = coin flip. AUC closer to 1 = better."
🚫 9. Exam Traps -- Don't Fall For These
COMMON MISTAKES:
  • Using linear regression for yes/no outcomes -- it produces values outside [0,1]
  • Trusting accuracy alone -- a 99% accuracy model can have 0% sensitivity
  • Confusing sensitivity (catch rate among actual positives) with specificity (clear rate among actual negatives)
  • Thinking a higher cutoff catches more attacks -- it's the OPPOSITE (lower cutoff = catch more)
  • Confusing FP (false alarm, Type I) with FN (miss, Type II) -- in security, FN is the dangerous one
  • Saying AUC = 0.5 means a good model -- 0.5 is coin flip, useless
  • Forgetting the Challenger example -- probability 0.86 at 53 degrees F meant extremely risky
  • Mixing up Power BI (PowerPoint embedding) vs Tableau (threshold alerting) collaboration strengths
