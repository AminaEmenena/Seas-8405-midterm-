W1 - Visualization Fundamentals

Bar chart: compares categories, bars have GAPS

Histogram: distribution of ONE numeric var, bars TOUCH, x-axis = number ranges

Scatter plot: relationship between TWO variables, no connecting line

Line chart: trends over TIME, connected points

Pie chart: parts of whole, angle = rel.freq x 360, HARD TO READ, bar always better

Heatmap: matrix values using color intensity

Dot plot: individual values for small datasets

Stem-and-leaf: small datasets, preserves actual digits

Word cloud: bigger word = more frequent, good for text analysis

Data-ink ratio (Tufte): maximize data ink, minimize chart junk, remove unnecessary gridlines/borders/3D

Pre-attentive attributes: color, size, orientation, shape -- processed in <200ms

Perception hierarchy: position > length > angle > area > color

Sequential palette: low-to-high single hue gradient

Diverging palette: center point with two hues diverging

Categorical palette: distinct colors for unrelated groups, max ~7

Color blindness: ~8% males, red-green most common, tools can swap palettes

Bar vs Histogram: labels on x-axis = bar. Number ranges on x-axis = histogram

ELK: open source (Elasticsearch + Logstash + Kibana)

Python: pandas/matplotlib/seaborn, most flexible, LLMs write code for you

GP vs Specialized: GP = Swiss army knife. Specialized = Splunk(SIEM), Grafana(time-series), ArcGIS(geo)

Descriptive stats: summarize what you HAVE (mean, charts)

Inferential stats: sample -> conclusions about POPULATION (hypothesis tests)

Population: everything. Sample: slice you measure. Must be representative

4 sampling: Simple Random (equal chance), Stratified (bit from EVERY group), Cluster (WHOLE groups), Systematic (every m-th)

Stratified vs Cluster: stratified = bit from every group. Cluster = everything from few groups. EASY TO CONFUSE

4 data types NOIR: Nominal (labels no order: IP, port#, gender), Ordinal (ordered labels: severity), Interval (numbers no true zero: temp C/F), Ratio (true zero: weight, age, bytes)

Type test: Label or number? Label->order? No=nominal Yes=ordinal. Number->zero=nothing? Yes=ratio No=interval

Port number = NOMINAL. Temperature C/F = INTERVAL. Packet size = RATIO

Frequency table: freq f, relative freq f/total, percentage rel*100, cumulative freq

Class recipe: R=max-min, m=1+3.3*log(n), width=R/m rounded UP

Pie angle: relative freq * 360

W3 - Endpoint Security, Preprocessing & Measures

Endpoint: any device on network (laptop, phone, server, IoT, tablet)

ML Pipeline: Dataset -> Clean -> Feature Eng -> Train -> Score -> Evaluate

"Garbage In, Garbage Out": bad data = bad results, data prep = 80% of work

Step Zero: EXPLORE first -- df.describe(), df.info(), data dictionary

df.dropna(): remove null rows. df.fillna(value): fill nulls. df.drop_duplicates(): remove dupes

df.replace(): swap values. df.astype(): convert types. df.reset_index(drop=True): reindex

Text: str.lower(), str.upper(), str.strip(), str.replace()

df.loc: df.loc[df['col']>5] boolean mask, df.loc[0:5,'A':'C'] slice

Imputation: Mean/Median/Mode (simple, underestimates variability), Constant (0/"Unknown"), Forward Fill, Backward Fill, KNN (k nearest neighbors), Model-based (regression/tree/neural net)

Feature engineering: create NEW features from existing, "secret sauce", needs domain knowledge

Normalization: scale features so none dominates, accelerates training

Mean (X-bar): average, SENSITIVE to outliers (billionaire in room)

Median: middle value, rank=(n+1)/2, ROBUST to outliers, use for skewed (salaries, home prices)

Mode: most frequent, ONLY center for nominal data, can be unimodal/bimodal/multimodal

Shape: mean=median=mode -> symmetric. Mode<Median<Mean -> right-skew. Mean<Median<Mode -> left-skew

"Mean chases the tail": mean always pulled toward the long tail

Range: max-min. Variance S^2: sum(Xi-Xbar)^2/(n-1). SD S: sqrt(S^2) back in original units

Why square deviations? Plain gaps cancel. Why n-1? Bessel correction for sample bias

Parameter (population Greek: mu, sigma) vs Statistic (sample Latin: X-bar, S)

Empirical Rule: 68-95-99.7% within 1-2-3 SD, BELL-SHAPED ONLY

Chebyshev: any shape, at least 1-1/k^2 within k SD. k=2: 75%. k=3: 89%

Z-score: (Xi-mean)/SD, unitless, |Z|>3 = likely outlier

Correlation r: Cov(X,Y)/(Sx*Sy), range [-1,+1], unitless, NOT causation, only LINEAR

Covariance: positive = move together, negative = opposite

W4 - User Security & Hypothesis Testing

User: any entity with ID + permissions, includes bots/APIs/service accounts

DBIR 2025: 60% breaches human element, 22% credential abuse, 20% vuln exploitation, 16% phishing

System Intrusion: 53% of breaches. Internal actors: 10x more records than external

Privacy: GDPR (EU consent, 72hr notify), CCPA (CA know/delete/opt-out), PIPEDA (Canada), LGPD (Brazil), DPA 2018 (UK)

H0 (null): boring default, = sign, "innocent". H1 (alt): your claim, inequality

NEVER "accept H0" -> "fail to reject H0"

Type I (alpha): false alarm = reject true H0. Type II (beta): missed detection = keep false H0

Power = 1-beta. Alpha chosen BEFORE data. Bigger n reduces BOTH errors

One-tailed: one rejection region. Two-tailed: both tails (alpha/2 each)

6 steps: 1.State H0/H1 2.Pick alpha 3.Choose statistic 4.Find distribution 5.Rejection region 6.Compute & decide

W5 - Code Security & Hypothesis Mechanics

Code security: identify/assess/mitigate vulns. CIA (Confidentiality, Integrity, Availability)

Von Neumann: CPU(Control+ALU) + Memory + I/O. Shared memory = injection attacks possible

Heartbleed (2014): CVE-2014-0160, OpenSSL missing bounds check, fix: validate payload length

Equifax (2017): CVE-2017-5638, Apache Struts unpatched 6 months, 147M records

XZ Utils (2024): CVE-2024-3094, 3yr social engineering, backdoor in liblzma targeting sshd

CrowdStrike (2024): Channel File 291, Content Validator had own bug, 8.5M BSOD. SQA = security

SAST: static, no execution, white-box, early. DAST: dynamic, running, black-box, runtime

Rule: No Security Scans & Reviews -> No Code to Production

Z-test: Z = (X-bar - mu0) / (sigma/sqrt(n)). SE = sigma/sqrt(n)

p-value: P(data this extreme | H0 true). Small p = evidence against H0

Decision: p < alpha -> reject. p >= alpha -> fail to reject

Two-sided: p = 2*P(Z >= |z|) -- DOUBLE the tail probability

W8 - Parametric vs Non-Parametric & Trees

Parametric: assumes normal, tests mean, more powerful, sensitive to outliers (Z-test, t-test)

Non-parametric: distribution-free, tests median, robust to outliers (sign test, Kruskal-Wallis)

Decision: bell-shaped -> parametric. Skewed/ordinal/outliers -> non-parametric

Sign test: H0: M=m0, count pluses (Xi>m0), R ~ Binomial(n, 0.5), discard ties, shrink n

Decision tree: flowchart. Root(top) -> Internal nodes(questions) -> Leaves(final labels)

Recursive partitioning: split on variable maximizing purity

Overfitting: too deep = memorizes noise. Fix: early stopping or pruning (bottom-up better)

CART (Breiman 1984, binary splits) vs ID3/C4.5 (Quinlan, multi-way)

Classification tree (categorical target) vs Regression tree (numeric target)

No distributional assumptions needed (unlike hypothesis tests)

W10 - APTs & Linear Regression

APT: Advanced (custom malware, zero-day) + Persistent (months/years undetected) + Threat (data theft/disruption). APTs are "slow" and "low"

Threat actors: cybercriminals, state-sponsored, hacktivists, insiders, terrorists, competitors

6 Tiers: I-II ($10s) exploit known vulns. III-IV ($Ms) discover unknown. V-VI ($Bs) CREATE vulns via supply chain

Kill chain 7 steps: Recon -> Weaponize -> Deliver -> Exploit -> Install -> C2 -> Actions on Objectives

Kaspersky 5 stages: Gain Access -> Foothold -> Deepen -> Lateral -> Look/Learn/Remain

CrowdStrike naming: Bear=Russia, Buffalo=Vietnam, Chollima=DPRK, Crane=S.Korea, Hawk=Syria, Jackal=Hacktivist, Kitten=Iran, Leopard=Pakistan

Linear regression: Y = b0 + b1*X + e. b0=intercept (Y when X=0). b1=slope (change in Y per 1-unit X)

Y=response/dependent. X=predictor/independent. Slope is the number you care about most

Least squares: minimizes sum of SQUARED residuals (vertical distances to line)

Residual: vertical distance from data point to fitted line

Gauss-Markov: least squares = best unbiased linear estimator (BLUE)

Normality: NOT needed to fit line. Only needed for confidence intervals and hypothesis tests on slope

Always SCATTER PLOT FIRST to check linearity

Security example: slope=5 on "failed logins vs hour" means each hour = 5 more failed logins

Positive slope: rise together. Negative: one rises other falls. Near-zero: X tells little about Y

W11 - Collaboration & Logistic Regression

Collaboration: shared goals, mutual respect, open communication, shared accountability

Collaboration features: sharing/access controls, real-time editing, commenting/annotation, version control, interactive dashboards, data integration/sync, security features, user-friendly interface, alerts/notifications, mobile access, ecosystem integration

Power BI: publish Excel to workspace, embed live reports in PowerPoint (interactive in edit+slideshow), mobile annotate+share, sharing permissions (org/existing/specific)

Tableau: publish to cloud, alerting (subscriptions/metrics/threshold alerts), commenting, mobile-responsive layouts

Logistic regression: predicts probability [0,1] for yes/no using S-curve (sigmoid)

Why not linear for yes/no: straight line can go below 0 or above 1 (nonsense for probability)

Challenger O-ring: 0.86 failure probability at 53F, 0.05 at 81F. Cold = risky

Cutoff (threshold): probability above which you label "yes". Default 0.5 but it's a DIAL

Lower cutoff: catch more true positives BUT more false alarms. Higher: fewer false alarms BUT miss more

Confusion matrix: 2x2 of predicted vs actual. Diagonal=correct. Off-diagonal=wrong

TP=True Positive(correct yes). TN=True Negative(correct no). FP=False Positive(false alarm=Type I). FN=False Negative(miss=Type II)

Sensitivity: TP/(TP+FN) "of real attacks, how many caught?" -- security cares about this most

Specificity: TN/(TN+FP) "of normal traffic, how much left alone?"

Accuracy: (TP+TN)/total. Can be MISLEADING: 99% normal traffic -> lazy "always no" model = 99% accurate but 0% sensitivity

ROC curve: sensitivity vs 1-specificity across ALL cutoffs. Perfect = hugs top-left corner

AUC: 0.5 = coin flip (BAD). 1.0 = perfect. Higher is better

W12 - ANOVA & Non-Parametric Tests

ANOVA: compare means of 3+ groups. Extends t-test. H0: mu1=mu2=...=muk. H1: at least one differs

Why not multiple t-tests: 3 groups at alpha=0.05 -> 3 comparisons -> false positive inflates to ~14%

F-statistic = MSB/MSW = Between-group variance / Within-group variance. Large F -> reject H0

Between-group: how different group means are from grand mean (SIGNAL)

Within-group: spread inside each group (NOISE)

3 assumptions: 1.Independence 2.Normality (Shapiro-Wilk/Q-Q) 3.Homogeneity of variance (Levene's/Bartlett's)

When normality fails: use Kruskal-Wallis (non-parametric, ranks-based)

When equal variance fails: use Welch's ANOVA

Tukey post-hoc: after ANOVA rejects, tells you WHICH specific groups differ

SOC example: F=32.75, p=0.000 -> reject -> Tukey: all three teams differ

Two-Way ANOVA: 2 factors, asks 3 questions: main effect A, main effect B, INTERACTION A*B

Interaction is MOST IMPORTANT concept: effect of one factor DEPENDS on other factor's level

Non-parallel lines in interaction plot = interaction exists

Read INTERACTION ROW FIRST in Minitab output. If significant, interpret main effects with caution

MANOVA: multiple CORRELATED response variables. H0: mean VECTOR equal across groups

Why not multiple ANOVAs: inflates Type I, ignores correlation, misses combination effects

Wilks' Lambda: MANOVA test statistic

ANOVA family: t-test(2 groups,1 response), One-Way(3+,1), Two-Way(2 factors,1,interaction), Repeated Measures(1+,1,same subjects), MANOVA(1+,2+ responses)

Non-parametric equivalents: Kruskal-Wallis(one-way), Friedman(two-way), Spearman(correlation)

Security data non-normal: zero-inflated counts, skewed response times, ordinal severity (CVSS), heavy tails (power-law losses), small samples (breach investigations n=5-15), categorical variables
