💻 1. What is Code & Code Security
Code: Instructions written in any programming language that tell a computer what to do.
Code Security: The practice of identifying, assessing, and mitigating vulnerabilities in source code. Ensures Confidentiality, Integrity, and Availability (CIA).

Von Neumann Architecture

The foundational computing model consisting of:

  • CPU -- Control Unit + Arithmetic Logic Unit (ALU)
  • Memory Unit -- stores data and instructions
  • I/O Devices -- interface with external world
Von Neumann Architecture
+-------------------+ | CPU | | +------+ +-----+ | | |Control| | ALU | | | | Unit | | | | | +------+ +-----+ | +--------+----------+ | +----+----+ | Memory | | Unit | +---------+ | +----+----+ | I/O | | Devices | +---------+
Why it matters for security: Von Neumann architecture stores code and data in the same memory space -- this fundamental design enables buffer overflow attacks, code injection, and many other vulnerability classes.
🚨 2. Major Code Security Incidents

Heartbleed (2014)

CVE-2014-0160 -- OpenSSL TLS heartbeat extension vulnerability
  • Root cause: Missing bounds check on payload length
  • Attack: Attacker sends small payload claiming large length
  • Result: Server returns payload + extra memory (passwords, private keys, session tokens)
  • Fix: Validate payload length before responding
Heartbleed Attack Flow
Client: "Echo back 'hello' (I claim it's 65,535 bytes)" Server: "hello" + 65,530 bytes of whatever was in memory ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ passwords, keys, session data leaked!

Equifax (2017)

CVE-2017-5638 -- Apache Struts vulnerability
  • Impact: 147 million people affected
  • Root cause: Failed to apply patch in timely manner
  • Lesson: Vulnerability management and timely patching are critical

XZ Utils (2024)

CVE-2024-3094 -- The most critical code security incident in history
  • "Jia Tan" spent 3 years becoming a trusted maintainer through social engineering
  • Backdoor mechanism: Multi-stage backdoor in liblzma exploiting glibc IFUNC to intercept RSA decryption in OpenSSH daemon (sshd)
  • Potential impact: Remote Code Execution on millions of Linux servers
  • Why most critical: It was deliberate social engineering, not an accidental coding mistake

CrowdStrike Outage (2024)

Not a breach but an SQA-as-security case study
  • Channel File 291 config update contained a bug causing out-of-bounds memory read
  • Content Validator (designed to check updates) had its own bug
  • Result: BSOD on 8.5 million Windows systems
  • Lesson: A single line of defective code can cause global Denial of Service
Remember This
Heartbleed = bounds check. Equifax = unpatched. XZ Utils = social engineering (worst). CrowdStrike = SQA failure (global DoS)
🛡 3. Vulnerability Cataloging & Management
CVE (Common Vulnerabilities and Exposures): A MITRE program that catalogs publicly disclosed vulnerabilities with unique identifiers (e.g., CVE-2024-3094).
NIST: Provides standards and guidelines for organizations to manage cybersecurity risk.

Software Supply Chain Attacks

Definition: Threat actors tamper with third-party components to compromise downstream applications.
  • Check Point research: 925 attacks per week per organization
  • Exposed secrets in source code: credit cards, passwords, API tokens, private keys
Key insight: You are only as secure as your weakest dependency. Supply chain attacks exploit the trust relationships in software ecosystems.

📊 5. Hypothesis Testing -- The Z Test Statistic
Z test statistic formula:
Z Test Formula
X-bar - mu0 Z = ------------------- sigma / sqrt(n) Where: X-bar = sample average mu0 = H0 claimed value (null hypothesis) sigma = population standard deviation n = sample size sigma / sqrt(n) = standard error (SE)
Key insight: Standard error shrinks with larger samples. The same gap between X-bar and mu0 becomes more convincing with more data.
  • Z of 0.5 = nothing special (data is close to what H0 predicts)
  • Z of 3 = big deal (data is 3 standard errors away from H0 claim)
Remember This
Z tells you: "How many standard errors is my sample mean from the claimed value?" Bigger |Z| = stronger evidence against H0.
🎯 6. p-Values & Decision Rules
p-value: The probability of getting a result at least as extreme as yours, assuming H0 is true. It is the smallest alpha at which H0 would be rejected.
  • Small p = surprising data = evidence against H0
  • Large p = data is consistent with H0 (not surprising)

Decision Rule

p-value < alpha --> Reject H0 (result too surprising for chance)
p-value ≥ alpha --> Do not reject H0 (result consistent with boring default)

Tail Direction Matters

TypeHypothesisp-value Calculation
Left-sidedH1: mu < mu0p = P(Z ≤ z)
Right-sidedH1: mu > mu0p = P(Z ≥ z)
Two-sidedH1: mu ≠ mu0p = 2 * P(Z ≥ |z|)
p-value method vs rejection-region method: Always give the same answer. The p-value method is usually faster because software gives it directly.
Common mistake: Reading a large p-value as "H0 is proven true." It only means there is not enough evidence to reject H0 -- absence of evidence is not evidence of absence.
🔧 7. Worked Example -- Wire Tensile Strength
Setup: 16 wires tested, X-bar = 967.8, sigma = 128. Test H0: mu = 1000 vs H1: mu < 1000, alpha = 0.05
Solution Steps
Step 1: Standard Error SE = sigma / sqrt(n) = 128 / sqrt(16) = 128 / 4 = 32 Step 2: Critical value approach k = mu0 - SE * z_alpha = 1000 - 32(1.645) = 947.36 X-bar = 967.8 is NOT below 947.36 --> Do not reject H0 Step 3: p-value approach (same answer) Z = (967.8 - 1000) / 32 = -32.2 / 32 = -1.006 p = P(Z <= -1.006) = 0.1562 0.1562 >= 0.05 --> Do not reject H0 Conclusion: Not enough evidence to say wires are weaker than spec.
Both methods agree: The sample mean (967.8) is below 1000, but not far enough below to be statistically significant at alpha = 0.05.
⚠️ 8. Exam Traps -- Hypothesis Testing
Common exam mistakes to avoid:
  • Forgetting to divide sigma by sqrt(n) -- You need standard error (sigma/sqrt(n)), not sigma alone!
  • Not doubling p for two-sided tests -- Two-sided means p = 2 * P(Z ≥ |z|)
  • Reading large p as "H0 is proven true" -- It only means not enough evidence to reject
  • Comparing p to wrong alpha -- Make sure you know what significance level is specified
Remember This
SE = sigma / sqrt(n), NOT just sigma. Two-sided = DOUBLE the tail. Large p = "can't reject" NOT "H0 is true."
